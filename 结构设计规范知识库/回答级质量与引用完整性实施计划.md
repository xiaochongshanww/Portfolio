# 回答级质量与引用完整性实施计划

## 目标

把现有“检索结果是否命中”的评估升级为“最终回答是否正确、依据是否可靠、引用是否可访问”的自动化闭环。

## 原则

- 评估期望只保存在评估器，不进入模型提示词。
- 核心判定使用确定性规则，不以 LLM 自评作为唯一依据。
- 盲测集与检索调优集分离，禁止针对单个问题增加业务硬编码。
- 无依据问题必须拒答；检索结果不足时不能用常识补值。
- 图片链接不仅检查 Markdown 语法，还必须验证对应本地资源和 HTTP 响应。

## 待办清单

- [x] 1. 建立回答级评估数据契约
  - 支持必含事实、任选事实、禁用事实、规范编号、条文/表号、单位、拒答和截图要求。
  - 检查重复 ID、空问题、无断言、未知类别和无效组合。

- [x] 2. 建立独立盲测与对抗集
  - 至少 24 条，与现有 100 条检索调优集分离。
  - 覆盖精确取值、公式、条件边界、否定问法、错误前提、跨规范和无依据问题。
  - 用例期望不得进入 RAG 上下文。

- [x] 3. 实现回答级确定性评估
  - 调用真实 `/v1/chat/completions` 非流式接口。
  - 检查固定章节、事实、单位、规范编号、条文/表号、拒答行为和禁用事实。
  - 输出逐项失败原因、回答原文及汇总 JSON/Markdown。

- [x] 4. 实现来源引用完整性审计
  - 解析 Markdown 图片引用，拒绝裸路径、虚构路由和不可访问资源。
  - 校验页面截图对应真实 PDF 和有效页码。
  - 校验规范编号、条文号、表号能够被本次检索证据支持。

- [x] 5. 增加回答质量后台任务和控制台视图
  - 后台执行，记录进度，避免阻塞 API。
  - 评估页展示回答级通过率、引用完整率、拒答正确率及失败用例。

- [x] 6. 接入无人值守质量门禁
  - 一键验证运行回答级评估。
  - 报告记录数据版本、评估集哈希和生成时间；过期报告阻断门禁。
  - 设定总体通过率和关键检查阈值。

- [x] 7. 完整运行与回归
  - 运行后端测试、前端生产构建、检索评估、结构化评估、回答评估和质量门禁。
  - 修复真实失败后才能将本清单全部标记完成。

## 初始验收阈值

- 回答级用例数不少于 24。
- 总体通过率不低于 90%。
- 规范编号、条文/表号、拒答和引用完整性关键检查通过率均为 100%。
- 图片 HTTP 可访问率为 100%。
