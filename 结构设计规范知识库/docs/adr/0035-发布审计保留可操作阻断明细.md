# ADR 0035：发布审计保留可操作阻断明细

> 状态：已接受
> 决策日期：2026-08-20
> 维护角色：发布与质量负责人
> 文档更新：2026-08-20
> 代码/流程核对：已核对 `audit_release_readiness.py`、来源资格校验和 Markdown/JSON 测试
> 完整运行验证：外部审计当前保留 20 条来源资格明细，门禁仍为 `ready=false`
> 验证证据：[发布审计阻断明细验证记录](../releases/发布审计阻断明细验证记录.md)、`tests/test_release_readiness.py`
> 关联评估/发布：I-052；[发布检查单](../releases/发布检查单.md)
> 复核周期：审计输出契约或来源治理字段变化时

## 背景

来源资格审计以前只输出阻断数量。操作人员仍需再次运行底层来源校验并手工对应来源和字段，人工处理成本高，也容易遗漏某一类阻断。

## 决策

来源审计检查在结构化结果中保留 `items` 数组。每项必须是来源登记校验产生的原始脱敏错误或阻断说明；Markdown 报告将其渲染为“来源资格明细”。该字段只用于诊断和整改，不改变 `ok`、`ready`、阻断级别或来源权限结论。

## 后果

- 发布负责人可以直接按报告逐项处理来源台账。
- JSON 可被控制台、CI 或后续治理工具消费，Markdown 仍适合人工审阅。
- 明细输出不能替代权利证明，也不能将 B/C 级来源转化为可发布来源。
