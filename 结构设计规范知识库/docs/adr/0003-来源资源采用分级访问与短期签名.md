# ADR 0003：来源资源采用分级访问与短期签名

> 决策角色：工程负责人
> 关联评估/发布：I-006 受控图片资源访问
> 验证证据：`src/app/core/content_access.py`、`src/app/core/security.py`、`src/app/api/images.py`、`tests/test_asset_access.py`、[Structural Spec KB CI #9](https://github.com/xiaochongshanww/Portfolio/actions/runs/31244572233)
> 复核周期：来源授权模型、客户端鉴权方式或资源域名变化时

## 背景

问答会在 Markdown 中引用 MinerU 提取图片或原始 PDF 的按页截图。浏览器直接加载 Markdown 图片时不能附加 Open WebUI 使用的 Bearer Header；如果完全公开资源端点，任何获得路径的人都可能绕过问答鉴权读取受限扫描页。把 API Key 放入查询参数又会使长期凭据进入聊天记录、浏览器历史、代理日志和引用文本。

来源治理还要求不同文档具有不同展示边界，不能用一个全局开关把测试图片、允许公开资料和仅限受控验证的扫描件视为同一等级。

## 决定

1. 每份来源在 `data/metadata/specs.json` 中分别声明 `image_access` 和 `page_image_access`，合法值为 `public`、`authenticated`、`disabled`。
2. 未登记来源默认按 `authenticated` 处理；无效策略按 `disabled` 失败关闭。
3. `public` 资源可以直接读取；`disabled` 资源始终拒绝展示。
4. `authenticated` 资源在启用 API 鉴权时允许有效 API Key 或短期 HMAC-SHA256 签名 URL；关闭全局鉴权时只允许无代理头的回环请求。
5. 签名只绑定规范化请求路径、HTTP GET 语义和过期时间，使用独立的 `ASSET_SIGNING_KEY`；签名 URL 不携带 API Key。
6. RAG 只为允许展示的资源生成引用。启用鉴权后，受保护引用自动使用短期签名 URL；禁用来源不会写入模型提示或回答引用候选。
7. `/images/*` 必须将解析后的目标路径限制在 `IMG_DIR` 内，禁止目录穿越和目录读取。
8. 知识包 v3 强制携带 `runtime/metadata/specs.json`，确保目标环境保留来源访问策略；v1、v2 只保留技术兼容，不具备该策略完整性保证。

这是一项资源访问控制，不是最终用户账号、租户或角色权限系统。公开服务仍需 TLS、代理边界、密钥轮换和来源权利审核。

## 备选方案

1. 所有图片公开：客户端最简单，但无法满足受限扫描件的展示边界。
2. 所有图片只接受 Bearer Header：安全边界清晰，但标准 Markdown 图片无法显示。
3. 把 API Key 放入 URL：实现简单，但会泄露长期凭据，拒绝采用。
4. 服务端代理并把图片内嵌为 Base64：避免独立资源请求，但回答体积、缓存和模型客户端兼容性较差。
5. 建立完整用户会话与对象存储授权：适合多租户产品，但超出当前单实例 API Key 架构的必要复杂度。

## 后果

- 开启 `API_AUTH_ENABLED` 时必须额外配置至少 32 字符的 `ASSET_SIGNING_KEY`。
- 签名到期后旧聊天中的受保护图片需要重新生成回答或重新签发，文本引用不受影响。
- 修改来源策略需要重新构建运行资产，并重新导出 v3 知识包。
- `PUBLIC_ASSET_BASE_URL` 必须指向同一验证签名的 API 路径；把图片复制到不执行策略的静态主机将绕过本决定。

## 验证与回退

- 自动测试覆盖有效签名、过期、路径篡改、过长有效期、API Key 访问、远程未授权访问、未知来源默认收紧、无效策略失败关闭和目录穿越。
- 知识包往返测试验证策略文件和 `source_access_policy` 能力声明。
- 如签名机制需要替换，新增 ADR 和兼容版本；不得回退为公开受限资源或在 URL 中传递长期 Key。
