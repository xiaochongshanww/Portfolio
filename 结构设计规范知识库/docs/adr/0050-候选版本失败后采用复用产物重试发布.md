# ADR 0050：候选版本失败后采用复用产物重试发布

> 状态：已接受  
> 日期：2026-08-24  
> 维护角色：工程负责人、内容治理负责人  
> 文档更新：2026-08-24  
> 代码/流程核对：2026-08-24，已核对候选校验、候选门禁、原子激活、管理 API 和控制台入口  
> 完整运行验证：后端专项回归通过；真实候选复用发布任务 `84d52998ce49` 已成功完成并激活  
> 验证证据：`tests/test_source_catalog.py`、`tests/test_source_management_api.py`、`tests/test_admin_runtime_contract.py`、前端类型检查、生产构建和真实候选复用发布任务 `84d52998ce49`  
> 复核周期：候选版本生命周期、来源 revision、候选门禁或发布事务变化时

## 背景

增量候选重建先生成完整候选版本，再执行检索门禁和原子激活。候选构建可能已经完成了解析、分块、向量化和资产组装，却因为门禁服务暂时不可用、运行时状态异常或激活阶段故障而失败。若每次都重新走 PDF 解析，会重复消耗解析器、GPU、Embedding 配额和时间，也会扩大故障恢复范围。

## 决策

增加“候选复用发布”流程。它把已经生成的候选产物视为不可变输入，只重新验证其来源身份和完整性，重新执行候选门禁，并通过同一套原子激活事务发布。流程创建新的 `source_republish` 任务，不修改原失败任务。

接口为：

```text
POST /admin/sources/candidates/{job_id}/republish
```

其中 `job_id` 必须是失败的 `source_rebuild` 任务。服务端必须拒绝以下情况：

- 候选 manifest 或版本目录不存在、不完整或与任务不匹配；
- 来源 revision 不是失败状态，或来源 revision 与候选快照不一致；
- 当前来源目录相对候选发生新增、修改、替换或下架；
- 候选版本已经是活动版本；
- 同一个候选已有排队中或执行中的复用发布任务。

## 不重复执行的步骤

候选复用发布不调用 PDF Builder、MinerU、PyMuPDF、Chunk 处理或 Embedding。它只读取既有候选目录，重新加载候选 Chroma/精确向量/BM25 状态，运行候选质量门禁，并在通过后完成激活事务。

## 失败与恢复

重试发布失败时，当前活动版本保持不变，原失败任务和新失败任务均保留日志与关联信息。激活过程中任何写入或内存切换异常都必须恢复旧活动指针、manifest 和检索状态。来源目录发生变化时，必须回到“分析变更”并生成新的候选，不能发布过期候选。

## 结果

- 解析阶段失败仍然必须重新构建，不能使用本流程绕过缺失产物。
- 门禁或激活阶段的瞬态失败可以在不重复解析的情况下恢复。
- 每次复用发布都有独立任务、门禁证据和 `candidate_job_id`，可以审计真实执行路径。
- 当前流程适用于单实例、单工作线程的本地运行模式；多实例部署仍需外部任务协调和共享对象存储。
