# ADR 0011：质量验证采用显式目标与执行失败语义

## 背景

`scripts/verify_quality.py --api-base` 原本只控制管理任务提交地址。回答级盲测由 API 后台任务再次请求固定的 `http://127.0.0.1:8000`，因此在自定义端口或隔离实例上，验证器实际使用了两个目标。与此同时，检索评估返回 `ok: false`、回答盲测全部请求失败时，工作流仍可正常返回字典，后台任务因未抛出异常而被标记为 `succeeded`。最终报告只能显示质量失败，不能准确区分评估执行失败。

## 决策

1. `verify_quality.py` 的 `--api-base` 是本次验证的唯一外部 API 目标。检索评估通过该 API 的管理任务运行；回答级盲测由验证器进程直接请求同一目标，不再让后台任务二次猜测外部地址。
2. API 管理界面启动回答级盲测时使用只由部署者设置的 `ANSWER_EVALUATION_API_BASE`。默认值保持 `http://127.0.0.1:8000`，自定义监听端口或容器拓扑必须显式覆盖。
3. 管理接口不接受客户端提供的任意 `api_base`。这避免把受鉴权管理端变成可访问任意 URL 的服务端请求入口。
4. 质量未达标与评估执行失败分开表示：
   - 所有用例均完成，但断言失败或通过率不足：报告 `ok: true`，任务可成功，质量门禁失败；
   - 检索服务未就绪、目标 API 不可达、响应无法解析或任一回答请求未完成：报告 `ok: false`，任务失败，并保留机器可读错误与已生成报告。
5. 无人值守验证在启动 API 评估前调用 `/ready`。未就绪时不提交依赖该 API 的评估任务，报告直接列出就绪原因。

## 结果

- 自定义端口、隔离数据根和默认端口遵循同一目标契约。
- 后台任务状态可以用于自动化诊断，不再把基础设施故障当作一次成功评估。
- 质量下降仍保留完整失败用例，不会因为任务失败语义而丢失质量证据。
- 管理端回答盲测的内部地址成为新增部署配置；配置错误会快速失败并给出明确诊断。

## 非目标

- 本决策不改变评估阈值、评估集内容或模型选择。
- 本决策不把回答级盲测迁移到远程 SaaS，也不允许管理 API 代理任意目标。
- 本决策不把 `/health` 视为知识库可用证明；质量运行仍以 `/ready` 为前置条件。
