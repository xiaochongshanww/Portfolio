# ADR 0006：知识版本采用计划确认与受保护清理

> 状态：已接受
> 决策日期：2026-08-08
> 维护角色：工程负责人
> 文档更新：2026-08-08
> 代码/流程核对：2026-08-08
> 完整运行验证：2026-08-08，CI #23 的九个任务全部通过
> 关联事项：I-012
> 验证证据：[知识版本保留与清理验证记录](../releases/知识版本保留与清理验证记录.md)
> 复核周期：版本目录、活动指针、任务编排或保留策略变化时

## 背景

候选版本事务化激活后，每次重建会在 `data/db_versions/{job_id}` 留下数据库、解析文本、图片、解析器产物和质量证据。保留这些版本有助于故障分析和回滚，但无限保留会持续消耗磁盘；直接按目录时间或数量删除又可能破坏活动服务、正在构建的候选和人工要求保留的证据。

## 决策

1. 版本清理分为“生成计划”和“按计划执行”两个阶段，管理端不存在任意路径立即删除接口。
2. 活动版本、排队或运行中的重建版本、带人工固定标记的版本、最短保护期内版本，以及策略要求保留的最近门禁通过版本不可进入删除计划。
3. 保留策略同时使用数量、期限和总占用高低水位。超过高水位时只扩大对非保护版本的回收范围，直到低水位；保护约束不因磁盘压力失效。
4. 计划持久化到审计目录，并绑定目录大小、最后修改时间和关键文件摘要。执行前重新计算保护集和指纹；不一致的版本跳过并记录原因。
5. 删除目标必须解析为版本根目录下的普通直接子目录，不允许符号链接、重解析点、版本根目录自身或外部路径。执行时先原子改名为隔离墓碑，再递归删除。
6. 每次计划、执行、跳过和失败都写入结构化审计记录。部分失败返回部分失败状态，不得报告为完整成功。
7. 原始 PDF、活动根 manifest、活动指针、审批修正和全局审计资料不属于版本清理范围。

## 后果

- 版本清理需要一次显式确认，但可以在不接触文件系统命令行的情况下完成。
- 空间目标可能因为全部剩余版本受保护而无法达到；系统应将此作为可观察的未满足目标，而不是越权删除。
- 清理计划有有效期，期间任何版本变化都会使相关删除项失效，这是有意的并发保护。
