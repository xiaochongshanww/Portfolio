## 背景

I-031 已把外部镜像拉取与容器启动拆分，并对仓库瞬时故障执行有限重试，但仓库中的四类外部输入仍由可变标签解析：`docker/dockerfile:1`、`node:22-alpine`、`python:3.11-slim` 和 `ghcr.io/open-webui/open-webui:v0.9.5`。即使源码、依赖锁和 Compose 文件完全相同，上游重新发布同一标签后仍可能取得不同字节，削弱构建复现、事故追踪和回退证据。

2026-08-09 通过 `docker buildx imagetools inspect` 取得当前多架构清单摘要：

| 用途 | 可读标签 | 多架构清单摘要 |
| --- | --- | --- |
| Dockerfile frontend | `docker/dockerfile:1` | `sha256:87999aa3d42bdc6bea60565083ee17e86d1f3339802f543c0d03998580f9cb89` |
| 前端构建基础 | `node:22-alpine` | `sha256:c610fcdfb1d5b4740dd70c284ed3cb16bb857e0f7166196e36a5501df7a3aa32` |
| Python 构建与运行基础 | `python:3.11-slim` | `sha256:90744cff8f32887f075c47d747a173ff333e9e98801667af93c357fa9f5e28ff` |
| OpenWebUI | `ghcr.io/open-webui/open-webui:v0.9.5` | `sha256:e045bde3b004cc7f8c319412345eb56c87ea6ac57031534a31ca37ad5424beb3` |

这些摘要标识 OCI image index，而不是单一 amd64 manifest，因此不会把受支持部署无意收窄到当前主机架构。

## 决策

1. Dockerfile syntax、所有外部 `FROM` 和 Compose 外部运行镜像统一采用 `可读标签@sha256:<64位摘要>`；标签保留版本意图，摘要提供不可变身份。
2. 同一 Python 基础在 builder 和 runtime 阶段必须使用完全相同的标签与摘要。由当前源码构建的 `structural-spec-kb:*` 本地镜像不要求摘要，但只能由声明 `build` 的服务产生和复用。
3. 提供确定性校验入口：解析 Dockerfile 引用，并通过 `docker compose config --format json` 检查渲染后的服务图；任何未固定、摘要格式错误或不可解释的本地镜像引用均失败关闭。
4. 同一入口提供显式远程漂移检查，去掉本地摘要后查询标签当前的多架构摘要。远程不可达与摘要漂移均返回非零，但必须输出不同机器可读错误；普通提交门禁只执行离线身份校验，避免把仓库可用性变成每次提交的随机依赖。
5. GitHub Actions 每周和按需执行远程漂移检查。Dependabot 分别启用 Dockerfile 与 Docker Compose 生态更新；更新只创建可审阅变更，不自动合并。
6. 镜像更新必须同时核对标签、摘要、上游发行说明、许可/来源、平台清单和项目完整矩阵。摘要漂移、版本升级和安全修复使用同一审阅流程，不手工只改摘要后跳过验证。
7. 摘要固定只证明“取得已声明身份”，不证明镜像无漏洞、上游可信、签名有效或适合生产。漏洞扫描、签名/证明验证和私有镜像镜像化仍是独立后续决策。

## 备选方案

- 继续只用标签：维护成本最低，但不能复现同一提交实际取得的镜像，因此拒绝。
- 只写 digest、不保留标签：身份不可变，但代码审阅无法直观看出版本意图，Dependabot 更新能力也更弱，因此拒绝。
- 固定单平台 manifest：可复现但会破坏 amd64/arm64 自动选择，不符合当前可移植目标，因此拒绝。
- 每次主 CI 都查询远程摘要：能最快发现漂移，但把公共仓库限流和网络波动重新引入每次提交门禁，因此改为独立定时任务。
- 直接引入第三方扫描 Action：漏洞能力有价值，但需要单独选择扫描器、数据库缓存、严重度策略和例外治理；不与身份固定混成一次决策。

## 兼容性与边界

- 需要支持 `tag@digest` 的 Docker/BuildKit 与 Compose；当前 Docker 28 / Compose 2.33 基线支持该语法，[CI #78](https://github.com/xiaochongshanww/Portfolio/actions/runs/31297478841) 已以真实构建、容器健康检查和 OpenWebUI 模型发现证明远程运行链路。
- 远程漂移检查只访问公开镜像，不读取或输出项目密钥；私有仓库支持不在本轮范围。
- Dependabot 能发现版本化 Docker/Compose 引用的更新；同标签重发由独立远程漂移任务补充发现。
- 当前清单摘要来自 2026-08-09 的真实 registry 查询，提交前必须再次执行远程校验，避免在实施窗口内已发生漂移。
- I-032 不改变应用依赖锁、运行知识包、内容来源政策或模型质量状态。

## 验收条件

- 四类外部引用全部采用标签与多架构摘要双重固定，Compose JSON 渲染后仍保留摘要。
- 校验覆盖合法固定、本地构建镜像豁免、缺少摘要、非法摘要、builder/runtime 漂移、Compose 命令失败和远程摘要漂移。
- 主 CI 执行确定性身份校验；独立 workflow 支持每周与手工远程漂移检查，所有 Action 固定提交 SHA。
- Dependabot 配置 Dockerfile 与 Docker Compose 更新入口，发布检查单和部署文档定义更新步骤及边界。
- Ruff、全量后端、前端、三份依赖锁、配置、Compose、质量证据、CI Action、真实容器构建和远程十任务矩阵全部通过。
