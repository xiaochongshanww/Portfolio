# ADR 0004：知识包采用受控兼容矩阵与运行探针

> 状态：已接受
> 决策日期：2026-08-08
> 维护角色：工程负责人
> 文档更新：2026-08-08
> 代码/流程核对：2026-08-08
> 完整运行验证：2026-08-08（Windows/Linux 双向矩阵通过）
> 关联事项：I-009、D-004
> 验证证据：[跨平台知识包兼容验证记录](../releases/跨平台知识包兼容验证记录.md)、[Structural Spec KB CI #18](https://github.com/xiaochongshanww/Portfolio/actions/runs/31248823912)
> 复核周期：Python、Chroma、处理器架构、知识包格式或交付范围变化时

## 背景

运行知识包直接携带 Chroma 持久化索引。ZIP 路径安全、文件大小和 SHA-256 一致只能证明包未损坏，不能证明目标环境能够加载原生索引。旧格式还没有把兼容性和能力声明绑定到包标识，修改清单元数据可能不改变 `package_id`。

同时，“内部证明某组环境可迁移”与“向外部用户承诺跨平台可移植产品”是两个不同决策。后者还受内容权利、签名信任根、目标设备和支持成本约束，不能由一次 CI 成功自动关闭。

## 决策

1. 当前导出格式升级为 schema v4；继续校验和导入 v1、v2、v3。
2. v4 `package_id` 同时绑定数据版本、payload，以及格式、schema、profile、创建时间、计数、兼容性、能力和质量元数据。
3. 兼容元数据记录应用版本、Python 版本与实现、操作系统、规范化处理器架构、Chroma、Embedding 模型和集合名称。
4. 新增 `package-probe`。它在临时数据目录导入知识包，并在独立子进程中实际打开 Chroma、核对集合数量和读取样本；不切换在线活动数据库。
5. CI 由 Windows、Linux 分别生成包含真实 Chroma 索引和中文路径资产的合成包，再在相反操作系统执行严格探针。
6. 当前受控矩阵限定为 CPython 3.11、Chroma 1.5.9、x86_64 Windows/Linux。等价架构名统一为 `x86_64` 或 `aarch64`。
7. D-004 保持未决：上述技术证据不构成对外分发、矩阵外兼容或长期支持承诺。

## 备选方案

1. 只保留静态校验：成本低，但无法发现 SQLite/HNSW/原生库的目标环境加载失败。
2. 正式导入后再启动 API 冒烟：能发现问题，但会污染或切换目标数据，失败回退成本高。
3. 只交付 chunks，在目标端重建向量索引：可移植性更强，但需要 Embedding 凭据、费用、时间和一致性治理；保留为矩阵外或未来交付配置。
4. 宣称 Chroma 天然跨平台：缺少项目栈的可重复证据，也无法覆盖版本与架构变化，不接受。

## 影响

- 知识包导入前多一个真实运行检查，流水线增加两个生产任务和两个反向消费任务。
- v4 清单元数据篡改会导致身份校验失败；旧包仍按原算法验证。
- 独立子进程避免 Windows 上 Chroma 原生索引文件锁影响临时目录清理。
- 每次升级 Python、Chroma 或运行架构都必须重新取得矩阵证据。
- 包完整性仍不证明发布者身份，数字签名继续由 D-003 管理。

## 验证要求

- 单元测试覆盖 v4 身份绑定、v1/v2/v3 兼容和架构别名。
- 本地测试使用真实 Chroma 索引完成导出、校验、隔离导入和样本读取。
- 远程 CI 必须完成 Windows 到 Linux、Linux 到 Windows 双向探测。
- 发布检查单必须要求目标环境执行 `package-probe`。
