# ADR 0028：管理 API 采用响应模型与生成类型契约

> 状态：已接受
> 维护角色：工程负责人
> 文档更新：2026-08-12
> 代码/流程核对：2026-08-12（响应模型、快照、生成类型与 CI 门禁已实现）
> 完整运行验证：I-038 本地 533 项后端测试与完整前端/工程门禁通过；远程 CI 待完成
> 决策日期：2026-08-12
> 关联评估/发布：I-038
> 验证证据：[实施清单](../architecture/管理API与前端类型契约实施清单.md)、[契约规范](../reference/管理API与前端类型契约规范.md)、[验证记录](../releases/管理API与前端类型契约验证记录.md)
> 复核周期：管理 API 路由、响应字段、前端生成器或 OpenAPI 版本变化时

## 背景

控制台已经承担构建、校对、结构化、评估、版本和质量运营工作，但基线审计发现 `/admin` 下 44 个操作的成功响应在 OpenAPI 中全部是空 schema。前端请求函数默认返回 `any`，组件即使通过 `vue-tsc`，也无法发现后端删除字段、改变类型或返回错误结构。现有运行测试能覆盖部分样例，却没有建立所有管理端操作的机器可读契约。

## 决策

1. 每个 JSON 管理端操作必须声明具名 Pydantic 响应模型；文件流端点必须声明准确媒体类型，不伪装成 JSON。
2. 响应模型固定稳定顶层字段和可枚举状态；由解析器、评估报告或结构化草稿承载的开放 JSON 只在明确字段内保留扩展能力。
3. 后端 OpenAPI 由应用代码确定性导出为仓库快照，不依赖运行中的服务、模型凭据或活动知识库。
4. 前端类型只由该快照生成，不手工复制后端接口。生成器使用精确锁定的开发依赖，生成结果进入 Git。
5. 前端 API 函数不再默认返回 `any`；所有调用必须显式声明生成的响应类型，请求正文同样复用生成类型。
6. 本地和 Windows/Linux CI 重新生成 OpenAPI 与 TypeScript，任何未提交差异均失败；OpenAPI 测试同时拒绝空成功响应 schema、重复 operation id 和未覆盖路由。
7. 生成契约只描述传输结构，不替代业务校验、鉴权、内容质量门禁或运行探针。

## 备选方案

- 继续依赖端到端测试：只能覆盖已写样例，字段漂移常在运行时才暴露。
- 手写 TypeScript 接口：短期简单，但后端与前端存在两个权威来源，长期必然漂移。
- 只提交 OpenAPI、不让前端消费：可供阅读，但无法让 `vue-tsc` 保护真实调用。
- 在浏览器运行时引入通用 schema 验证器：可增加防御，但不能替代编译期契约，且增加运行包体积；本轮不采用。

## 影响

- 新增或修改管理 API 时必须同步响应模型并重新生成契约。
- FastAPI 会按响应模型验证实现输出，缺失必需字段将显式失败，不再静默传给控制台。
- 生成文件会增加仓库体积，但换来可审计的接口差异和跨语言单一来源。

## 回退

可移除生成类型消费并恢复宽松请求函数，但不得保留与实现不一致的快照。若某个开放数据结构暂时不能完全建模，应将开放范围限制在明确字段内，而不是撤销整个管理 API 的响应契约。
