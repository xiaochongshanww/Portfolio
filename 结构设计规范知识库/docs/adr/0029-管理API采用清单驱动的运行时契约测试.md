# ADR 0029：管理 API 采用清单驱动的运行时契约测试

> 状态：已接受
> 维护角色：工程负责人
> 文档更新：2026-08-12
> 代码/流程核对：2026-08-12（44 个隔离 ASGI 场景与故障矩阵已实现）
> 完整运行验证：本地 582 项后端测试与完整前端/工程门禁通过；远程 CI 待补
> 验证证据：[实施清单](../architecture/管理API运行时契约覆盖实施清单.md)、[契约规范](../reference/管理API与前端类型契约规范.md)、[验证记录](../releases/管理API运行时契约覆盖验证记录.md)
> 复核周期：管理 API 路由、响应模型、中间件或测试运行环境变化时

## 背景

I-038 已将管理 API 的传输结构固定为 Pydantic、OpenAPI 和前端生成类型，但静态契约只能证明路由声明了什么，不能证明实现函数在代表运行状态下实际返回同样的结构。`/admin/active-db` 曾因旧活动指针中的空路径值触发响应校验 500，说明只校验 schema 和生成文件不足以阻止实现输出漂移。

现有 HTTP 测试覆盖少量状态和任务接口，没有一个会随管理路由增减而自动失败的完整成功路径清单。继续零散增加端点测试仍可能留下无声缺口。

## 决策

1. 每个 `/admin` OpenAPI operation id 必须且只能登记一个运行时成功场景；场景同时固定 HTTP 方法、模板路径和成功媒体类型。
2. 测试从应用 OpenAPI 动态取得权威操作集合，并拒绝缺失、重复、未知和方法/路径/媒体类型漂移。路由增减必须显式维护场景，不能依赖人工记忆。
3. 所有场景通过 FastAPI `TestClient` 执行真实 ASGI 路由、请求解析、响应模型校验、异常中间件和序列化。JSON 结果再由 OpenAPI `$ref` 指向的 Pydantic 模型复验；PNG 结果校验媒体类型与文件签名。
4. 场景使用临时目录和确定性代表数据，至少包含非空任务、版本、评估、校对、结构化、修正和元素载荷；外部模型、MinerU、网络服务、后台线程和真实运行数据均不得参与。
5. 严格响应模型的缺失字段和额外字段必须由统一异常链转换为 HTTP 500 `INTERNAL_ERROR`，证明失败关闭而不是把错误载荷交给控制台。
6. 运行时契约测试是接口实现门禁，不替代服务函数的业务测试、真实知识包冷启动、浏览器测试或发布质量评估。

## 备选方案

- 只依赖 OpenAPI 快照：无法发现实现函数返回值与模型不一致。
- 继续按故障零散补测试：不能证明没有遗漏，也无法在新增路由时自动失败。
- 对所有操作运行完整生产依赖：覆盖更接近生产，但会引入模型凭据、解析器、线程和真实数据副作用，不适合作为每次提交的确定性门禁。
- 直接调用 Python 端点函数：能校验部分返回值，但会绕过路由匹配、请求解析、中间件和 FastAPI 响应序列化。

## 影响

- 新增或删除管理操作时，必须在同一变更中维护运行时场景；否则后端测试失败。
- 响应模型变更必须同时通过静态 OpenAPI 漂移和运行时代表载荷两层门禁。
- 场景替身需要随业务返回结构维护，但只存在于测试环境，不进入运行时产品代码。
- 运行时用例数量随管理操作线性增长，当前固定为 44 个成功场景和 4 个覆盖/故障测试。

## 回退

若 `TestClient` 运行机制因框架升级改变，可替换为等价的 ASGI 客户端，但不得退回只检查 schema 的状态。替代方案必须继续覆盖完整 operation id 集合、真实响应序列化和隔离无副作用要求。
