# ADR 0008：运行数据根采用显式单一配置

> 状态：已接受

> 维护角色：工程负责人  
> 文档更新：2026-08-08

> 完整运行验证：本地 236 项后端测试与远程 CI #30 的九个任务全部通过
> 关联路线图：I-015  
> 验证证据：[运行知识包冷启动验证记录](../releases/运行知识包冷启动验证记录.md)、[Structural Spec KB CI #30](https://github.com/xiaochongshanww/Portfolio/actions/runs/31256712890)
> 复核周期：运行目录、知识包导入或持久卷契约变化时

## 背景

知识包 CLI 已允许通过 `--data-dir` 导入到任意目录，但 API 和管道模块仍在导入时把运行资产固定到项目内 `data/`。这会形成两个彼此独立的路径来源：导入成功只能证明包可以打开，不能证明随后启动的 API 会读取该包。容器、便携目录和空环境部署也无法用一个明确配置绑定持久卷与运行时。

## 决策

1. 使用 `DATA_DIR` 作为运行数据根的唯一主配置；未设置时保持项目内 `data/` 的现有行为。
2. 相对 `DATA_DIR` 统一相对于项目根目录解析，绝对路径按原值使用并规范化。
3. `raw`、`metadata`、`processed`、`images`、`mineru`、`audit`、`corrections`、`manual_structuring`、`structured_tables`、`jobs`、`db_versions`、根 manifest 和活动指针均从 `DATA_DIR` 派生。
4. `IMG_DIR` 和 `SOURCE_METADATA_PATH` 继续作为精细覆盖项；未设置时分别使用 `DATA_DIR/images` 与 `DATA_DIR/metadata/specs.json`。
5. `DB_DIR` 继续作为缺少活动指针时的旧库回退配置，默认值仍为项目内 `db/`，避免无迁移操作改变已有开发环境。
6. `package-import --data-dir` 与 API 的 `DATA_DIR` 必须指向同一目录。CLI 默认值改为运行时解析后的 `DATA_DIR`，但显式参数保持最高优先级。
7. 活动指针继续保存可移植相对路径；读取端保持对既有相对路径和 Windows/Posix 绝对路径的兼容。
8. Windows 与 Linux CI 必须从另一平台生成的真实 Chroma 知识包导入隔离数据根，启动 API，并验证 `/ready` 与知识清单；只完成 Chroma 直接打开不再视为完整冷启动证据。

## 结果

- 部署者可以把全部可变运行数据挂载到源码目录之外，并用单一变量启动 API。
- 测试和 CI 可以在临时目录完成导入与启动，不污染仓库中的真实 `data/`。
- 旧环境未设置 `DATA_DIR` 时行为不变；现有 `DB_DIR`、`IMG_DIR` 和 `SOURCE_METADATA_PATH` 显式配置仍有效。
- 运行时环境变量必须在 Python 进程启动前设置；进程内修改后需要重启，因为路径常量在模块导入时确定。

## 不采用的方案

- **仅在冷启动脚本中复制包到项目 `data/`**：会掩盖 API 路径不可配置的问题，并污染工作区。
- **让 API 自动搜索最近导入目录**：搜索规则不确定，可能激活错误知识版本。
- **立即移除 `DB_DIR`**：会无必要地破坏尚未使用活动指针的旧开发环境。
