# ADR 0002：知识包导出强制质量门禁

> 状态：已接受
> 维护角色：工程负责人
> 文档更新：2026-08-08
> 代码/流程核对：2026-08-08
> 完整运行验证：本地自动化测试已通过，等待远程 CI
> 决策日期：2026-08-08
> 决策角色：工程负责人
> 关联评估/发布：I-005 质量门禁与知识包导出联动
> 验证证据：`src/pipeline/knowledge_package.py`、`src/quality/gate.py`、`tests/test_knowledge_package.py`、`tests/test_quality_gate.py`
> 复核周期：质量阈值、评估成本或知识包格式变化时

## 背景

运行知识包可以把当前活动数据库直接交付到其他环境。此前 `package-export` 只验证 manifest、数据库和文件完整性，不检查检索、结构化表、回答级盲测及任务状态。即使评估报告缺失、过期或明确失败，也能生成看似正常的交付包。

单纯要求操作人员在导出前手工运行检查单不足以形成机器可验证的发布边界。另一方面，质量门禁可能因外部模型故障或评估基础设施异常误阻断受控排障，因此需要保留可追责的紧急出口。

## 决定

从知识包格式 v2 开始，`package-export` 在写入 ZIP 前实时计算质量门禁：

- 常规检索、结构化检索和回答级报告必须匹配当前数据版本与当前评估集哈希。
- 三类评估报告默认不得早于导出时间 7 天，也不得来自未来时间；命令行可在发布策略允许的范围内缩短或调整有效期。
- 门禁未通过时默认阻断导出，并写入 `data/audit/package_exports/`。
- 紧急豁免必须同时提供责任人和不少于 8 个字符的原因；责任人、原因、失败检查和完整门禁快照写入审计事件与包清单。
- 门禁通过时不允许附带无意义的豁免参数。
- v2 包清单必须包含 `quality`；校验器拒绝数据版本不一致、状态矛盾或缺少责任信息的质量证据。
- v2 `package_id` 同时绑定数据版本、payload 和质量证据，门禁状态或豁免内容不同的包不会共用标识。
- 校验和导入继续兼容 v1 包，但 v1 不含机器可验证的质量证据，不能据此宣称已经通过当前发布门禁。

该门禁只证明项目定义的自动质量条件，不证明内容获得分发授权。来源和权利检查仍是独立发布阻断项。

## 备选方案

1. 继续完全依赖人工检查单：实现简单，但无法阻止误操作，也无法从包本身追溯质量状态。
2. 永不允许豁免：边界最严格，但外部模型或评估服务故障时无法进行受控排障交付。
3. 只读取 `quality_gate_latest.json`：开销低，但静态文件可能与当前数据、评估集或报告年龄脱节。
4. 导出时重跑全部评估：证据最强，但回答级盲测成本和耗时较高。当前方案实时重算门禁并验证已有报告溯源；发布操作仍先运行完整质量验证。

## 后果

- 普通知识包导出变成失败即关闭的发布操作。
- 评估报告超过有效期后必须重新运行 `scripts/verify_quality.py`，或留下明确豁免记录。
- 包格式升级到 v2；旧 v1 包保持技术兼容，但质量可信度较低。
- 审计目录会持续增长，维护流程需要按发布保留策略归档，不能随意清空。
- 当前重建仍先激活数据库；本决定只阻断知识包导出，不等同于重建事务化激活。

## 验证与回退

- 自动测试覆盖通过门禁、过期报告、阻断审计、完整豁免、v2 质量证据校验和 v1 兼容。
- 发布前运行完整后端测试、前端构建和知识包往返验证。
- 如新门禁出现误判，只能使用带责任人与原因的显式豁免；不得删除校验调用或伪造报告。
- 若格式 v2 需要撤回，新增替代 ADR 和格式版本；不重写本记录或静默恢复无门禁导出。
