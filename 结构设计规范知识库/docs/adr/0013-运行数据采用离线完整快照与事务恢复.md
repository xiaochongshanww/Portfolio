# ADR 0013：运行数据采用离线完整快照与事务恢复

## 背景

运行知识包用于把可问答的数据库、manifest 和必要共享资产部署到目标环境，已经支持校验、升级与整包回退。它有意排除原始 PDF、任务、审计、批准修正、人工结构化草稿和完整质量历史，因此不能承担主机损坏、持久卷误删或完整环境迁移后的灾难恢复。

当前文档要求 `DATA_DIR` 位于受备份保护的持久卷，却没有仓库内可执行的创建、离线校验和事务恢复契约。只复制若干子目录容易遗漏重建输入或形成跨时间点拼接；直接覆盖目标目录则可能在中途失败后留下半恢复状态。

## 决策

1. 新建独立的 `structural-spec-runtime-backup` ZIP 格式，schema v1。完整快照覆盖指定 `DATA_DIR` 下所有普通文件和目录，不套用知识包的对外分发、质量门禁或能力裁剪语义。
2. 快照根清单为 `runtime-backup.json`，记录文件路径、大小、SHA-256、修改时间、权限模式、目录元数据、总大小、payload 哈希和内容寻址 `backup_id`。ZIP 负载统一位于 `data/`，不保存主机绝对路径、环境变量或仓库外秘密。
3. 创建前拒绝符号链接、输出位于源数据目录内、无法解析的活动任务记录，以及 `queued`/`running` 任务。操作者必须显式确认维护窗口并记录责任人。
4. 创建采用两次完整清单扫描：第一次计算声明并写归档，第二次重新计算源清单。文件集合、内容、大小或元数据在期间变化时，删除未完成输出并失败，不产生可用快照。
5. `backup-validate` 完全离线执行路径、重复成员、符号链接、解压大小、清单、文件声明、哈希、总量与 `backup_id` 校验，不写 `DATA_DIR`。
6. `backup-restore` 必须先完整校验并解压到目标父目录的临时目录。目标非空时只有显式 `--replace` 才允许恢复；替换采用同文件系统原子改名，失败时恢复原目录。目标中的活动任务同样阻断替换。
7. 恢复命令也要求维护窗口确认。API 必须在恢复前停止，恢复后由操作者执行配置预检、`/health`、`/ready`、活动包身份、任务恢复和质量状态核对。
8. 快照为内部高敏运维资产，不自动进入 Git、知识包或发布物。格式本身不加密、不签名；静态加密、访问控制、异地副本、保留期限和删除审计由目标存储系统负责。

## 兼容性

- schema v1 只承诺同应用主版本、受支持 Python/Chroma 运行矩阵内的完整文件恢复；它不把数据库格式转换为跨版本格式。
- `backup_id` 由规范化文件与目录声明计算，不受归档文件名、创建时间或责任人影响。
- 运行知识包和运行数据快照保持两种独立格式：前者用于受控部署与回退，后者用于完整内部恢复。任何工具不得把快照误标为可分发知识包。

## 非目标

- 本决策不实现在线一致性快照、增量备份、持续复制、云存储上传、自动调度或多副本协调。
- 本决策不把 API Key、`.env`、浏览器数据、Open WebUI 数据卷或仓库外日志纳入 `DATA_DIR` 快照。
- 本决策不解决内容授权、备份介质法律保留期限、勒索软件防护或组织级密钥管理。
