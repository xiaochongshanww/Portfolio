# ADR 0012：质量验证采用内置评估资产与显式凭据

## 背景

I-018 已统一验证目标并修正执行失败语义，但还留下两个可移植性和安全边界：

1. 管理评估接口接收 `file` 字符串并在服务端构造 `Path`。同机调用时客户端传入绝对路径可以工作，远程或容器目标则没有相同文件系统；受鉴权接口也不应把任意服务端路径作为常规输入。
2. `verify_quality.py` 只从仓库根 `.runtime_api_key` 读取凭据。该文件没有正式输入契约；关闭鉴权时脚本仍会因文件缺失而失败，启用鉴权时也没有环境变量或外部密钥文件的标准入口。

## 决策

1. 管理 API 只接受内置评估资产标识：检索评估为 `regular` 或 `structured`，回答评估为 `answer`。服务端维护标识到版本化评估文件的映射，任务输出同时记录标识、文件哈希和实际服务端路径。
2. 删除管理请求中的 `file` 字段并禁止未知字段。控制台和验证器同步迁移；任意自定义评估文件只允许在受控本地 Python 调用中使用，不经管理 HTTP API 传递。
3. 验证客户端的凭据优先级为：`QUALITY_API_KEY` 环境变量、显式 `--api-key-file`、`QUALITY_API_KEY_FILE` 环境变量、兼容读取 `.runtime_api_key`。`--no-api-key` 可显式忽略所有来源，用于确认关闭鉴权的目标。
4. 不提供原始 `--api-key` 命令行参数，避免密钥出现在 shell 历史和进程列表。报告只记录凭据来源和是否携带凭据，绝不记录值。
5. 只要本轮需要 API，验证器除 `/ready` 外还必须请求受保护的 `/admin/status`。鉴权预检和就绪预检相互独立，操作者可以同时看到凭据错误与知识库未就绪原因。
6. 没有凭据且目标关闭鉴权时属于合法模式；目标返回 401/403 时，验证器以明确的鉴权错误失败并跳过 API 评估。

## 兼容性

- `.runtime_api_key` 暂作为最低优先级兼容来源保留；新自动化应使用环境变量或不提交到仓库的密钥文件。
- `POST /admin/jobs/evaluate` 的 `file` 字段和 `POST /admin/jobs/evaluate-answers` 的任意额外字段改为 HTTP 422。管理 API 本就不是稳定第三方接口，控制台在同一提交中迁移。
- 报告继续保留实际 `evaluation_set` 路径和哈希，新增稳定的 `evaluation_set_id` 用于跨环境比较。

## 非目标

- 本决策不提供用户上传评估集，也不允许 URL、网络共享路径或仓库外路径。
- 本决策不改变评估用例、阈值、模型或质量门禁。
- 本决策不替代服务端 API Key 轮换、角色权限或集中式秘密管理。
