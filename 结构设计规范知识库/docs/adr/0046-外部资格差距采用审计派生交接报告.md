## 背景

当前 external 发布审计已经能够输出阻断明细，但来源资格、真实试用和精排质量证据分别由不同的台账、证据包、试用记录和质量报告承载。人工交接时容易遗漏责任角色或验证条件，也容易把工程已完成误读成外部资格已完成。

## 决策

增加 `scripts/render_readiness_gap_report.py`，只接受 `profile=external` 的就绪审计 JSON，并从其 `closure.items` 生成一份人工阅读报告。报告仅保留检查项、阻断状态、责任角色、整改动作和验证条件，不生成新的资格结论，也不复制原文或秘密。

输入结构缺失、profile 漂移、顶层和 closure 状态不一致时必须失败关闭。`--require-ready` 只在报告需要作为自动化发布前置条件时启用；当前 external 审计不通过时，报告生成成功不代表发布成功。

## 取舍

- 保留审计 JSON 作为唯一事实源，避免维护第二份可编辑状态。
- 允许在审计未收口时生成交接报告，便于真实证据补齐，而不是隐藏阻断。
- 不把内部研究 profile 的通过结果合并为 external 通过结果。
- 不通过静态规则、计划记录或模拟精排结果替代真实外部证据。

## 后续

真实来源权利、封闭试用和精排质量证据到位后，先更新各自事实源，再重新运行 external 审计和本报告；发布检查单仍是最终执行入口。
