# ADR 0049：规范来源采用内容寻址目录与候选发布

> 状态：已接受
> 日期：2026-08-23
> 维护角色：工程负责人、内容治理负责人
> 文档更新：2026-08-23
> 代码/流程核对：2026-08-23，已核对来源目录、PDF 上传、不可变快照、候选构建、门禁激活和管理台入口
> 完整运行验证：工程回归通过；真实新规范 MinerU 构建和权利人工审批待执行
> 验证证据：`tests/test_source_catalog.py`、`tests/test_source_management_api.py`、`tests/test_candidate_activation.py`、`frontend/src/components/SourcesTab.spec.ts`
> 复核周期：来源存储、管理接口、候选激活、权利模型或知识包格式变化时

## 背景

过去新增规范需要把 PDF 放入 `data/raw`、手工编辑 `data/metadata/specs.json`，再从命令行或通用构建页发起重建。该流程适合早期维护，但不能稳定表达上传、替换、下架、权利状态、来源版本和在线知识版本之间的关系，也容易让维护者误以为修改源目录会直接改变在线内容。

ADR 0048 已确定“增量处理、完整候选发布”，但明确未覆盖浏览器上传和来源治理。本决定补齐该边界，不改变其完整候选和质量门禁原则。

## 决策

1. 新增独立“规范管理”模块，浏览器可上传、编辑、校验、替换、下架、撤销和提交来源变更。
2. PDF 以 SHA-256 内容寻址保存于 `data/source_assets/objects/`；来源使用稳定 `source_id`，替换只新增资产版本，不覆盖旧对象。
3. 运行来源目录保存在 `data/source_catalog/catalog.json`。Git 中的脱敏来源台账继续作为治理证据，不由运行 API 自动修改。
4. 每次构建前固化不可变来源 revision，包含来源选择、资产哈希、元数据快照和只读构建输入目录。
5. 上传和元数据保存只形成待应用变更，不修改活动索引。来源 revision 通过完整候选构建和检索门禁后，与知识版本一同激活。
6. 替换或下架失败时保留旧活动来源和知识版本；活动指针、根 manifest 和内存检索状态在激活异常时一并恢复。
7. B/unknown 级来源不能配置公开图片访问，C 级来源不能进入候选快照。上传成功不是权利审批结论。
8. 初次迁移通过显式“导入现有规范”操作完成，不在 API 启动时隐式复制现有 PDF。

## 数据身份

| 身份 | 作用 |
| --- | --- |
| `source_id` | 长期稳定的规范来源身份 |
| `asset_version_id` | 一次上传或替换的 PDF 版本 |
| `sha256` | PDF 内容身份与完整性校验 |
| `catalog_revision` | 可变来源目录的并发/审计修订号 |
| `source_catalog_revision` | 一次构建使用的不可变来源集合 |
| `data_version_hash` | 解析、Chunk、向量和运行资产形成的知识版本身份 |

## 结果与边界

- 普通维护者不再需要直接编辑 JSON 或用命令行新增规范。
- 原始 PDF、治理元数据和在线索引有独立但可追溯的版本身份。
- 本地 JSON 目录适用于当前单实例、单工作线程部署；多实例写入需要迁移到事务数据库和对象存储。
- 当前自动校验只证明 PDF 可读、未加密、哈希一致和必要元数据完整，不证明扫描质量、规范现行性或分发权利。
- 来源对象暂不自动垃圾回收；历史 revision 或版本仍可能引用的对象不得直接删除。
