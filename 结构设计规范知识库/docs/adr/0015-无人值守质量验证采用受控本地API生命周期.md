# ADR 0015：无人值守质量验证采用受控本地 API 生命周期

> 状态：已接受
> 维护角色：工程与质量负责人
> 文档更新：2026-08-09
> 代码/流程核对：2026-08-09，已核对验证入口、API 启动契约、凭据来源和失败报告
> 完整运行验证：尚未完成，等待 I-022 实现与进程矩阵
> 验证证据：[实施清单](../architecture/质量验证托管API生命周期实施清单.md)、[ADR 0011](0011-质量验证采用显式目标与执行失败语义.md)、[ADR 0012](0012-质量验证采用内置评估资产与显式凭据.md)
> 复核周期：质量验证入口、API 启动方式、凭据模型或单进程所有权变化时
> 决策日期：2026-08-09

## 背景

完整质量验证依赖运行中的 API，因为常规检索应复用活动运行配置，回答盲测还要调用同一服务的问答和图片接口。现有验证器已能预检 `/ready` 与鉴权，也能区分请求失败和质量失败，但操作方仍须在另一个终端先配置并启动 API。

2026-08-08 的最新报告显示常规评估没有执行，24 条回答盲测全部因默认端口拒绝连接而失败。这不是 24 条内容同时回归，而是运行前置条件没有形成单一命令和单一进程所有权。将这种报告直接理解为模型质量会误导决策；反复手工启动又容易出现端口、环境变量、回调地址或凭据不一致。

## 决策

1. `scripts/verify_quality.py` 保留连接外部已运行 API 的现有模式，并新增显式 `--manage-api` 模式；不静默改变旧命令行为。
2. 托管模式只允许 `http://localhost:<port>`、`http://127.0.0.1:<port>` 或 IPv6 loopback 等本机地址，拒绝 HTTPS、路径前缀、查询、片段、用户信息和非 loopback 主机。
3. 目标端口必须空闲。验证器只管理自己创建的 Uvicorn 子进程，不复用、终止或覆盖未知监听进程。
4. API 子进程与验证器继承当前受控环境；父进程只把规范化后的基址写入 `ANSWER_EVALUATION_API_BASE`。任何模型 Key、API Key 或签名 Key 都不得放入命令行参数。
5. 父进程先等待 `/health`，再由既有子验证器执行 `/ready`、鉴权、检索、回答和门禁。启动失败形成新的机器可读失败报告，不继续发送注定失败的评估请求。
6. API 日志写入忽略版本控制的报告目录。反馈到终端或报告的日志尾部必须按已知秘密环境变量脱敏。
7. 父进程对 API 具有唯一生命周期所有权：正常完成、子验证器失败、异常和中断都先温和终止，超时后强制回收；回收失败必须使命令失败。

## 兼容性

- 已有 `--api-base`、`--api-key-file`、`QUALITY_API_KEY` 和 `--no-api-key` 行为保持不变。
- 托管模式不生成或猜测模型凭据，也不修改 `.env`；缺少配置时由 API 启动预检明确失败。
- 自定义端口由同一 `--api-base` 同时约束父进程、验证器和 API 内部回答评估回调，避免默认 8000 漂移。
- 该能力只解决单机验证的可复现生命周期，不改变生产部署、后台任务单实例或 OpenWebUI 拓扑。

## 非目标

- 不自动下载、导入或修复知识资产。
- 不自动创建、轮换或持久化供应商/API 凭据。
- 不把进程成功等同于检索或回答质量通过。
- 不管理远程 API、容器编排、反向代理或多实例服务。
- 不绕过内容授权、人工复杂表核对或发布质量门禁。
