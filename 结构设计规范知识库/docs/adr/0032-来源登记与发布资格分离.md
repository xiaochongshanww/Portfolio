# ADR 0032：来源登记与发布资格分离

> 状态：已接受

> 维护角色：内容治理与工程负责人
> 文档更新：2026-08-20

> 验证证据：[来源登记台账](../governance/来源登记台账.md)、`scripts/validate_source_register.py`、`tests/test_source_register.py`
> 关联评估/发布：I-048
> 复核周期：来源模型、运行元数据或对外边界变化时

## 背景

运行时的 `image_access` 和 `page_image_access` 只能控制资源访问路径，不能证明网络搜集扫描 PDF 的复制、展示、摘录、表格导出或商业使用权。将两者混为一谈会把“技术上能访问”误写成“有权对外分发”。

## 决策

1. 使用独立的机器可读来源台账记录原件哈希、取得凭证索引、权利等级、展示权限、解析版本、复核和下架状态。
2. 台账与 `data/metadata/specs.json` 必须一一映射；哈希漂移、重复来源和权限矛盾阻断结构校验。
3. 台账校验分为两层：默认命令验证工程结构；`--require-release-eligible` 验证对外资格。当前 B 级来源可以通过前者，但必须失败于后者。
4. 台账使用 `release_scope=production` 与 `release_scope=test_only` 区分可进入生产交付的来源和仓库测试夹具；测试夹具不参与生产权利计数，但不得进入活动生产 manifest 或生产知识包。
5. 授权原件、联系人信息、付款凭证和原始 PDF 不因台账而进入治理文档或运行知识包；台账只保存脱敏索引和哈希。
6. 派生文本、图片、表格、向量和回答引用继承原始来源的最严格限制。

## 结果与边界

该决策解决了“工程上没有来源状态控制”的缺口，但不能替代真实权利核查、法律意见、下架流程或用户试用证据。当前 5 个生产扫描来源仍是 B 级，项目不得据此公开或收费分发。
