# ADR 0019：部署环境采用分层只读自检

## 背景

项目已经分别提供应用配置校验、PDF 解析器探测、知识包验证与运行探针、API `/health`/`/ready` 以及发布质量预检。这些入口服务于不同生命周期，但部署者在 API 尚未启动时仍需手工拼接多条命令，才能判断问题来自 Python、依赖、配置、运行资产、模型凭据还是知识生产环境。

统一诊断不能通过“自动修复”掩盖环境事实，也不能把静态环境成立误报为 API、检索或内容质量已经通过。诊断输出还可能进入工单和日志，因此不得包含密钥原值。

## 决策

1. 提供 `python -m src.doctor` 作为部署环境统一只读自检入口。
2. 自检分为两个配置：
   - `runtime` 检查轻量 API 运行所需的解释器、精确锁直接依赖、应用配置、静态资源、活动知识资产和模型凭据；
   - `build` 复用解释器、依赖和应用配置检查，再检查 Embedding 凭据、PDF 输入、知识生产目录与 MinerU 兼容性；它不要求已经存在运行 manifest、数据库、前端产物或回答模型凭据。
3. 每项检查使用稳定标识和 `passed`、`warning`、`failed` 状态；只有必需检查失败才产生非零退出码。
4. 默认输出适合终端阅读的中文摘要；`--format json` 输出带 schema 版本的机器契约。两种格式都包含检查摘要、事实描述和可执行修复建议，不输出任何秘密值、环境变量全量内容或 PDF 文本。
5. 自检不得创建目录、写报告、修改配置、启动网络服务、调用外部模型或执行知识构建。已有活动资产只能读取元数据和路径状态。
6. 环境自检通过只说明启动前静态条件成立。API 启动后仍以 `/ready` 为运行就绪依据，发布仍以质量验证和门禁为依据。

## 结果

- 部署者获得一个跨 Windows/Linux 的统一故障入口，自动化也可依赖稳定 JSON 和退出码。
- 运行与知识生产的重型要求保持分离，避免把 MinerU 误设为轻量问答环境的必需依赖。
- 自检器需要随依赖锁、配置、运行资产契约和解析器兼容策略持续更新。
- 本决策不选择安装器、桌面版或公共 Web 服务，不改变 D-002 的产品交付边界。
