# ADR 0030：前端管理调用采用 OpenAPI 生成客户端

> 状态：已接受
> 维护角色：工程负责人
> 文档更新：2026-08-12
> 代码/流程核对：2026-08-12（生成 client/SDK、44 个语义别名、共享拦截器与全部管理组件已核对）
> 完整运行验证：I-040 本地完整门禁与真实浏览器验证通过；[CI #105](https://github.com/xiaochongshanww/Portfolio/actions/runs/31529342185) 十项任务全部通过
> 验证证据：[实施清单](../architecture/管理API生成客户端迁移实施清单.md)、[管理 API 与前端类型契约规范](../reference/管理API与前端类型契约规范.md)
> 复核周期：管理 API、OpenAPI 生成器、前端认证或请求错误语义变化时

## 背景

I-038 已从确定性 OpenAPI 快照生成响应与请求类型，I-039 又证明了 44 个管理操作的代表运行时输出符合契约。但是前端仍在 `contracts.ts` 手工维护 HTTP 方法、模板化路径、请求体和响应类型之间的条件类型映射，再由 `api.ts` 接受拼接后的 URL。

这层映射可以在路径仍能匹配字符串模板时把某个操作错误地关联到另一个响应类型；OpenAPI 已变化但手写映射未同步时，也可能继续通过类型检查。它因此构成后端 OpenAPI 之外的第二份传输事实源。

本地使用锁定的 `@hey-api/openapi-ts 0.97.3` 验证后，现有快照可以同时生成 Fetch client、逐操作 SDK、请求参数和返回类型；SDK 能根据操作声明序列化路径、查询和 JSON 请求，并根据响应媒体类型解析载荷。

## 决策

1. 前端管理操作必须通过 OpenAPI 生成的逐操作 SDK 调用，不再以字符串 URL 加手写条件类型表达方法、路径、请求体和响应类型关系。
2. 生成器固定启用 `@hey-api/typescript`、`@hey-api/client-fetch` 和 `@hey-api/sdk`；生成产物与 OpenAPI 快照一并提交，并继续由漂移门禁校验。
3. 应用可以维护一个手写语义别名模块，把冗长的生成操作名映射为稳定、可读的界面调用名。该模块只能重导出生成函数，不得重新声明路径、方法、请求体或返回类型。
4. API Key 注入、候选 Key 首次验证、401 全局事件、统一 `ApiError` 和非管理端兼容调用保留在共享适配器中。生成 client 通过拦截器复用这些语义。
5. 页面截图继续由生成操作取得 `Blob` 并创建对象 URL；其生命周期仍由组件负责释放。
6. 生成 client 的认证、错误转换和二进制响应必须有前端单元测试；管理组件完成迁移后，仓库中不得残留 `AdminGetPath`、`AdminPostPath` 等手写映射。

## 备选方案

- 保留现有泛型 URL 包装器：改动最小，但不能消除第二份传输事实源。
- 只生成请求/响应类型：已经是 I-038 的状态，不能绑定方法、路径和参数。
- 在所有组件中直接使用冗长生成名称：契约最直接，但可读性差，生成器命名变化会制造无意义的界面层改动。
- 为每个后端路由重写 operation id：可以改善生成名称，但会同步扰动 44 个运行时场景标识和外部契约，不是消除手写映射的必要条件。

## 影响

- OpenAPI 参数、方法或响应变化会直接改变生成函数签名，并在受影响调用点触发编译失败。
- 生成目录体积增加，但不新增运行时第三方依赖；Fetch client 源码由锁定生成器产出。
- 认证和错误拦截器成为管理 SDK 的运行时边界，需要用单元测试固定行为。
- 非管理端 `/ready`、`/metrics`、`/knowledge/documents` 和聊天流式调用可按各自节奏迁移，本轮不强制扩大范围。

## 回退

若生成 client 在浏览器兼容性或二进制响应上出现不可接受问题，可回退到共享 Fetch 执行器，但每个操作仍必须由生成操作类型绑定，禁止恢复手写路径条件类型。
