## 背景

当前剩余差距需要人工补充来源凭证、权利复核、原始文件处置、封闭试用和产品决策。若这些信息散落在邮件、受限文件夹和多个文档中，容易出现漏项、版本漂移或把计划误当成完成证据。

## 决策

建立不进入 Git 的受控发布证据包索引。索引登记：

- 每个 production 来源的取得、权利复核和存储处置证据引用；
- 来源登记版本、复核责任人和日期；
- 已完成且结论为 `continue` 的封闭试用记录引用；
- D-001、D-002 的决策状态和证据引用；
- 可选精排报告的文件引用和哈希。

索引校验只确认引用完整、路径受限、哈希一致和字段安全，不改变来源登记、试用校验或产品决策的权威性。发布审计只有在显式提供 `--evidence-manifest` 时才增加该检查，避免把受限证据路径硬编码到仓库。

## 后果

- 人工补证有统一入口和明确缺口列表。
- 授权原件、原始规范、截图和密钥不会因工程化而进入代码仓库。
- 证据索引就绪仍不等于对外发布就绪，必须继续通过原有发布门禁。
