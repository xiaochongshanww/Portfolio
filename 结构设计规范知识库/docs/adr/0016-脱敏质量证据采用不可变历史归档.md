# ADR 0016：脱敏质量证据采用不可变历史归档

## 背景

I-025 使系统卡和当前质量状态一致，但单一 `质量证据状态.json` 每次写入都会覆盖上一份可提交证据。被忽略的 `data/audit/reports/*_latest.json` 也只保存最近一次本地执行，因此 Git 历史之外无法稳定回答“当时依据哪份评估资产、结论是什么”。2026-07-05 的历史通过文字就因没有对应产物而无法复核。

原始质量报告可能包含问题、回答、错误详情、本机路径或运行环境信息，不适合直接进入 Git。项目需要保存可审计的最小证据，同时明确它不是数字签名、时间戳服务或外部合规存证。

## 决策

1. 每次有意运行 `python scripts/snapshot_quality_evidence.py --write` 时，从两份本地最新报告和三份评估集生成白名单字段组成的脱敏快照。
2. 同一快照同时写入不可变历史目录 `docs/quality/质量证据历史/`。文件名由验证报告 UTC 时间与规范化 JSON 的 SHA-256 前 12 位组成；相同输入重复执行只保留一份。
3. `docs/quality/质量证据历史索引.json` 完全由历史文件确定性重建，不手工编辑。索引记录状态、时间、失败项、评估集数量、归档路径和完整内容指纹。
4. 写入顺序固定为“历史归档 → 历史索引 → 当前快照”。任一步失败都不得提前发布新的当前快照；同目录临时文件通过原子替换提交。
5. 无 `--write` 模式必须验证历史文件结构、文件名指纹、重复内容、索引一致性，并确认当前快照已经归档。CI 在没有原始审计报告的干净检出中执行同一验证。
6. Git 中只保存脱敏快照和索引，不保存原始问题、回答、错误详情、秘密、绝对路径或 `data/audit/`。历史归档不因结论失败而删除。
7. 本机制提供仓库内部可追溯性和 Git 变更审查，不提供独立时间证明、签名者身份、不可抵赖性或外部信任根。若未来对外发布需要更强证据，另立 ADR 决定签名、可信时间戳和外部保留策略。

## 备选方案

- 仅保留 `latest`：实现简单，但历史结论会再次失去可复核产物，因此拒绝。
- 将完整原始报告提交 Git：保真度高，但扩大问题、回答、路径和运行信息泄露面，因此拒绝。
- 人工维护历史表格：容易遗漏、改错哈希或与实际资产漂移，因此拒绝。
- 立即引入外部存证服务：当前没有对外合规需求和信任主体定义，成本与边界均不明确，暂不采用。

## 影响与回退

- 受控环境每次保留新质量结果后会新增一个小型 JSON 文件，仓库随证据次数线性增长。
- 修改历史文件会触发指纹或索引校验失败；合法纠错必须保留旧归档并生成一份新证据，不覆盖旧内容。
- 若实现需要回退，可停止生成新历史，但不得删除已提交归档；当前快照仍必须与系统卡一致。

## 验收条件

- 相同输入重复写入不新增归档，两个不同时间的输入按时间确定性排序。
- 篡改归档、索引漂移或当前快照未归档均会失败关闭。
- 索引写入失败时，当前快照保持原值。
- 干净检出不依赖 `data/audit/`，Windows/Linux 与 ASCII 控制台均可执行验证。
- 系统卡、架构、运营和发布文档都引用历史索引并声明信任边界。
