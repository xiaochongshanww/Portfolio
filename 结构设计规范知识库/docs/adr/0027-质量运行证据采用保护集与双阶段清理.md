# ADR 0027：质量运行证据采用保护集与双阶段清理

> 状态：已接受
> 维护角色：工程负责人
> 文档更新：2026-08-09
> 代码/流程核对：2026-08-09（决策与实施清单已建立，实现中）
> 完整运行验证：待 I-037 实现、故障矩阵和远程 CI 完成后补充
> 决策日期：2026-08-09
> 关联评估/发布：I-037
> 验证证据：[实施清单](../architecture/质量运行证据保留与受控清理实施清单.md)、[验证记录](../releases/质量运行证据保留与受控清理验证记录.md)
> 复核周期：质量运行格式、脱敏快照、保留期限或审计要求变化时

## 背景

ADR 0026 将每次完整质量验证保存为不可变运行目录，解决了报告混用、部分发布和失败证据覆盖问题。该设计有意不自动删除历史，但持续运行会积累完整、未封存、失败中断和异常目录。当前真实审计目录已经出现未封存的故障注入残留；继续依赖人工浏览和直接删除既不可审计，也可能误删最新运行或脱敏历史引用的原始证据。

## 决策

1. 质量运行清理采用“只读清单 → 持久化计划 → 显式执行”三步流程，不在验证器、API 启动或普通状态读取中自动删除。
2. 清单只接受 32 位小写十六进制运行目录；链接、重解析点、越界路径、损坏封存清单和不可扫描目录标记为异常并禁止自动处理。
3. 保护集至少包含 `quality_run_latest.json` 指向的运行、当前及历史脱敏质量快照引用的运行、按完成时间最近的若干封存运行，以及尚未超过最小保护期的运行。
4. 默认策略保留最近 10 个封存运行；封存运行满 90 天、未封存运行满 7 天后才可进入计划；所有运行至少保护 24 小时。期限和数量可以通过 CLI 显式收紧或放宽，但不能为负数。
5. 指针存在但损坏时清单和计划失败关闭；工具不得猜测最新运行。脱敏快照损坏时同样拒绝生成删除计划，避免丢失其原始证据引用。
6. 计划记录策略、保护集摘要、创建/过期时间，以及每个候选运行的分类、大小、文件数、最新修改时间和内容指纹。计划默认 15 分钟失效。
7. 执行前重新加载指针、脱敏快照保护集和目录指纹。策略、保护状态或内容发生变化时拒绝执行，不以旧计划删除新证据。
8. 删除先把目标原子改名为运行根目录内的隔离名，再递归清理；失败时尽力恢复原名，并把部分失败写入执行报告。
9. 计划、执行报告和 JSONL 事件写入 `data/audit/quality_run_retention/`，只记录运行标识、分类、大小、指纹和错误摘要，不复制问题、回答、报告正文或凭据。
10. Git 中的脱敏历史继续按 ADR 0016 保持不可变。清理本机原始运行不能删除、覆盖或重写已提交的脱敏快照。

## 备选方案

- 验证成功后立即删除旧运行：磁盘可控，但容易在快照或排障前丢失原始失败证据。
- 只按文件修改时间执行定时删除：实现简单，但无法保护最新指针、快照引用和并发变化。
- 永久保留全部原始运行：追溯最完整，但未封存残留和敏感报告会无限增长，长期运维不可控。
- 只提供人工删除说明：无法稳定识别链接、损坏清单和保护集，也缺少可复核审计记录。

## 影响

- 运维人员需要显式执行计划和清理命令；项目不会在无人确认时回收原始质量证据。
- 被脱敏快照引用的原始运行默认长期保护；要解除保护必须先形成新的治理决定，不能通过删除参数绕过。
- 本决策控制本机审计目录生命周期，不改变质量阈值、发布结论、内容授权或外部证据保全边界。

## 回退

可停止使用清理命令并保留现有目录。已经成功删除的原始运行只能从受控 `DATA_DIR` 备份恢复；脱敏 Git 快照不能重建完整问题、回答和错误正文。
