# ADR 0047：Embedding 模型迁移必须通过真实向量与持久化索引门禁

- 状态：已采纳
- 日期：2026-08-20
- 维护角色：架构与质量负责人
- 文档更新：2026-08-20
> 代码/流程核对：2026-08-20，已核对迁移脚本、候选激活门禁、运行时向量探针、独立向量索引和 Chroma 记录层校验
- 完整运行验证：embedding-3 迁移候选已通过门禁并激活；当前活动版本为 embedding-3/1024 维
- 验证证据：[质量证据状态](../quality/质量证据状态.json)、`data/db_versions/embedding-migration-20260820154651/` 候选迁移目录
- 复核周期：Embedding 模型、Chroma 运行库、向量维度或迁移流程变化时
- 范围：向量模型、Chroma 运行库、候选版本激活

## 背景

知识库包含 1635 个 chunk。实测智谱 `embedding-3` 接口可用，并返回显式 1024 维向量。Windows 中文项目路径下，Chroma 1.5.9 的原生 Rust HNSW 索引无法稳定落盘并在重开后加载；依赖旧文件名或仅检查 SQLite 条目会掩盖 dense 索引不可用。当前运行版本因此把文档、元数据和集合记录保留在 Chroma，同时将归一化 `float32` 向量保存为候选目录内的版本化精确向量索引，由运行时执行余弦召回。

## 决策

1. 当前活动版本使用 `embedding-3`/1024 维；配置默认值与活动 manifest 保持一致，模型或维度变化必须重新迁移。
2. 迁移在全新目标目录创建集合，写入新正文、元数据、Chroma 记录和独立精确向量索引；不得复制旧 HNSW 后删除再新增，也不得直接 `update` 向量。
3. Chroma 只通过 SQLite 记录层校验集合条目数量；独立向量索引必须校验模型、维度、ID 集合、有限数值和重载后的向量查询。不得把 Chroma 原生 HNSW 文件名作为跨平台契约。
4. 候选门禁除真实 Embedding 向量探针外，还必须通过 100 条常规检索和 12 条结构化表检索；检索运行优先使用候选目录内的独立向量索引。
5. 任一条件失败时保持旧活动指针不变，并保留候选失败证据；不得仅因 API 余额充足或维度正确而切换模型。

## 后果

迁移会产生一次完整的 embedding 调用成本，并额外保存约 6.7 MB 的 1024 维 `float32` 向量矩阵。精确扫描适合当前 1635 条知识库规模，避免 Windows 中文路径与原生 HNSW 扩展的兼容性风险；数据规模显著增长前，应重新评估专用向量索引。2026-08-20 的候选迁移已通过门禁并激活，后续不得手工修改活动指针。

## 验证证据

- 实测 `embedding-3` 单请求返回 1024 维向量。
- 完整 1635 条本地迁移回放已验证中文路径下独立向量索引可保存、重载和查询。
- 真实候选目录 `data/db_versions/embedding-migration-20260820154651/` 包含 1635 条 Chroma 记录和独立向量索引。
- 候选门禁通过：真实向量探针通过，100 条常规检索失败 0，12 条结构化检索失败 0。
