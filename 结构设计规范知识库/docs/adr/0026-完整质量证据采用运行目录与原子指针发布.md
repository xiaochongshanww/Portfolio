# ADR 0026：完整质量证据采用运行目录与原子指针发布

> 复核周期：质量报告格式、完整验证编排、审计保留或最新报告消费者变化时

## 背景

证据上下文 v1 已能阻断不同运行、不同配置的评估报告被拼成一次发布结论，但常规检索、结构化检索、回答盲测、质量门禁和总验证报告仍分别覆盖 `*_latest` 文件。进程在写入中断时可能留下不可解析文件或半套新旧报告；下一次运行还会覆盖上一轮详细失败证据，只剩脱敏摘要可追溯。

## 决策

1. 每次完整质量验证以 `verification_run_id` 建立 `data/audit/reports/runs/<run_id>/` 运行目录，五类 JSON 与 Markdown 报告先写入该目录，不直接把单项结果发布为完整最新状态。
2. 所有报告使用同目录临时文件、刷新落盘和原子替换写入；读取损坏或缺失的评估报告时，质量门禁必须失败关闭并返回机器可读完整性检查，不能因 JSON 异常直接崩溃。
3. 完整运行结束后生成 `manifest.json`，记录契约版本、运行 ID、完成时间、总结果及每个必需产物的文件名、大小和 SHA-256；清单不复制问题、回答、错误详情或秘密。
4. 只有必需产物存在、JSON 可解析且清单写入成功后，才原子替换 `quality_run_latest.json`。指针只保存运行 ID、清单身份和相对产物路径，不允许绝对路径或目录穿越。
5. `*_latest` 文件继续作为旧消费者的兼容副本，但新代码优先解析原子指针。指针是最新完整运行的权威入口；兼容副本中断或混合时不能覆盖指针结论。
6. 带运行 ID 的后台评估只写对应运行目录；没有运行 ID 的控制台单项评估继续写兼容 `latest`，但不得创建或切换完整运行指针。
7. 完整验证中被显式跳过或因前置条件失败而未执行的评估必须生成同运行的失败占位报告，使证据包结构完整且门禁明确失败，不得借用上一次报告补齐。
8. 运行目录包含可能敏感的详细问题、回答和错误，继续由 `data/audit/` 忽略并纳入受控运行数据备份；Git 历史只保留既有脱敏快照与索引。
9. 托管 API 模式采用两阶段发布：子验证器只形成未封存的运行目录和受控交接文件，父进程完成 API 回收并合并生命周期结果后写入最终验证报告、清单和指针；子进程不得提前切换最新指针。
10. `manifest.json` 出现后运行目录进入只读状态；发布兼容副本或指针时发生故障，可以在产物哈希和发布参数未变化时重试，但不能覆盖已封存报告。

## 备选方案

- 只把现有 `latest` 改成原子写：可避免半个 JSON，但不能保证五类报告作为一组发布，也不能保留每次运行的详细证据。
- 只依赖运行 ID 检查：能识别混合，不能防止旧证据被覆盖或读取时崩溃。
- 把完整报告提交 Git：可追溯但会持久化问题、回答、错误和潜在内容派生物，不符合当前最小披露边界。
- 使用数据库保存证据：当前单机文件运行模型不需要额外服务；运行目录、清单和原子指针已经能提供确定性契约。

## 影响

- 完整验证会新增运行目录、清单和最新指针；磁盘占用随运行次数增长，现阶段优先保留审计证据，不自动删除。
- 旧部署没有指针时继续读取 `*_latest`；首次新契约完整运行后自动切换到指针优先。
- 预检仍保持无报告写入；诊断性部分验证会发布一套明确失败的完整运行证据，而不是保留表面可用的旧结论。
- 运行指针和清单提供完整性与原子发布，不构成数字签名、可信时间戳或抵抗主机管理员篡改的外部证明。

## 回退

可回退到兼容 `*_latest` 读取，但不得删除已经形成的运行目录来掩盖失败记录。回退后的质量结论必须注明不再具备运行目录与原子指针保证，旧指针不能被解释为回退代码新生成的证据。
