# ADR 0005：候选版本通过预激活门禁后事务化切换

> 状态：已接受
> 决策日期：2026-08-08
> 维护角色：工程负责人
> 文档更新：2026-08-08
> 代码/流程核对：2026-08-08
> 完整运行验证：2026-08-08，CI #21 全部通过
> 关联事项：I-011
> 验证证据：[候选版本事务化激活验证记录](../releases/候选版本事务化激活验证记录.md)
> 复核周期：重建、评估、活动指针或运行资产布局变化时

## 背景

旧重建流程在候选 Chroma 构建完成后立即覆盖根 manifest、写入活动指针并重载在线检索状态，常规检索、结构化表和回答级质量检查只能在激活后执行。失败版本可能短暂在线；同时，解析文本、图片、MinerU 产物和审计目录仍是全局可变目录，单独版本化数据库不能保证完整回退。

现有完整质量门禁还包含经 HTTP 调用在线 API 和外部 LLM 的回答级盲测。为了在激活前执行它而临时替换全局检索状态，会让在线请求看到候选数据；在同一进程启动第二套隔离 API 又会引入端口、密钥、模型费用和生命周期管理，不应伪装成简单检查。

## 决策

1. 管理端重建把 `db`、`processed`、`images`、`mineru`、`audit`、manifest 和候选质量证据写入 `data/db_versions/{job_id}/`，构建期间不覆盖活动运行资产。
2. 候选版本使用独立 `RetrievalState` 打开 Chroma、构建 BM25，并核对集合数量；不修改全局在线检索状态。
3. 激活前强制运行 100 条常规检索评估和 12 条结构化检索评估，并检查 manifest、数据版本、Embedding/collection 契约、必需产物和高风险审计项。任一阻断项失败时保留候选证据，但不写活动指针。
4. `data/active_db.json` 同时指向活动数据库、解析文本、图片、MinerU、审计目录和版本 manifest，是运行资产的提交点。`data/manifest.json` 保留为兼容副本。
5. 切换时先原子写根 manifest，再原子写活动指针，最后以锁保护的一次状态替换更新在线 Chroma/BM25；任一步抛错时恢复旧指针和旧根 manifest。指针提交与内存替换之间的短窗口最多继续读取旧内存状态，不读取未通过门禁的候选状态。
6. 回答级盲测不纳入本次预激活门禁。它继续作为完整发布质量门禁独立执行；概览和 API 必须分别展示“候选版本激活门禁”和“完整发布质量门禁”。
7. 运行知识包导入保留其隔离探针和安装事务；导入的活动指针至少声明数据库、manifest 和安装后的图片目录。

## 备选方案

1. 激活后运行完整门禁并失败回退：实现简单，但失败版本已经可能被请求读取，不接受。
2. 只验证 manifest 和 Chroma 数量：无法发现检索排序或权威性回归，不足以成为激活门禁。
3. 在在线进程中临时切换候选状态运行回答盲测：会污染在线请求边界，不接受。
4. 启动隔离候选 API 并完成回答盲测后激活：保证最强，但涉及外部 LLM、临时服务和成本治理；保留为后续增强，不能阻塞本次确定性改进。

## 影响

- 每次重建增加 112 条确定性检索评估，耗时和 Embedding 调用量上升。
- 失败候选及其报告保留在版本目录，便于诊断，也需要后续版本保留与清理策略。
- 活动图片和解析文本由活动指针解析；历史无扩展字段的指针继续回退到原 `data/processed` 与 `data/images`。
- 完整发布门禁仍可能因回答报告缺失、过期或失败而阻断发布，即使候选激活门禁已经通过。

## 验证要求

- 故障注入必须证明门禁失败不修改活动文件，状态替换失败恢复旧指针和根 manifest。
- 候选 Chroma 加载失败不能清空已有在线状态。
- API 与控制台分别展示候选激活和完整发布门禁。
- 后端全量测试、前端构建、容器冒烟和远程 CI 全部通过后，I-011 才可标记完成。
