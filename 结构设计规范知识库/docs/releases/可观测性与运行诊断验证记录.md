## 验证范围

本记录覆盖路线图 I-007 的单实例可观测性基础，不将其表述为集中日志、Prometheus 指标、分布式追踪或不可篡改审计系统。

## 已实现契约

| 能力 | 当前行为 |
| --- | --- |
| 日志格式 | `LOG_FORMAT=json` 为默认单行 JSON；可切换为保留结构字段的 `text` |
| 请求关联 | 校验入站 `X-Request-ID`，非法值替换；响应和请求日志返回同一 ID |
| 隐私最小化 | RAG 日志只记录查询字符数、候选数和上下文规模，不记录完整查询；请求日志不记录客户端 IP |
| 后台任务 | 创建请求的 `request_id` 保存到任务，并传播到工作线程、事件日志和任务 JSONL |
| 就绪检查 | 依赖全部满足返回 200；否则返回 503、`reasons`、数据版本和逐项检查 |
| 运行指标 | 提供启动时间、运行时长、请求/响应/处理中数量、路由组/状态/错误分布和耗时统计 |
| 控制台 | 未就绪响应仍可展示；嵌套指标、失败原因和任务请求 ID 可人工阅读 |

## 保留限制

1. 指标存储在进程内，重启清零，多个 worker 或副本不会自动聚合。
2. 当前没有指标持久化、Prometheus exposition、集中日志后端或 Trace ID/Span ID。
3. `request_id` 用于技术关联，不代表经过认证的用户、租户或审计主体。
4. 后台任务是单进程线程池，进程中止后的恢复、超时和卡死检测仍需后续完善。
