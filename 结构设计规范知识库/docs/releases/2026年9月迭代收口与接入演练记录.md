### 接入演练发现

合成一页诊断 PDF，不包含规范取值，也不导入正式数据。首次在临时 API 中完成上传、元数据修改、来源快照、PyMuPDF 解析、4 个 chunk 和真实 embedding 生成，但持久化等待超过 600 秒演练时限。

二次线程栈确认停在 `_wait_for_hnsw_sync` 的休眠循环。数据库 `embeddings` 已有 4 条，`embeddings_queue` 仍保留 4 条，元数据消费序号已到 4。队列表是可保留的重放日志，不能把条目总数当成未完成写入数量。

修复改为等待当前精确向量检索依赖的持久化记录数量，再进行停库后的持久化复验；保留超时、数据完整性和候选门禁，不主动清空 Chroma 日志，也不降低评估阈值。新增 7 项记录持久化测试，覆盖保留重放日志、延迟落库、记录数量不符、数据库缺失和损坏。

修复后，同一合成 PDF 在约 28.2 秒内完成构建并进入门禁（任务 `8a5002b6e328`）。产物包含 4 个 chunk、1 张图片、向量和 manifest；常规门禁按预期拒绝非规范语料，未写入活动指针。临时目录没有活动基线，因此请求的增量模式按既有规则回退为全量。证据：`.tools/iteration-20260921/intake-hv6g_tm7/result.json`。此项使用 PyMuPDF，不代表 MinerU/GPU OCR 已验收。

另用现有 7 份规范、2689 个 chunk 的副本验证正向路径，不重新解析，不冒充新规范：100 条常规评估和 12 条结构化评估均无失败，候选激活函数成功切换临时活动指针；重新加载后 Harness 检索命中正文结构化表，引用截图返回 HTTP 200、162582 字节。正式活动指针前后字节一致。

正向证据位于 `.tools/iteration-20260921/activation-r02hghb_/`：`data/db_versions/baseline-copy/quality/candidate_activation_gate.json`、`asset-followup.json`。首次脚本的 `result.json` 保留失败记录：测试副本未包含来源目录，且 TestClient 默认来源名不是回环 IP，引用请求被 403 拒绝。补齐原样来源配置并显式模拟 `127.0.0.1` 后复验通过；未修改业务鉴权代码或扩大来源权限。脚本直接调用激活函数，没有经过任务调度器的最终状态收尾，因此临时任务记录不能作为后台完整作业成功的证据。

以上是两段独立演练：合成输入覆盖接入和拒绝发布，既有基线副本覆盖门禁通过、激活和引用。尚未证明一份真实新增扫描规范连续完成全部生产步骤。
