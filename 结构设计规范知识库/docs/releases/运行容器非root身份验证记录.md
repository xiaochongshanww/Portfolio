## 当前基线

`structural-spec-kb:i046-local` 的镜像配置没有声明用户；以 `id -u` 和 `id -g` 启动的真实容器均返回 `0`。运行依赖从 builder 的 `/root/.local` 复制到最终镜像，因此直接切换用户还会破坏依赖可见性。

## 验证目标

1. 依赖在 `/opt/venv` 构建、检查并复制，最终环境不引用 `/root/.local`；
2. 最终 Dockerfile 在所有安装、目录准备和文件复制之后声明专用非 root 用户；
3. Compose 支持将镜像用户构建为 Linux 宿主机 UID/GID，避免绑定卷不可写；
4. 本地和 CI 真实容器验证 UID 非 0、`/app/data` 可写、API 健康和静态控制台可访问；
5. OpenWebUI 联调仍使用同一非 root API 镜像并通过绑定卷启动。

## 当前证据

- 实施前 4 项契约按预期失败，覆盖 root 家目录依赖、缺少专用用户、Compose 无身份参数和 CI 无实跑探针；
- 使用 `APP_UID=12001`、`APP_GID=12001` 的真实镜像构建成功，builder 的 `pip check` 返回无冲突；
- 镜像 `Config.User` 为 `app:app`，真实容器 UID/GID 为 `12001:12001`，Python 与 Uvicorn 均来自 `/opt/venv`；
- venv 与系统安装工具均不在最终运行路径，`python -m pip` 不可用；
- `/app/data`、`/app/db`、`/app/logs` 均可写，API `/health` 为 `ok`，控制台静态页为 HTTP 200；8021 测试容器已清理；
- `APP_UID=0` 的真实构建在用户创建前失败关闭；空值、非数字和零值由分别校验的正整数契约拒绝。
- 三份依赖锁、`pip check`、Ruff、OpenAPI、配置示例、质量快照、容器策略和 Docker 上下文校验全部通过；后端为 `608 passed, 1 skipped`；
- 前端干净安装、安全审计、生成 API 契约、17 项组件测试、类型检查和生产构建全部通过，审计为 0 漏洞；
- 测试容器均已清理，原有 `127.0.0.1:8000` API 仍保持监听。

## 结论边界

当前本地完整证据证明实现边界成立；远程 Linux 绑定卷和 OpenWebUI 联调完成前，I-047 保持实施中。非 root 不证明容器不可逃逸，也不替代平台沙箱、镜像扫描或宿主机权限治理。
