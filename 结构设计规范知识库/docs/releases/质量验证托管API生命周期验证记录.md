## 验证范围

本记录验证 `scripts/verify_quality.py --manage-api` 是否能在单条命令内安全启动本机 API、复用同一目标执行既有质量流程，并在所有结果路径回收自己创建的进程。它不把 API 可启动解释为知识内容、检索结果或模型回答已经通过。

## 当前质量结论

真实项目生命周期试跑刻意跳过检索和回答评估，只读取既有自动质量门禁。托管 API 启动和回收均通过，但门禁因 `regular_evaluation`、`answer_evaluation` 和 `regular_report_freshness` 未通过而返回非零。这证明生命周期与内容门禁可以独立表达，不证明当前内容质量回归，也不证明内容质量通过。

当前环境没有受控可用的模型供应商凭据来源，因此尚未重新执行 100 条常规检索、12 条结构化检索和 24 条回答盲测。凭据不得写入命令行、Git 或验证记录；该外部证据缺口保持显式，不阻断已经可独立证明的工程实现。
