组件测试覆盖以下行为：

1. 关闭鉴权且无本地 Key 时直接进入控制台。
2. 首次探测返回 401 时只显示验证界面，不继续请求其他受保护资源。
3. 有效候选 Key 先通过 `/admin/status`，随后才写入本地存储并加载数据。
4. 无效候选不会覆盖此前保存的 Key，输入内容不会被 401 事件清空。
5. 手工刷新遇到 401 时在单次探测后停止，不产生受保护接口请求风暴。
6. 网络异常和 5xx 进入可重试的服务不可用状态，不显示鉴权弹窗。

首次全量测试曾因新实施清单缺少文档治理元数据失败，结果为 `230 passed, 1 failed`；补齐强制元数据后重新执行并通过 231 项测试。该失败属于有效门禁发现，不是产品代码回归。

## 3. 真实运行矩阵

本机使用真实 FastAPI、活动 1635 条 Chroma/BM25 数据和 Vite 开发服务验证。测试凭据为临时本地值，不使用生产或用户密钥。

| 模式 | 视口/动作 | 观察结果 |
| --- | --- | --- |
| `API_AUTH_ENABLED=false` | 1280px 首次访问，无浏览器 Key | 未出现验证弹窗，直接显示 6 份文档和 1635 chunks |
| `API_AUTH_ENABLED=false` | 390x844 | 页面宽度与视口同为 390px；主区可纵向滚动，无页面横向溢出 |
| `API_AUTH_ENABLED=true` | 390x844，无 Key | 只显示验证界面；工作区未渲染；API 日志只有一次 `/admin/status` 401 |
| `API_AUTH_ENABLED=true` | 输入无效候选 | 保持弹窗和候选输入；只新增一次 `/admin/status` 401 |
| `API_AUTH_ENABLED=true` | 输入有效候选 | 弹窗关闭，加载完整工作区；后续请求携带已验证 Key |
| `API_AUTH_ENABLED=true` | 1440x900 刷新 | 已保存 Key 自动通过探测；页面无横向溢出，浏览器无 warning/error |
| API 进程停止 | 点击刷新 | 显示“后端暂时不可用”和 HTTP 502 说明，不显示 API Key 弹窗 |
| API 恢复 | 点击重新连接 | 恢复完整工作区，不需要重复输入有效 Key |

运行完成后已关闭临时 API/Vite 进程、清理浏览器测试标签并恢复默认视口。启动对账报告 `recovered_count=0`、`corrupt_count=0`，未改写既有任务状态。

## 4. 当前限制

1. 当前仍是单实例 API Key，而非用户账号、角色、租户或服务端会话。
2. Key 保存于当前浏览器 `localStorage`；生产环境必须使用 HTTPS、强随机 Key 和受控终端，不把该机制当作高等级凭据管理。
3. 本轮验证 FastAPI 与项目控制台的握手；Open WebUI 的独立连接 Key 和完整 Compose 拓扑仍按部署手册保留为待验证项。
4. 本机未运行 Docker Linux engine，容器构建与冒烟证据由远程 CI 补齐后才能关闭 I-014。
