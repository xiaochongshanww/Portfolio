## 验证范围

- 将数据源文档分类为新增、变化、复用和删除，并记录原因。
- 把 PDF、元数据、批准修正、结构化表修订和处理契约纳入复用判定。
- 从不可变活动版本复用解析资产，从精确向量索引按稳定 Chunk ID 复用向量。
- 对缺失、损坏、维度错误、非有限或零向量执行重新 Embedding。
- 始终构建包含全部活动文档的独立候选数据库和精确向量索引。
- 处理契约不兼容、旧 manifest 无契约或活动向量缓存不可用时自动全量回退。
- 候选门禁失败不更新活动指针；激活成功后才发布派生缓存索引。
- 管理 API 和前端支持变更预检、默认增量和显式强制全量重建。

## 已验证语义

第一次从没有处理契约的旧活动版本升级时，系统会有意执行一次全量基线构建。完成基线后，未变化文档可以复用解析资产，稳定 Chunk 可以复用向量。删除或替换文档不会直接修改在线集合，而是在完整候选中排除旧资产，通过门禁后一次切换活动指针。

`data/document_cache/index.json` 是激活后的派生诊断索引。它损坏或发布失败不会把候选误认为活动版本，也不会取代 `active_db.json` 的提交语义。

## 结论边界

本记录证明增量处理、完整候选组装、自动全量回退和管理入口的工程行为已经通过本地自动化验证。它不证明真实规范集上的耗时、配额和磁盘收益，也不证明浏览器上传、来源权利审批或回答级质量已经完成。真实性能数据应在可用的受支持 MinerU 环境中，分别执行强制全量和典型新增、替换、删除场景后补录。
