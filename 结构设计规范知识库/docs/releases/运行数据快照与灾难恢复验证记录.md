## 已验证契约

1. `backup-create` 只在显式维护窗口、无活动任务且输出位于 `DATA_DIR` 外时创建完整快照，并用两次 inventory 扫描拒绝创建期间变化。
2. schema v1 清单声明根目录、普通文件、空目录、大小、SHA-256、修改时间、权限模式、payload/inventory 哈希和内容寻址 `backup_id`。
3. `backup-validate` 完全离线工作，拒绝路径穿越、重复成员、ZIP 符号链接、超限、未声明或缺失负载、内容篡改、目录拓扑和身份不一致。
4. `backup-restore` 先校验并解压到目标同文件系统临时目录；非空目标必须显式 `--replace`，安装失败恢复原目录，二次回退失败时保留旧数据并报告位置。
5. 三个命令成功和失败均输出机器可读 JSON；创建和恢复不读取、复制或输出 API Key。
6. 完整快照与可分发运行知识包保持不同格式、目的和权限边界。

## 故障矩阵

| 场景 | 已验证结果 |
| --- | --- |
| 无维护窗口确认 | 创建和恢复拒绝执行 |
| 活动或损坏任务记录 | 创建拒绝；活动目标和活动备份也拒绝恢复 |
| 源内输出、源符号链接 | 创建拒绝 |
| 两次扫描间源变化 | 临时归档删除，不生成可用快照 |
| 路径穿越、重复成员、ZIP 符号链接 | 离线校验拒绝 |
| 超限、负载篡改、身份篡改 | 离线校验拒绝 |
| 非规范排序或父目录声明缺失 | 离线校验拒绝 |
| 损坏归档或解压失败 | 目标目录不发生变化 |
| 非空目标未指定 `--replace` | 恢复拒绝 |
| 目标安装失败 | 原目标完整回退 |
| 自动回退再次失败 | 临时目录保留旧数据，错误返回保全位置 |

## 能力边界

- 快照是停机维护能力，不提供在线一致性、增量备份、持续复制、多副本协调或自动调度。
- 格式本身不加密、不签名，也不上传外部存储；静态加密、访问控制、异地副本、保留和删除审计由目标存储系统负责。
- 快照只覆盖指定 `DATA_DIR`，不包含 `.env`、API Key、OpenWebUI 数据卷、浏览器状态或仓库外日志。
- schema v1 不转换 Chroma 或其他数据库格式，只承诺受支持应用主版本和运行矩阵内的文件级恢复。
- 恢复成功不等于服务已可用；仍须重启 API 并核对配置、`/health`、`/ready`、活动包、质量状态和任务启动对账。
- 本验证不授予原始 PDF 或派生产物的分发权；完整快照必须按高敏内部资产处理。
