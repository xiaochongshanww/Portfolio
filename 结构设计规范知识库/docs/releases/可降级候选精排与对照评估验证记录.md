- 远程 CI：[Structural Spec KB CI #89](https://github.com/xiaochongshanww/Portfolio/actions/runs/31301665110) 十项任务全部通过，包括依赖锁、Windows/Linux 后端、前端、运行容器与 Trivy、OpenWebUI 鉴权集成、双平台产包和 Windows↔Linux 双向消费。
- 真实智谱精排 API：已使用受控凭据尝试调用；包括 2026-08-20 的最小探测在内，提供方返回 HTTP 429（额度或可用资源不足），没有把该失败写成质量结论，也没有输出响应正文或保存凭据。
- 真实 100 条基线/精排对照：未形成有效完整结果；对照工具在发生降级时已失败关闭，不能宣称精排提高检索质量，也不能在默认配置中启用。
- 受控执行入口：`scripts/run_rerank_evidence.py` 从外部 Key 文件读取凭据，只在调用期间注入并在返回/失败后恢复环境，只写独立对照报告，不覆盖当前质量运行指针；当前环境未注入可用供应商 Key，尚未形成新的真实结果。
- 完整执行入口：`scripts/run_rerank_quality_evidence.py` 可从独立 Key 文件启动临时 loopback API，执行精排对照和启用精排的回答盲测，生成发布审计所需的两份独立报告并回收 API；当前仍未提供可用外部凭据，未执行真实运行。
- 空候选池或缺少 `_rerank_rank` 元数据的用例：对照工具失败关闭，不计入真实精排成功数。
- 供应商降级时对照报告仅保留脱敏错误代码和可选 HTTP 状态，例如 `rate_limited / 429`，不保存上游正文、查询或密钥。
- 回答级盲测：主质量运行已通过，但尚未执行“启用精排配置”下的回答级盲测，因此不能据此打开精排默认开关。

## 回退

设置 `RERANK_ENABLED=false` 并重启 API 即恢复既有基线检索，不需要重建或迁移知识资产。精排元数据只存在于单次运行结果，不写入 Chroma、活动 manifest 或知识包。当前对照工具在 429 等降级场景下返回非零退出，并保留不完整标记。
