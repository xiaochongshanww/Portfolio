## 验证目标

证明质量验证不再把“配置了非空 Key”误判为“供应商能力可用”，并保证能力失败发生在三类内容评估之前。探测结果必须脱敏，`--preflight-only` 不得写质量报告，`/ready` 不得变成依赖外网的高频探针。

这份运行证明旧预检只能确认 Key 非空和本地资产就绪，不能确认真实外部能力。它不证明模型内容质量差，也不能被改写为发布通过。

## 本地验证

实现新增受保护的 `POST /admin/provider-probes`，并将其放在 `/ready` 与 `/admin/status` 之后、三类评估之前。当前故障矩阵覆盖成功、401/403、429、超时、5xx、网络不可达、无效载荷和未配置；响应只保留稳定状态、模型、能力、延迟和可选 HTTP 状态。

使用独占 loopback API、现有知识资产和合成失效供应商凭据执行 `--preflight-only`，两项能力均返回 `auth_failed`/HTTP 401，命令在约 0.36 秒内退出非零。验证期间：

- 没有启动常规、结构化或回答评估；
- 没有修改权威质量指针或报告；
- 输出没有出现供应商 Key、探测文本、上游正文或模型输出；
- 托管 API 已由父进程回收；既有 8000 端口服务未被接管。

## 结论边界

供应商探测成功只证明两条调用链在该时刻可用。它不证明额度长期充足、供应商 SLA、检索命中率、答案正确率或发布质量；这些结论仍由同次完整评估和质量门禁给出。
