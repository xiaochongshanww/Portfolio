## 1. 验证目标

证明预构建 Chroma 运行知识包在受控技术矩阵内可以跨 Windows/Linux 迁移，并把验证变成每次提交可重复执行的流水线契约。本记录不证明包内规范内容可向第三方分发，也不关闭 D-003、D-004。

## 2. 受控矩阵

| 维度 | 当前范围 |
| --- | --- |
| Python | CPython 3.11，按 `requirements-runtime.txt` 哈希锁安装 |
| Chroma | 1.5.9 |
| 架构 | x86_64；AMD64/x64/x86_64 规范化为同一架构 |
| 来源与目标 | Windows -> Linux、Linux -> Windows |
| 包格式 | 导出 v4；校验兼容 v1/v2/v3/v4 |
| 索引内容 | 3 条显式四维向量、中文正文与元数据 |
| 可选资产 | 中文文件名的结构化表、图片和来源访问策略 |

合成包只用于技术兼容验证，不包含项目真实规范 PDF、真实向量或生产密钥。由于合成数据不满足生产评估时效，生成器使用仅限 CI 的显式质量豁免，并记录责任人和原因。

## 3. 机器验收契约

1. Windows 和 Linux Runner 分别按哈希锁安装运行依赖。
2. 每个平台调用生产 `package-export` 实现生成真实 Chroma ZIP，并上传短期 CI artifact。
3. 相反平台下载包，运行 `package-probe --expect-source-platform ... --require-cross-platform`。
4. 探针必须完成静态校验、临时导入、Chroma 打开、集合计数和样本读取。
5. 来源与目标操作系统必须不同；除一个操作系统差异外不得存在其他兼容告警。

## 6. 已知边界

- 未验证 macOS、aarch64、32 位平台、其他 Python 主次版本或其他 Chroma 版本。
- 当前探针证明索引可读和计数一致，不代替问答质量评估、Embedding 服务连通性或来源授权审核。
- GitHub artifact 是 CI 内短期交换介质，不是产品分发渠道。
- SHA-256 和 v4 身份绑定不能证明发布者身份；不受控渠道仍需要 D-003 的签名与信任根决策。
- 如目标环境超出矩阵，应重新构建索引，或设计 chunks + 目标端向量化的可移植配置。
