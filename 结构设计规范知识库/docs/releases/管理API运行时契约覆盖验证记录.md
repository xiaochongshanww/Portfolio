## 验证目标

证明 `/admin` 的每个 OpenAPI 操作都具有一个无生产副作用的真实 ASGI 成功路径，并且路由清单漂移、实现输出缺失必需字段或携带未声明字段时会失败关闭。本记录不证明模型回答质量、真实生产数据全部组合、业务权限或公网部署通过。

## 实现范围

- `tests/test_admin_runtime_contract.py` 登记 44 个操作场景，以 operation id 对照当前 OpenAPI 的方法、模板路径和媒体类型。
- 每个场景通过 `TestClient` 执行实际请求解析、路由匹配、中间件、响应模型和序列化；43 个 JSON 结果由 OpenAPI `$ref` 指向的 Pydantic 模型复验，1 个页面结果校验 PNG 媒体类型和文件签名。
- 临时目录承载 PDF、审批修正和页面图片，确定性替身覆盖任务、检索、版本、评估、校对和结构化服务；测试不调用模型、MinerU、网络或后台线程。
- 故障矩阵覆盖缺失、未知、重复和方法/路径/媒体类型漂移场景，并覆盖严格响应缺失必需字段和额外字段的 HTTP 500 失败语义。
- 管理端 6 处 Pydantic v2 `dict()` 调用迁移为 `model_dump()`，消除运行时覆盖触发的弃用警告。
- `requirements-tools.txt` 改为 ASCII 可读说明，并新增防回退断言，修复裸 Windows venv 旧版 pip 按 GBK 解码 UTF-8 中文注释导致的安装失败。

## 已知边界

1. 隔离场景验证代表性载荷，不穷举生产文件中所有开放 JSON 组合。
2. 服务函数内部算法仍由各自单元与集成测试负责；运行时契约测试不重复模型推理或 PDF 解析。
3. `TestClient` 当前产生上游 `httpx` 迁移提示，不影响本轮响应结果；框架升级时应按 ADR 0029 保留等价 ASGI 覆盖。
4. 发布质量仍为 `not_passed`，本轮不改变 100 条常规、12 条结构化和 24 条回答真实复验要求。

## 当前结论

I-039 的实现、故障矩阵、本地完整门禁和远程跨平台证据均已齐备。管理 API 运行时契约覆盖进入生效维护状态；本结论不改变发布质量仍为 `not_passed` 的事实。
