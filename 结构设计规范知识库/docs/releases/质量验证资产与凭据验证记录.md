## 已验证契约

1. `POST /admin/jobs/evaluate` 只接受 `regular` 或 `structured`，回答评估只接受 `answer`；旧 `file`、未知标识和额外字段返回 HTTP 422。
2. 服务端维护标识到版本化评估文件的映射，任务输出、JSON 和 Markdown 报告写入 `evaluation_set_id`。
3. 控制台和 `verify_quality.py` 不再向管理 API 发送客户端文件系统路径。
4. 验证客户端支持 `QUALITY_API_KEY`、`--api-key-file`、`QUALITY_API_KEY_FILE`、兼容 `.runtime_api_key` 和 `--no-api-key`。
5. `/ready` 就绪预检与 `/admin/status` 鉴权预检相互独立；关闭鉴权允许空 Key，错误 Key 返回可操作的 401 诊断。
6. 正确 Key、错误 Key、stdout、stderr、JSON 报告和对象表示均通过脱敏断言，未出现凭据值。

## 能力边界

- `.runtime_api_key` 仍作为最低优先级兼容来源保留，新部署不应依赖它。
- 管理 API 不支持用户上传或指定自定义评估文件；自定义用例只允许受控本地 Python 调用。
- 本轮隔离进程验证没有调用外部模型，也不证明 24 条回答盲测当前达到发布阈值；发布前仍需在完整活动知识库和真实模型凭据环境运行完整质量验证。
- 凭据来源契约不替代服务端 Key 轮换、角色权限、集中秘密管理或公网安全评审。
