## 验证范围

- 两个数据版本、包标识和内容不同，但结构化表、图片与来源策略路径相同的合成真实 Chroma 运行包。
- 同一隔离 `DATA_DIR` 中的首次 A 部署、A→B 升级和 B→A 回退。
- 每次切换后的真实 Uvicorn 启动、HTTP 就绪、包身份、数据版本、计数和数据库路径。
- 结构化表、图片、根 manifest、活动指针和两个数据库版本的恢复与保留。
- 覆盖导入中途失败时的逐文件事务恢复。
- `--no-activate` 对活动指针、根 manifest 和共享资产的无副作用语义。
- Windows/Linux 本机恢复以及 Windows→Linux、Linux→Windows 的既有跨平台导入和 API 冷启动。

## 结论与边界

当前受控矩阵已经证明：在维护窗口中保留上一版完整 ZIP 后，可以通过同一事务导入路径完成运行包升级和整包回退，且 API、数据库、manifest 与包内共享资产恢复到同一版本。`--no-activate` 可安全预装数据库版本，不会提前改变在线共享资产。

本记录不证明零停机热更新、多副本流量切换、任意 Python/Chroma/处理器组合或主机级灾难恢复。运行知识包默认不包含原始 PDF、任务、审计、人工修正源记录和全部质量历史，这些内容仍需要独立持久卷备份。本验证也不改变资料授权、包签名信任根、对外分发或商业使用结论。
