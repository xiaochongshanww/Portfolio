## 1. 评审目的

冻结三个内置评估资产的输入边界、修订身份、报告兼容字段和生命周期状态机，为后台维护能力的实现提供可复核基线。该记录只确认工程契约，不确认评估问题、答案或规范引用的专业正确性。

## 2. 基线结论

| 项目 | 结论 | 证据 |
| --- | --- | --- |
| 评估集身份 | 仅允许 `regular`、`structured`、`answer` 三个服务端逻辑 ID | `docs/reference/评估集格式参考.md`、`src/evaluation/management.py` |
| 最低规模 | 三类评估集最低条数为 100、12、24 | 同上；管理校验器执行 |
| 发布模型 | 草稿可编辑，发布修订不可变；回退通过创建新修订完成 | `src/evaluation/management.py`、生命周期测试 |
| 失败恢复 | 清单写入失败恢复旧清单/草稿；新增修订文件只在本次创建时清理 | `tests/test_evaluation_management.py` |
| 报告兼容 | 报告绑定评估集 ID、修订 ID、内容哈希、数据版本、配置指纹和运行 ID | `docs/reference/评估集格式参考.md`、质量门禁测试 |
| 外部边界 | 不开放任意文件路径、URL、PDF 或评估集上传；不把迁移视为内容授权 | ADR 0012、管理 API 契约 |

## 3. 状态机审阅

已确认的最小状态流为：

```text
已发布修订
   -> 创建草稿 -> 草稿
   -> 编辑/增删 -> 草稿（校验失效）
   -> 校验通过 -> 已校验草稿
   -> 发布 -> 新已发布修订 + 旧修订保留
   -> 回退 -> 从历史内容创建新的已发布修订
```

任何写入失败都必须保留旧发布修订；评估报告不被删除，只在身份不匹配时标记为历史/待更新。发布和回退产生质量重跑待办，质量验证中心据当前修订和报告身份计算是否完成。

## 4. 评审范围与限制

- 已核对内置文件字段、数量、类型分布和内容哈希，格式参考文档已记录真实值。
- 已核对 OpenAPI、生成客户端、运行时契约和质量运行比较接口；当前管理端为 75 个操作。
- 已通过隔离临时数据根验证迁移、审计、失败恢复、并发发布和快照包含评估集生命周期数据。
- 本记录不替代真实浏览器中的键盘/窄屏验收，也不替代新增评估用例的专业内容复核。

## 5. 后续门槛

在评估集管理进入“当前生效”完整能力前，仍需完成：

1. 真实后台页面流程、失败反馈、键盘操作和窄屏布局人工验收。
2. 新增或修改用例的规范依据、答案要点和引用内容专业复核。
3. 完整全量工程门禁和一次受控质量运行，确认当前报告与活动数据版本一致。
