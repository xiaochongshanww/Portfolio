## 验证目标

证明管理 API 的成功响应具有机器可读边界，OpenAPI 快照可确定性复现，Vue 控制台实际消费生成的请求/响应类型，并且后端、前端或生成文件漂移能够在本地和 CI 失败关闭。本记录不证明模型回答质量、公开 API 稳定性、角色权限或公网部署通过。

## 实现范围

- `src/app/schemas/admin.py` 为状态、文档、任务、评估、质量、版本、校对、结构化和元素操作定义响应模型；默认禁止未建模字段，仅七个登记的原始载荷响应允许顶层扩展。
- `/admin` 的 43 个 JSON 操作声明具名 HTTP 200 schema；页面截图操作只声明 `image/png`。
- `scripts/export_openapi.py` 在无服务、无模型调用和无运行数据写入的条件下导出或校验 `frontend/openapi.json`。
- `@hey-api/openapi-ts 0.97.3` 从快照生成 `frontend/src/generated/api/`；`api.ts` 与控制台组件通过 `contracts.ts` 消费生成类型，不再使用默认 `any`。
- 后端 CI 在 Windows/Linux 校验快照；前端 CI 重生成类型并拒绝工作树差异和未跟踪输出。

## 故障边界

1. 后端新增或修改管理路由而未提供响应模型时，OpenAPI 契约测试失败。
2. 后端实现与快照不一致时，`python scripts/export_openapi.py` 失败且不覆盖文件。
3. 快照与生成类型不一致时，`npm run api:check` 失败；新生成但未跟踪的文件同样失败。
4. 组件访问不存在字段、把可选字段当必需字段或提交错误请求体时，前端类型检查失败。
5. 开放 JSON 仍只受顶层边界约束，内部语义需要业务测试；契约通过不能替代质量门禁。
6. 非登记响应出现未建模顶层字段时，Pydantic/FastAPI 响应校验失败；七个开放响应的精确集合由 OpenAPI 测试锁定。
