# 发布检查单

> 状态：生效  
> 维护角色：发布负责人  
> 文档更新：2026-08-09
> 流程核对：2026-08-09
> 完整运行验证：不适用（当前为流程模板，仓库尚无实际发布记录）  
> 验证证据：本目录当前仅包含检查单和发布记录模板  
> 复核周期：每次发布

每次对外可见发布都复制 [发布记录模板](发布记录模板.md) 到本目录并填写。未通过项必须明确豁免人、风险和回退方案。当前仓库尚无实际发布记录，因此本文件只代表已生效的发布要求，不代表已完成生产发布。

发布前可先运行只读审计：

```powershell
python scripts/audit_release_readiness.py --json-output release-readiness.json --markdown-output release-readiness.md
```

该命令汇总质量快照、来源资格、封闭试用和交付决策；退出码为 0 才表示阻断项全部满足。JSON 中 `checks[id=source_release].items` 保留逐来源、逐字段的整改明细，所有未通过检查还会提供 `checks[].remediation`，并在顶层提供只读的 `closure` 收口矩阵；Markdown 报告同步输出“来源资格明细”“收口矩阵”和“整改行动”章节。这些输出都不改变门禁结论。精排质量证据作为非阻断提醒，因为精排默认关闭；启用精排前仍必须单独完成真实对照和回答盲测。若路线图将 I-034 标记为“已完成”，审计会额外校验 `data/audit/reports/rerank_comparison_latest.json` 和 `data/audit/reports/rerank_answer_latest.json`：前者必须是当前数据版本下完整的 100 条供应商对照，后者必须声明启用精排、覆盖当前 24 条回答盲测且通过率不低于 90%。

如接入封闭试用记录，先运行 `python scripts/validate_trial_record.py --record <trial-record.json>`，再运行 `python scripts/render_trial_record.py --record <trial-record.json> --output <trial-record.md>` 生成供负责人审阅的阅读版。阅读版只是 JSON 的派生视图，不替代参与者反馈、原始页面复核、数据清理证据或发布审计。

来源补证可先运行 `python scripts/render_source_register_report.py --output <受限目录>\source-register.md` 生成逐来源阅读版，再按报告准备受控证据；阅读版只是来源台账的派生视图，不包含原文或授权原件，不替代 `--require-release-eligible`。

需要集中管理受限补证材料时，可先在受限目录生成证据包索引，再显式将其接入审计：

```powershell
python scripts/create_release_evidence_manifest.py --output <受限目录>\release-evidence.json
python scripts/validate_release_evidence_manifest.py --manifest <受限目录>\release-evidence.json --markdown-output <受限目录>\release-evidence.md
python scripts/validate_release_evidence_manifest.py --manifest <受限目录>\release-evidence.json --require-ready
python scripts/audit_release_readiness.py --evidence-manifest <受限目录>\release-evidence.json
```

证据包索引只登记引用、责任人、日期和 SHA-256，不保存授权原件、规范内容或密钥；索引通过不等于来源取得对外授权，也不替代试用、交付决策和质量门禁。

发布审计是构建与发布阶段的只读 CLI，不是运行时 `/admin` 接口。它读取路线图、待决策登记、来源治理文档和发布质量证据；轻量运行镜像按设计不携带这些治理文件，因此运行控制台只展示运行时状态，不替代发布审计。需要发布判断时，应在完整仓库和受控证据目录中运行本命令。

仅限项目成员范围内的研究或封闭验证可显式使用内部 profile：

```powershell
python scripts/audit_release_readiness.py --profile internal-research
```

该 profile 只证明当前活动来源按台账允许内部研究，且质量证据、运行 manifest 和来源范围通过；它不要求真实用户试用，不改变默认对外审计结果，也不授予截图、摘录、表格、知识包、问答或 API 的对外传播权。默认不带 `--profile` 仍是 `external`。

完整精排证据可使用：`python scripts/run_rerank_quality_evidence.py --zhipu-key-file <智谱 Key 文件> --api-key-file <目标 API Key 文件> --mimo-key-file <Mimo Key 文件>`。`--api-key-file` 同时提供回答盲测客户端凭据，并为临时 API 子进程设置 `API_KEYS`；它不修改当前终端环境。该命令只写精排专用报告，不更新 `quality_run_latest.json`；Key 文件不得提交到仓库。

Windows 终端执行 `audit_release_readiness.py`、`validate_source_register.py` 和 `validate_trial_record.py` 时，命令入口会统一使用 UTF-8 输出；JSON 结果采用 ASCII 转义，适合重定向给脚本或 CI，不需要依赖本机代码页解码。

## 发布阻断项

质量门禁失败、来源权利未确认、无法回退、关键接口未鉴权、控制台静态资源不可访问、回答引用错误或出现未解决高风险审计时，不得发布。
