## 验证目标

证明管理控制台的方法、路径、参数和返回类型由同一份 OpenAPI 生成操作绑定，不再依赖手写 URL 条件类型；同时证明 API Key、401、错误文案和页面截图体验没有因迁移退化。本记录不证明模型回答质量、人工校对完成度或公网部署通过。

## 实现范围

- 锁定的 `@hey-api/openapi-ts 0.97.3` 同时生成 TypeScript 类型、Fetch client 和 44 个逐操作 SDK 函数，生成目录继续提交并由 `api:check` 验证漂移。
- `admin-api.ts` 将生成函数重导出为稳定语义别名；该层不包含 `/admin` 字面量，也不重新声明方法或传输模型。
- `api.ts` 配置同源 client、存储 Key 与显式候选 Key 的优先级、统一 `ApiError`、401 全局事件和页面图片对象 URL。
- 六个管理组件改用结构化 `path`、`query`、`body` 参数；`contracts.ts` 删除全部 `Admin*Path` 条件类型，只保留生成类型和展示视图。
- 静态扫描阻断旧管理包装器和运行时代码中的管理 URL 字面量；单元测试覆盖认证头、候选 Key、JSON/文本错误、401 和 PNG Blob。

## 已知边界

1. 本轮只迁移 `/admin` 控制台调用；健康、指标、知识文档与聊天流式调用仍使用专用实现。
2. 语义别名隔离生成器的冗长 operation id，但生成函数签名变化仍会在组件编译时暴露。
3. 本地浏览器使用当前活动知识资产和受控本地 Key，不代表反向代理、公网身份或多用户会话通过。
4. 发布质量仍为 `not_passed`，本轮不改变真实精排对照、结构化人工发布和回答盲测要求。
