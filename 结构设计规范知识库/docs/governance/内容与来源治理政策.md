# 内容与来源治理政策

> 状态：草案  
> 维护角色：内容治理负责人  
> 文档更新：2026-08-08  
> 流程核对：2026-08-08  
> 完整运行验证：不适用（尚未完成真实来源台账与法律专业复核）  
> 验证证据：本文件中的来源登记要求；真实证据库尚未建立  
> 复核周期：每季度或每次对外范围变化  
> 访问级别：internal

## 1. 目的与边界

本政策管理入库 PDF、解析文本、页面截图、结构化表和回答引用的来源与使用边界。它是工程控制基线，不构成法律意见；对外发布、收费、收到投诉或签署内容授权前，应由具备资质的法律专业人士复核。

## 2. 内容分级

| 等级 | 条件 | 可用范围 |
| --- | --- | --- |
| A：已授权或自有 | 有明确书面授权、采购许可或自有权利 | 按授权范围对外服务和展示 |
| B：权利状态待核实 | 网上收集扫描件、来源不完整或展示权不明确 | 仅限内部研究和封闭验证；不得作为公开或收费产品语料 |
| C：禁止使用 | 来源违法、权利人明确拒绝、含不应处理的个人信息 | 停止处理、隔离并删除派生产物 |

当前网络搜集的扫描 PDF 默认按 B 级管理，除非来源登记能证明更高等级。不得因为“规范公开”自动推定扫描件、版式、页面截图或数据库再分发均可对外使用。

## 3. 来源登记

每一份入库内容必须有独立登记，不在 Git 保存原件或授权材料。登记系统至少记录发布范围（`production` 或 `test_only`）、
来源种类、权利状态和运行映射。登记系统至少记录：

```text
source_id
规范名称、编号、版本
原始文件 SHA-256
取得日期和来源 URL/采购凭证索引
权利状态与允许用途
是否允许页面截图、原文摘录、对外检索、付费服务
解析版本、manifest 版本、负责人
复核日期、下架状态和投诉记录索引
```

建议将受控登记表保存在加密的内部存储中；仓库仅保存脱敏的 schema、哈希与状态。

## 4. 对外展示规则

- 回答应优先给出规范标识、条文/表号、页码、简短必要摘录和可验证来源，不批量输出原 PDF 或可替代原作的完整内容。
- 图片、长摘录、整页表格和下载能力仅在来源登记明确允许时启用。
- 用户上传的文件与平台自有内容隔离；未经明确授权不得进入共享知识库或训练/评估集。
- 收到权利通知后，先停止相关来源的检索与展示，保留最小必要审计记录，再完成核查、下架或恢复。

仓库中的技术映射使用 `data/metadata/specs.json`：

| 内容结论 | `image_access` / `page_image_access` |
| --- | --- |
| 已确认允许相应资源公开展示 | `public` |
| 只允许受控用户、封闭验证或内部使用 | `authenticated` |
| 禁止展示、待下架或无法确认 | `disabled` |

当前 B 级扫描 PDF 显式使用 `authenticated`。该值只限制直接资源访问，不会把 B 级内容转化为可公开分发；C 级内容还必须按治理流程停止检索并隔离派生产物。

## 5. 校对与派生产物

人工修正、结构化表和评估样本均是派生内容，必须继承原始来源的使用限制。高风险数值、公式和强制性条文须保留来源页、审核人角色、审核时间和发布版本。

运行知识包中的向量数据库、结构化表和解析图片同样属于派生产物，必须继承每个来源的最严格使用限制。技术上能够导出知识包不代表有权向第三方分发。默认不得把 B 级来源导出给不属于封闭验证范围的用户；原始 PDF 只有在来源登记明确允许再分发时才可加入知识包。

## 6. 对外开放前的必备证据

1. 所有可对外检索内容均有 A 级权利依据或明确的可公开使用结论。
2. 已发布隐私政策、服务条款、工程免责声明和投诉/下架渠道。
3. 已完成数据处理、模型供应商和跨境传输的审查。
4. 已对展示、下载、截图和导出能力按内容等级实施技术控制。
