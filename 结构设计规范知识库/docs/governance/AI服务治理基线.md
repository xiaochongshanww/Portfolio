> 状态：草案  
> 维护角色：产品与工程负责人  
> 文档更新：2026-07-29  
> 流程核对：2026-07-29

> 验证证据：本文件中的最低控制要求；实际治理台账尚未建立  
> 复核周期：每月或模型/供应商变化时  
> 访问级别：internal

## 1. 服务定位

本服务提供带来源依据的规范检索与问答辅助，不替代注册结构工程师、设计单位、审图机构或现行规范的专业判断。回答应说明适用版本、条件、单位和来源；证据不足时必须拒答或提示人工核对。

## 2. 模型与供应商登记

每个生产模型变更都必须登记：模型名称与版本、供应商、用途、调用区域、数据是否可能留存、提示词版本、Embedding 版本、启用日期、回退方案、对应评估报告和审批记录。

当前实现的运行参数以 `src/app/core/config.py` 为准；文档不复制密钥、完整供应商合同或用户数据。

## 3. 风险控制

| 风险 | 最低控制 |
| --- | --- |
| 规范引用错误 | 权威性排序、来源追踪、回答级评估和拒答规则 |
| 表格/公式误读 | 人工审核、结构化发布、版本回滚和截图核对 |
| 过期或错误内容 | 来源版本登记、manifest 溯源、定期复核 |
| 提示注入或越权请求 | 将检索内容视为不可信输入；限制工具和管理接口权限 |
| 敏感数据泄露 | API 鉴权、日志脱敏、最小化收集和访问控制 |
| 模型供应商不可用 | 明确错误状态、超时、重试边界和回退/暂停策略 |

## 4. 测量与发布

生产发布前至少保留检索、结构化表和回答级评估报告；任何低于门禁的变更不得静默上线。质量门禁和人工边界见 [质量运营流程](../operations/知识库维护与质量运营.md) 与 [RAG 系统卡](../quality/检索增强生成系统卡.md)。

## 5. 面向用户的透明度

对外产品至少说明：服务由生成式 AI 辅助、回答的证据来源与限制、人工核对建议、反馈/纠错入口、个人信息处理说明和所使用模型服务的必要信息。向境内公众提供服务前，应基于实际功能和适用规定完成合规评估与必要程序。
