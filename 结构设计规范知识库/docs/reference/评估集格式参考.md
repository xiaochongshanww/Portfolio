## 2. 公共字段

每行必须是一个 JSON 对象，并至少包含：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | string | 非空，同一评估集内唯一 |
| `query` | string | 非空；管理校验会去除首尾空白后检查 |
| `type` | string | 必须属于该评估集允许的枚举 |

JSONL 允许空行；发布时会按 `id` 稳定排序并以 UTF-8、无 ASCII 转义、紧凑 JSON 重新计算内容哈希。

## 3. `regular` 检索评估集

文件：`data/evaluation/queries.jsonl`。当前最低条数为 100。

| 字段 | 类型 | 默认值 | 用途 |
| --- | --- | --- | --- |
| `expected_sources` | string[] | `[]` | 期望命中的规范名称或文件标识 |
| `expected_clause` | string | `""` | 期望命中的条文号 |
| `expected_keywords` | string[] | `[]` | 关键词命中约束 |
| `top1_source_required` | boolean | `true` | 是否要求首位结果命中期望来源 |

允许的 `type` 为：`alias`、`classification`、`clause`、`code`、`definition`、`formula`、`general`、`multi_spec`、`table`、`structured_table`。`structured_table` 仅在迁移兼容校验中保留，结构化专项的正式资产使用 `structured`。

## 4. `structured` 复杂表专项评估集

文件：`data/evaluation/complex_structured_tables.jsonl`。当前最低条数为 12，全部为 `structured_table`。

| 字段 | 类型 | 默认值 | 用途 |
| --- | --- | --- | --- |
| `expected_table_id` | string | `""` | 期望命中的结构化表标识；`structured_table` 必填 |
| `keyword_required` | boolean | `true` | 是否要求关键词约束 |
| `top1_source_required` | boolean | `true` | 是否要求首位来源命中 |

该资产当前不要求 `expected_sources`、`expected_clause` 或 `expected_keywords`，但保留这些字段可兼容常规评估模型。表格 ID 的具体语义由结构化表资产和人工校对结果共同决定。

## 5. `answer` 回答级盲测集

文件：`data/evaluation/answer_holdout.jsonl`。当前最低条数为 24。

| 字段 | 类型 | 默认值 | 用途 |
| --- | --- | --- | --- |
| `expected_all` | string[] | `[]` | 回答必须包含的要点 |
| `expected_any_groups` | string[][] | `[]` | 每组至少命中一个要点 |
| `forbidden_terms` | string[] | `[]` | 回答不得出现的词 |
| `expected_citations` | string[] | `[]` | 期望引用标识 |
| `expected_unit_groups` | string[][] | `[]` | 单位表达任选匹配组 |
| `requires_refusal` | boolean | `false` | 是否要求在无证据时拒答 |
| `requires_image` | boolean | `true` | 是否要求回答包含可验证图片引用 |

允许的 `type` 为：`direct_value`、`formula`、`boundary`、`false_premise`、`no_evidence`。`requires_refusal` 只能用于 `no_evidence`。

## 6. 与评估报告的兼容字段

评估运行读取已发布修订的完整快照，并在每一类报告的顶层记录以下身份字段：

| 字段 | 含义 | 兼容要求 |
| --- | --- | --- |
| `evaluation_set_id` | `regular`、`structured` 或 `answer` | 必须与任务请求的逻辑 ID 一致 |
| `evaluation_set_revision_id` | 实际使用的不可变发布修订 | 评估期间固定，不能随新发布修订漂移 |
| `evaluation_set_hash` | 规范化 JSONL 内容哈希 | 必须与该修订文件一致 |
| `evaluation_set_path` | 服务端实际资产路径 | 仅用于同环境追溯，客户端不可提交或覆盖 |
| `case_count` | 本次完成的用例数量 | 必须与报告对应资产的运行计数一致 |
| `data_version_hash` | 检索知识库数据版本身份 | 用于区分评估集变化和知识库变化 |
| `runtime_config_hash` | 影响评估结果的运行配置指纹 | 用于识别模型、检索和运行时配置变化 |
| `verification_run_id` | 所属完整质量运行身份 | 三类报告必须来自同一次完整运行 |

质量门禁只接受同时匹配当前活动数据版本、当前评估集发布修订和当前运行配置指纹的报告。发布或回退评估集会保留旧报告，但旧修订或哈希不匹配时必须进入“待重跑”，不能继续作为当前证据。报告比较可以据此分别展示评估集身份变化、运行数据变化、配置变化和指标变化。

## 7. 管理生命周期约束

- 管理 API 只接受 `regular`、`structured`、`answer` 三个逻辑 ID，不接受 `file`、路径、URL 或任意 JSONL 文件。
- 内置资产默认只读；执行 `python -m src.evaluation migrate --dry-run` 预览，确认后执行 `python -m src.evaluation migrate` 生成受控首个发布修订。
- 草稿允许编辑、新增和删除，但必须通过当前内容哈希对应的结构校验后才能发布。
- 已发布修订不可编辑；回退通过从历史修订创建新的发布修订完成。
- 管理层校验字段、类型、ID 唯一性和最低条数；它不能证明规范答案、条文引用或专业结论正确。
- 评估集内的规范事实、答案和引用属于质量验证资料，不能据此扩大原始规范材料的使用或分发权限。
