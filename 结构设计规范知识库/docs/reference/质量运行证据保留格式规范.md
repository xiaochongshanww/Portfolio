## 1. 目录

```text
data/audit/
  reports/
    .quality-report-store.lock
    quality_run_latest.json
    runs/<verification_run_id>/...
  quality_run_retention/
    events.jsonl
    plans/<plan_id>.json
    executions/<plan_id>.json
```

运行标识与计划标识均为 32 位小写十六进制字符串。工具不接受任意路径；链接、重解析点、非法名称和越界目录不会进入删除候选。

## 2. 清单输出

`python scripts/manage_quality_runs.py list` 输出 schema v1 JSON，包含：

- 生效策略、最新运行、脱敏快照引用和保护集指纹；
- 封存、未封存、异常及候选数量和总占用；
- 每个运行的分类、时间、大小、文件数、内容指纹、保护原因和候选状态。

保护原因固定使用 `latest`、`snapshot_reference`、`recent_complete`、`minimum_age` 和 `invalid`。指针或脱敏快照损坏时命令非零退出，不返回可删除候选。

## 3. 清理计划

计划 schema v1 的 `status` 为 `planned`，记录：

- `plan_id`、`created_at`、`expires_at`；
- 完整策略快照和 `protection_fingerprint`；
- 候选数量、预计释放空间；
- 每个候选的运行标识、分类、大小、文件数、最新修改时间和内容指纹。

计划不保存完整报告内容、问题、回答、错误正文、凭据或本机源文件路径。默认 15 分钟失效；修改计划 JSON 不会绕过执行时的当前状态重检。

## 4. 执行报告

执行必须同时提供计划标识和 `--confirm`。工具持有 `.quality-report-store.lock` 后重新计算保护集、候选资格和指纹。验证通过的目标先改名为同一 `runs/` 根内的 `.deleting-<run_id>-<nonce>`，再递归删除。

执行报告的状态为：

- `succeeded`：所有候选删除成功，包括空计划；
- `partial_failed`：至少一个候选隔离或删除失败，命令返回非零。

报告记录删除/失败数量、实际释放字节和逐项结果。删除失败会尽力恢复原目录；恢复也失败时保留隔离目录和错误摘要，必须人工处理，不能直接重跑旧计划。

## 5. 兼容与边界

- 清理工具不修改 `quality_run_latest.json`、兼容 `*_latest`、运行清单或 Git 脱敏快照。
- 被当前或历史脱敏快照引用的原始运行默认持续保护。
- `.quality-report-store.lock` 协调当前代码中的报告写入、最终发布和清理；旧版本进程不理解该锁，升级时应先停止旧验证器。
- 原始运行删除不可逆，恢复依赖受控 `DATA_DIR` 备份；Git 脱敏快照不能恢复详细报告。
