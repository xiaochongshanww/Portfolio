配置通过环境变量读取。`.env.example` 是可编辑示例；字段默认值、类型和行为以 `Settings` 实现为准。

| 变量 | 用途 | 生产要求 |
| --- | --- | --- |
| `ZHIPUAI_API_KEY` | 文本向量化与查询 Embedding | 必填，使用密钥管理系统 |
| `MIMO_API_KEY` | 问答和多模态校对模型调用 | 必填，使用密钥管理系统 |
| `MIMO_BASE_URL` / `MIMO_MODEL` | 模型供应商地址和模型 | 记录供应商、区域与变更版本 |
| `PDF_PARSER_BACKEND` | PDF 构建后端；默认 `mineru`，`pymupdf` 仅为显式替代 | 运行已构建知识包时不使用；改变后必须重建与评估 |
| `MINERU_BIN` / `MINERU_ARGS` | 外部解析 CLI 和附加参数 | 默认 `magic-pdf`；参数变化必须记录在构建 manifest |
| `MINERU_COMPATIBILITY_POLICY` | 外部解析器兼容策略 | 生产保持 `strict`；`allow-unverified` 仅用于隔离迁移试验 |
| `LLM_TIMEOUT_SECONDS` | 模型调用超时 | 按供应商 SLA 设置 |
| `RAG_TOP_K` / `RAG_MIN_SCORE` | 召回数量与最低分数阈值 | 修改后必须执行评估 |
| `EMBEDDING_MODEL` | 向量模型标识 | 修改后需要重建与回归验证 |
| `RETRIEVAL_DENSE_WEIGHT` / `RETRIEVAL_BM25_WEIGHT` / `RETRIEVAL_CLAUSE_BOOST` | 混合检索和条文匹配权重 | 修改后必须执行评估 |
| `RERANK_ENABLED` / `RERANK_PROVIDER` | 精排开关与提供方 | 当前只有空实现，`RERANK_ENABLED` 必须保持 `false` |
| `DATA_DIR` | manifest、活动指针、版本、任务、审计、修正、结构化表、图片与来源策略的统一运行数据根 | 默认项目内 `data/`；生产应指向受备份保护的持久卷，知识包导入和 API 必须使用同一值 |
| `DB_DIR` | 缺少 `active_db.json` 时的旧 Chroma 回退目录 | 默认项目内 `db/`；不应代替完整 `DATA_DIR` 备份或迁移 |
| `IMG_DIR` | 活动指针缺少图片目录时的精细覆盖 | 未设置时使用 `DATA_DIR/images`；只有独立存储时覆盖 |
| `SOURCE_METADATA_PATH` | 来源元数据和图片展示策略 | 未设置时使用 `DATA_DIR/metadata/specs.json`；未知来源默认受保护 |
| `IMG_BASE_URL` / `PUBLIC_ASSET_BASE_URL` | 图片内部/外部 URL 前缀 | 仅使用确认可公开的资源域名 |
| `STATIC_DIR` | Vue 生产构建目录 | 指向 `frontend/dist` 或等效绝对目录 |
| `API_AUTH_ENABLED` / `API_KEYS` | API Key 鉴权 | 公网部署必须启用；当前只支持通过环境变量手动轮换并重启服务 |
| `ASSET_SIGNING_KEY` / `ASSET_URL_TTL_SECONDS` | 受保护图片的 HMAC 签名密钥与有效期 | 开启鉴权时密钥至少 32 字符且与 API Key 分离；有效期 60-604800 秒 |
| `OPENWEBUI_API_KEY` | Open WebUI 连接本 API 使用的 Key，仅由 Compose 消费 | 启用 API 鉴权时必须与 `API_KEYS` 中的一项一致 |
| `CORS_ORIGINS` / `CORS_ALLOW_CREDENTIALS` | 浏览器来源和凭据策略 | 使用明确 HTTPS 域名，不使用通配符 |
| `RATE_LIMIT_*` / `MAX_REQUEST_BYTES` | 请求保护 | 按实际流量监控后调整 |
| `JOB_HEARTBEAT_SECONDS` / `JOB_STALE_AFTER_SECONDS` | 后台任务执行器心跳间隔与无进展诊断阈值 | 默认 15/7200 秒；后者不得小于 30 秒或心跳间隔的 2 倍；修改后执行任务恢复测试 |
| `ANSWER_EVALUATION_API_BASE` | API 后台任务执行回答级盲测时回调本服务的受信任内部地址 | 默认 `http://127.0.0.1:8000`；自定义监听端口、反向代理前缀或容器网络地址时必须显式覆盖；只允许无凭据、无查询参数的 HTTP(S) 地址 |
| `VERSION_RETENTION_KEEP_RECENT_PASSED` | 除活动版本外保留的近期门禁通过/旧版完整回滚版本数 | 默认 2；不能为负数 |
| `VERSION_RETENTION_SUCCESS_DAYS` / `VERSION_RETENTION_FAILED_DAYS` | 成功版本与失败/不完整版本的最长保留天数 | 默认 30/7；期限只作用于非保护版本 |
| `VERSION_RETENTION_MINIMUM_AGE_HOURS` | 新建或近期变化版本的最短保护时间 | 默认 24；磁盘压力也不能突破 |
| `VERSION_RETENTION_HIGH_WATERMARK_BYTES` / `VERSION_RETENTION_LOW_WATERMARK_BYTES` | 版本目录总占用的回收触发和目标水位 | 默认 20/16 GiB；低水位不能大于高水位 |
| `VERSION_RETENTION_PLAN_TTL_MINUTES` | 清理计划有效期 | 默认 15，范围 1-1440；过期后必须重新生成 |
| `LOG_LEVEL` / `LOG_FORMAT` | 日志级别与 `json`/`text` 输出格式 | 生产默认 `json`；不记录密钥、完整用户输入、受限原文或客户端 IP |

配置变更属于发布变更，需按 [发布检查单](../releases/发布检查单.md) 记录。禁止将真实 `.env` 文件、API Key 或生产 URL 中的敏感参数提交至仓库。

PDF 知识生产环境使用 `requirements-parser.txt`，当前兼容矩阵只有 `magic-pdf 1.3.12`。安装后先执行 `python -m src.pipeline parser-status`；成功结果必须包含 `compatibility=verified` 与 `verified=true`。严格策略会在任何候选产物清理前拒绝缺失、超时、版本无法识别或未验证的 CLI。显式 `allow-unverified` 会保留警告并写入 manifest，不表示可用于生产。

所有相对路径配置均相对于项目根目录解析，与启动命令当前目录无关。`DATA_DIR` 在 Python 进程导入模块时确定，修改后必须重启 API 和构建命令。执行 `package-import --data-dir <目录>` 时，后续 API 的 `DATA_DIR` 必须指向同一目录；不允许通过搜索目录或复制活动指针猜测当前知识版本。

`backup-create` 和 `backup-restore` 的 `--data-dir` 默认同样读取启动进程时的 `DATA_DIR`，也可显式覆盖。快照路径不是环境变量配置，必须位于数据根之外；三个备份命令不会读取或写入 API Key。完整协议见[运行数据快照格式规范](运行数据快照格式规范.md)。

`API_AUTH_ENABLED` 是控制台鉴权界面的唯一服务端事实来源。控制台启动时请求受保护的 `/admin/status`：关闭鉴权时即使浏览器没有 Key 也会直接进入；开启鉴权且当前 Key 缺失或无效时，后端返回 401，控制台才要求验证。连接失败和其他 HTTP 错误不会被解释为缺少 Key。浏览器只在候选 Key 验证通过后保存它；此本地存储不是用户会话、权限模型或服务端配置。

## 质量验证客户端凭据

`QUALITY_API_KEY` 和 `QUALITY_API_KEY_FILE` 只由 `scripts/verify_quality.py` 读取，不属于 API 服务端 `Settings`。凭据按以下顺序解析：

1. `--no-api-key` 显式忽略所有来源；
2. `QUALITY_API_KEY` 环境变量；
3. `--api-key-file <UTF-8 文件>`；
4. `QUALITY_API_KEY_FILE` 指向的 UTF-8 文件；
5. 项目根 `.runtime_api_key` 兼容文件；
6. 无凭据。

新自动化应使用秘密管理系统注入 `QUALITY_API_KEY`；人工运行优先使用项目外的 `--api-key-file`。脚本故意不提供原始 `--api-key` 参数，避免值进入 shell 历史或进程列表。报告只记录来源和是否提供凭据。`.runtime_api_key` 仅为旧环境兼容入口，不应成为部署契约。

## 启动前校验

API 进程导入配置时会立即校验类型、范围和关键安全组合。可在启动或发布前独立执行：

```powershell
python -m src.app.core.config
```

成功时向 stdout 输出 `{"ok": true, "message": "configuration: ok"}`。配置失败时返回退出码 2，并向 stderr 输出包含 `error=configuration_invalid` 与 `issues` 数组的 ASCII 安全 JSON；该契约不依赖 Windows/Linux 终端编码，可直接由部署脚本解析。当前规则包括：

- 布尔值只接受 `true/false`、`1/0`、`yes/no` 或 `on/off`，不再把拼写错误静默解释为 `false`。
- 超时、召回数量、请求上限、限流配额和检索权重必须满足代码定义的有效范围；Dense 与 BM25 权重不能同时为零。
- 启用 API 鉴权后必须提供至少一个真实 `API_KEYS` 和至少 32 字符的 `ASSET_SIGNING_KEY`；`OPENWEBUI_API_KEY` 如有设置，必须与其中一项一致。
- `ASSET_URL_TTL_SECONDS` 必须在 60 到 604800 秒之间，默认 3600 秒。
- `CORS_ALLOW_CREDENTIALS=true` 时，`CORS_ORIGINS` 不能包含 `*`。
- 当前没有实际 reranker 提供方，因此不能启用 `RERANK_ENABLED`。
- `LOG_LEVEL` 只接受 `DEBUG`、`INFO`、`WARNING`、`ERROR` 或 `CRITICAL`。
- `LOG_FORMAT` 只接受 `json` 或 `text`，默认 `json`；`text` 主要用于本地人工阅读。
- `JOB_HEARTBEAT_SECONDS` 必须在 1-300 秒；`JOB_STALE_AFTER_SECONDS` 至少为 30 秒且不小于心跳间隔的 2 倍。心跳过期阈值由服务按心跳间隔的 3 倍计算，且不低于 60 秒。
- `ANSWER_EVALUATION_API_BASE` 必须是包含主机的 HTTP(S) 基址，不能携带用户名、密码、查询参数或片段。该值只从受信任部署配置读取，管理请求不能覆盖。
- 版本保留数量、期限、最短保护时间和水位不能为负；高水位必须大于 0，低水位不能大于高水位，计划有效期必须在 1-1440 分钟。

`ZHIPUAI_API_KEY`、`MIMO_API_KEY` 和知识资产完整性由 `/ready` 报告，不作为 API 进程启动阻断条件。这样控制台仍可用于诊断和修复未就绪环境。
