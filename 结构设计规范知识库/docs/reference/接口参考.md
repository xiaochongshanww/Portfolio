## 机器可读契约

服务启动后，使用以下地址获取当前接口契约：

```text
/openapi.json
/docs
```

任何客户端生成、请求/响应字段判断和错误处理，应以同版本运行服务导出的 OpenAPI 为准。Markdown 仅说明入口、兼容性和运营约束。

仓库同时提交确定性快照 `frontend/openapi.json`。管理端当前 75 个 JSON 操作必须具有具名 HTTP 200 schema，1 个页面截图操作必须只声明 `image/png`。除七个明确登记的原始载荷响应外，响应 schema 均禁止未建模顶层字段。开发者使用以下命令维护契约：

```powershell
python scripts/export_openapi.py --write
cd frontend
npm run api:generate
npm run api:check
```

`api:generate` 同时生成 TypeScript 类型、Fetch client 和逐操作 SDK；`api:check` 面向干净检出和 CI，重生成后拒绝未提交差异，也拒绝管理组件退回字符串 URL 包装器。前端通过 `admin-api.ts` 的语义别名调用生成操作，通过 `api.ts` 的 client 拦截器统一处理 API Key、401、错误和图片 Blob。完整的单一来源、兼容与失败边界见[管理 API 与前端类型契约规范](管理API与前端类型契约规范.md)。

除静态 schema 与生成类型外，`tests/test_admin_runtime_contract.py` 以 OpenAPI operation id 清单驱动当前 76 个隔离 ASGI 成功路径。新增或删除管理操作但未同步场景、实际响应缺失必需字段、包含未声明字段或返回错误媒体类型时，后端门禁失败。该测试不访问模型、解析器、网络或真实运行数据。

### DeepSeek Harness 集成接口

以下接口供 `integrations/deepseek-harness/dsh-structural-kb` 只读 Bundle 使用。它们受全局 API Key 鉴权保护，不提供构建、审核、批准、发布或删除操作。

| 路径 | 用途 | 成功响应重点 |
| --- | --- | --- |
| `GET /integrations/deepseek-harness/ready` | 检查 Harness 可查询的知识库状态 | `ready`、`api_version`、`data_version_hash` |
| `POST /integrations/deepseek-harness/search` | 检索正文、正文表格、条文和结构化表格 | `results` 中的规范编号、权威等级、条文/表号、页码、摘录和命中原因 |
| `GET /integrations/deepseek-harness/page` | 获取来源 PDF 页面的受控地址 | `source_file`、`page`、`url` |

`search` 请求体只允许 `query`、`top_k`、`document`、`mode` 和 `include_assets`。`mode` 支持 `auto`、`table`、`clause`、`definition`、`general`。服务不可查询时返回 HTTP 503 和 `KNOWLEDGE_BASE_NOT_READY`；未找到依据仍返回 HTTP 200，并通过 `result_count=0` 和 `warnings` 表达，不得把两种情况混为一谈。插件的安装和运行步骤见 [DeepSeek Harness 插件运行手册](<../operations/DeepSeek Harness插件运行手册.md>)，边界和工具语义见 [DeepSeek Harness 插件集成设计](<../architecture/DeepSeek Harness插件集成设计.md>)。

管理端 `POST /admin/rebuild-plan` 同步返回重建预检，包含 `mode`、`fallback_to_full`、`fallback_reasons`、新增/变化/复用/删除计数、逐文档原因和处理契约。请求体与重建任务共用 `JobRequest`：`mode` 可取 `incremental`（默认）或 `full`。

`POST /admin/jobs/rebuild` 创建异步候选重建任务。增量模式只减少解析与 Embedding 输入，仍生成完整候选数据库；契约或缓存不满足复用条件时自动全量回退。任务成功输出包含 `incremental_plan`、`rebuild_mode`、`candidate_gate`、`candidate_gate_report`、`answer_evaluation_required` 和 `latest_reports_published`；候选门禁失败时任务失败并保留版本目录中的报告，活动指针不变。`GET /admin/quality/status` 分别返回 `candidate_activation`（预激活运行时/检索门禁）和 `quality_gate`（含回答级盲测的完整发布门禁），客户端不能把前者通过解释为可直接发布。

`POST /admin/jobs/{job_id}/resolve` 用于治理已经失败的历史任务。它只追加 `resolution` 审计对象，不修改原始 `status=failed`、错误码或错误信息；`acknowledged` 表示已核对且不再阻断，`superseded` 表示已被后续成功任务替代，后者必须关联一个 `succeeded` 任务。质量门禁只忽略具备完整处置状态、说明和时间的失败记录；任务日志会追加 `JOB_FAILURE_RESOLVED` 事件。

### 规范来源管理

规范管理接口统一位于 `/admin/sources`，受现有管理 API 鉴权和限流保护：

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 查询目录 | `GET /admin/sources` | 返回来源、资产版本、待应用变更和活动来源 revision |
| 上传新来源 | `POST /admin/sources/uploads?filename=...` | 请求体为原始 `application/pdf` 字节流 |
| 编辑元数据 | `PATCH /admin/sources/{source_id}` | 更新规范元数据和治理字段，不直接上线 |
| 替换 PDF | `POST /admin/sources/{source_id}/versions?filename=...` | 新增不可变资产版本，保留旧在线版本 |
| 重新校验 | `POST /admin/sources/{source_id}/validate` | 复核 PDF 可读性、密码状态和 SHA-256 |
| 下架/撤销 | `POST .../retire`、`POST .../discard-pending` | 只修改候选变更，旧在线版本保持可用 |
| 变更预检 | `POST /admin/sources/changes/plan` | 返回新增、替换、下架、保持和阻断项 |
| 提交构建 | `POST /admin/sources/changes/build` | 固化来源 revision 并提交候选知识库任务 |
| 迁移旧来源 | `POST /admin/sources/bootstrap` | 仅空来源目录可用，显式导入现有 `data/raw` |

上传端点采用流式落盘，不使用 multipart；浏览器应直接发送 `File` 作为请求体。单文件上限由 `SOURCE_UPLOAD_MAX_BYTES` 控制。上传成功只表示资产登记成功，候选门禁通过前不会改变在线知识库。

`GET /admin/status` 的 `quality_evidence_context` 只返回证据契约版本和当前 `runtime_config_hash`，不返回用于计算哈希的原始配置或任何 Key。完整验证必须核对三类报告的 `verification_run_id` 和运行指纹；客户端提交的运行 ID 只用于关联，不能提交或覆盖服务端配置指纹。

`POST /admin/provider-probes` 是受全局 API 鉴权保护的显式供应商能力探测。它并行执行一次最小智谱 Embedding 调用和一次最小 MiMo 聊天调用，返回 `provider`、`capability`、`model`、`ok`、稳定状态、耗时和可选 HTTP 状态。响应不会包含 Key、请求内容、上游正文或模型输出。状态可区分 `not_configured`、`auth_failed`、`rate_limited`、`timeout`、`unavailable`、`request_failed` 和 `invalid_response`；调用会产生少量外部请求和可能的供应商费用，不应用作高频健康检查。`/ready` 仍只检查本地资产和配置存在性，不调用外部供应商。

`GET /admin/evaluation/status` 和 `GET /admin/quality/status` 优先通过 `data/audit/reports/quality_run_latest.json` 读取同一次完整运行。只有指针不存在的旧部署才回退 `*_latest`；指针存在但损坏、清单或产物完整性失败时不回退，并在响应的 `quality_evidence_errors` 返回固定值 `quality_evidence_unavailable`。`quality_gate.failed_checks` 同时包含阻断项 `evaluation_report_integrity`，客户端不得把空摘要解释为零失败或尚未运行。

`GET /admin/quality/runs` 返回通过完整性校验的质量运行摘要；`GET /admin/quality/runs/compare` 只接受两个不同的 32 位小写运行 ID，并比较评估集修订/哈希、运行数据、配置指纹、指标变化和失败用例变化。接口只读取完整质量运行目录，不接受客户端提交报告内容；缺失、损坏或未完成运行返回 400。

### 评估任务语义

| 路径 | 目标与结果语义 |
| --- | --- |
| `POST /admin/jobs/evaluate` | 请求体为 `evaluation_set=regular|structured`、`top_k` 和可选的 32 位小写十六进制 `verification_run_id`；使用当前 API 已加载的检索状态，服务端自行写入 `runtime_config_hash`；检索未就绪或评估器返回 `ok: false` 时任务为 `failed`，报告和机器可读错误保留在 `outputs` |
| `POST /admin/jobs/evaluate-answers` | 请求体只允许 `evaluation_set=answer` 和可选 `verification_run_id`；使用服务端 `ANSWER_EVALUATION_API_BASE` 回调问答和图片接口，不允许客户端提供目标 URL、配置指纹或文件路径 |
| `GET /admin/evaluation/cases` | 只读浏览内置评估用例；`evaluation_set` 支持 `regular`、`structured`、`answer`，并可按 `search`、`case_type` 筛选，使用 `offset`/`limit` 分页。常规与结构化用例返回来源、条文、权威类型、表格编号和关键词约束；回答盲测返回必现、任选、禁止词、引用、单位、拒答和截图断言 |

### 评估集管理语义

`/admin/evaluation/sets` 是受控的评估集生命周期入口。客户端只能使用 `regular`、`structured`、`answer` 三个服务端注册的逻辑 ID，不能提交文件路径、URL 或任意评估文件。已发布修订不可编辑；修改必须先创建草稿，草稿经过当前内容哈希校验后才能发布。发布和回退都会创建不可变修订，旧修订文件不被覆盖。

| 路径 | 语义 |
| --- | --- |
| `GET /admin/evaluation/sets` | 返回评估集可读名称、当前发布修订、草稿状态和数量 |
| `GET /admin/evaluation/sets/{evaluation_set_id}` | 返回当前发布用例和草稿用例，内部修订 ID 仅作追溯信息 |
| `GET /admin/evaluation/sets/{evaluation_set_id}/revisions` | 返回不可变修订历史，含内置基线 |
| `POST /admin/evaluation/sets/{evaluation_set_id}/drafts` | 从当前发布修订创建草稿；已有草稿时必须显式请求重置 |
| `PATCH/POST/DELETE .../drafts/...` | 分别编辑、新增或删除草稿用例；每次修改都会使上次校验失效 |
| `POST /admin/evaluation/sets/{evaluation_set_id}/validate` | 返回结构错误、统计结果、警告和当前草稿内容哈希 |
| `GET /admin/evaluation/sets/{evaluation_set_id}/diff` | 返回草稿相对当前发布修订的新增、删除和修改 |
| `POST /admin/evaluation/sets/{evaluation_set_id}/publish` | 仅允许发布已通过且哈希仍匹配的草稿 |
| `POST /admin/evaluation/sets/{evaluation_set_id}/rollback` | 从历史修订创建新的发布修订，不删除历史记录 |

评估任务和候选/质量门禁使用当前已发布修订，并在报告或门禁证据中记录 `evaluation_set_revision_id` 与 `evaluation_set_hash`。发布新修订不会修改旧报告，但旧报告的修订或哈希不匹配时不能通过当前质量门禁；重新运行评估后才可形成新的当前证据。发布或回退事件同时写入 `data/evaluation_sets/quality_refresh_queue.jsonl`，质量验证中心据此展示待重跑评估；页面管理能力仍不等于评估答案的专业正确性审核。

评估任务成功只表示所有用例均完成。用例断言失败、命中率不足或回答通过率低于门禁阈值仍可形成 `succeeded` 任务，但报告中的 `failures`/`pass_rate` 会使质量门禁失败。目标 API 不可达、`/ready` 未就绪、响应不可解析或回答请求未完成属于评估执行失败，任务必须为 `failed`。这一边界防止把基础设施故障统计为一次有效的零分评估。

评估资产由服务端把稳定标识映射到仓库内版本化文件；客户端不得传递绝对路径、相对路径或任意自定义文件。未知标识、旧 `file` 字段和其他额外字段返回 HTTP 422。任务输出及 JSON/Markdown 报告包含 `evaluation_set_id`，并继续记录服务端实际文件路径和哈希用于同环境溯源。自定义评估集只能通过受控本地 Python 调用执行，不属于管理 HTTP API。

### 知识版本管理

| 路径 | 语义 |
| --- | --- |
| `GET /admin/versions` | 扫描版本根目录，返回状态、占用、指纹、保护原因、策略和当前可清理候选；支持 `q`、`state`、`scope`、`offset`、`limit` 查询参数，明细可服务端分页；不修改文件 |
| `PUT /admin/versions/{version_id}/retention` | 设置或取消人工固定；请求体为 `pinned` 和可选 `note`，操作写审计事件 |
| `POST /admin/versions/cleanup-plans` | 按服务端生效策略生成并持久化限时清理计划；客户端不能提交路径或阈值 |
| `POST /admin/jobs/cleanup-versions` | 提交已有 `plan_id` 进入串行后台任务；执行前重新核对保护集、策略和目录指纹 |

活动版本、排队/运行中的重建、人工固定、固定标记异常、路径异常、最短保护期和近期回滚版本始终受保护。计划过期、策略变化或目录指纹变化会阻止删除；部分删除失败会生成执行报告并使后台任务失败。接口不处理原始 PDF、根 manifest、活动指针、批准修正或全局审计目录。详细决策见 [ADR 0006](../adr/0006-知识版本采用计划确认与受保护清理.md)。

`GET /admin/versions` 的筛选参数只影响返回的版本明细，不影响服务端对全部版本执行保护判断和清理候选计算：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `q` | 字符串，最多 256 个字符 | 匹配版本 ID、扫描错误或保护/清理原因 |
| `state` | `active`、`running`、`passed`、`failed_gate`、`invalid_gate`、`legacy_complete`、`incomplete`、`unsafe` | 按版本状态筛选；省略时返回全部状态 |
| `scope` | `cleanup`、`protected`、`pinned` | 按可清理、受保护或人工固定范围筛选；省略时返回全部范围 |
| `offset` | 非负整数，默认 `0` | 匹配结果的起始位置 |
| `limit` | `0`～`200`，默认 `0` | 返回条数；管理后台分页使用正数，`0` 表示返回全部匹配明细以兼容内部调用 |

响应中的 `version_count` 和清理统计基于全部版本，`matched_version_count` 是筛选后的总数，`page_offset`/`page_limit` 是本次明细窗口。清理计划接口不使用分页参数，因此仍基于完整库存生成候选。

版本接口同时返回面向用户的 `version_label` 和用于目录、任务、治理接口的 `version_id`。`version_label` 默认由构建清单的
`built_at` 生成，例如 `KB-20260823-180620`（按 UTC 编码）；旧版本没有有效构建时间时使用其最后变化时间，异常目录再回退为内部 ID 的短标识。
可读标签仅用于展示和搜索，清理、固定、活动指针及文件路径仍必须使用 `version_id`。`active_version_label` 表示当前活动版本
的同一可读标签。清理计划候选也返回 `version_label`，但执行计划仍以不可变的 `version_id` 和目录指纹为准。

### 后台任务状态

| 路径 | 语义 |
| --- | --- |
| `GET /admin/jobs` | 返回持久任务列表及逐项 `diagnostics` |
| `GET /admin/jobs/{job_id}` | 返回单项任务及诊断；非法任务标识返回 HTTP 400，不存在返回 404 |
| `GET /admin/jobs/{job_id}/logs` | 返回最多 1000 条任务 JSONL 日志；`limit` 被限制在 1-1000 |

任务记录保留 `worker_id`、`heartbeat_at`、`progress_at`、`updated_at`、`error_code` 和 `recovery`。`diagnostics` 包含 `stalled`、`heartbeat_stale`、`reason`、进度/心跳年龄及生效阈值。`stalled=true` 表示任务超过配置时间没有推进步骤，不证明线程已经停止；`heartbeat_stale=true` 表示已记录的执行器心跳过期。

API 启动时会先对账任务，再初始化检索。旧执行器遗留的 `queued`/`running` 任务被收口为 `failed`/`interrupted`，错误码为 `PROCESS_RESTARTED`，并写恢复元数据和结构化日志。系统不会自动续跑或强杀 Python 工作线程，操作者应核对候选资产后显式重提。任务 JSON 使用同目录临时文件原子替换，并校验文件名与记录内 `job_id` 一致；损坏记录以 `JOB_RECORD_INVALID` 暴露且不阻断服务启动。该协议当前只适用于单 API 进程、单工作线程。

## 运行诊断契约

`GET /health` 只证明 API 进程能够响应，成功时返回 HTTP 200。`GET /ready` 检查 Chroma、活动 manifest、集合数量一致性、BM25 和两个模型密钥：全部满足时返回 HTTP 200，否则返回 HTTP 503。两种状态都返回同一结构：

```json
{
  "ready": false,
  "status": "not_ready",
  "checked_at": "2026-08-08T00:00:00+00:00",
  "reasons": ["MIMO_KEY_MISSING"],
  "data_version_hash": "",
  "built_at": "",
  "checks": {}
}
```

`reasons` 是供探针、控制台和告警规则使用的稳定机器码；`checks` 提供计数和依赖明细。客户端必须按 HTTP 状态判断是否接收问答流量，不能只判断响应体是否为 JSON。

`GET /metrics` 返回当前 API 进程自启动以来的 JSON 快照，包括请求总量、处理中请求、路由组和状态码分布、错误码分布、请求耗时统计以及最近错误。指标仅保存在进程内，重启后清零，也不会跨多个 worker 聚合；当前接口不是 Prometheus exposition 格式。

每个 HTTP 响应包含 `X-Request-ID`。客户端可以传入满足长度与字符约束的同名请求头，非法值会被替换。后台任务保存创建请求的 `request_id`，其 JSONL 日志也携带同一字段，可用于从请求追踪到任务执行。日志不会记录完整问答文本。

## 鉴权与兼容性

当 `API_AUTH_ENABLED=true` 时，聊天、校对和管理接口使用 `Authorization: Bearer <API_KEY>` 或 `X-API-Key: <API_KEY>`。模型列表、健康检查、指标、知识文档接口、静态资源和 OpenAPI 文档仍为公开运行面。

图片接口还执行 `data/metadata/specs.json` 中的来源策略：`public` 可直接读取，`authenticated` 接受 API Key 或系统生成的短期签名 URL，`disabled` 始终拒绝。未登记来源默认为 `authenticated`，无效策略按 `disabled` 处理。关闭全局 API 鉴权时，`authenticated` 资源只允许无代理头的回环请求；因此开发者不能用关闭鉴权的方式把受保护扫描页公开到局域网或隧道。

短期签名使用 `expires` 和 `signature` 查询参数，只携带资源授权证明，不包含 API Key。签名与路径绑定，过期、换路径或超出配置有效期均被拒绝。完整决策见 [ADR 0003](../adr/0003-来源资源采用分级访问与短期签名.md)。

## 变更策略

- 新增字段或端点：先更新后端响应模型，再重新导出 OpenAPI、生成前端类型并在发布说明中描述。
- 删除字段、改变语义、提高鉴权要求：视为破坏性变更，至少在一个发布周期前通知调用方。
- 管理接口不是稳定的第三方公共 API；对外开放前需补齐角色权限、审计和版本策略。
- `/ready` 从始终 HTTP 200 改为未就绪时 HTTP 503 属于探针语义修正；调用方应同步采用上述状态码契约。
