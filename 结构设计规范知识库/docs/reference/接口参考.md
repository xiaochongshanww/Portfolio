## 机器可读契约

服务启动后，使用以下地址获取当前接口契约：

```text
/openapi.json
/docs
```

任何客户端生成、请求/响应字段判断和错误处理，应以同版本运行服务导出的 OpenAPI 为准。Markdown 仅说明入口、兼容性和运营约束。

仓库同时提交确定性快照 `frontend/openapi.json`。管理端 43 个 JSON 操作必须具有具名 HTTP 200 schema，页面截图操作必须只声明 `image/png`。除七个明确登记的原始载荷响应外，响应 schema 均禁止未建模顶层字段。开发者使用以下命令维护契约：

```powershell
python scripts/export_openapi.py --write
cd frontend
npm run api:generate
npm run api:check
```

`api:generate` 用于更新并审阅生成文件；`api:check` 面向干净检出和 CI，重生成后拒绝未提交差异。完整的单一来源、兼容与失败边界见[管理 API 与前端类型契约规范](管理API与前端类型契约规范.md)。

除静态 schema 与生成类型外，`tests/test_admin_runtime_contract.py` 以 OpenAPI operation id 清单驱动 44 个隔离 ASGI 成功路径。新增或删除管理操作但未同步场景、实际响应缺失必需字段、包含未声明字段或返回错误媒体类型时，后端门禁失败。该测试不访问模型、解析器、网络或真实运行数据。

## 主要入口

| 路径 | 用途 |
| --- | --- |
| `POST /v1/chat/completions` | OpenAI-compatible 问答入口，支持流式响应 |
| `GET /v1/models` | 返回当前可用模型标识 |
| `GET /health` / `GET /ready` | 存活与依赖就绪检查 |
| `GET /metrics` | 服务指标快照 |
| `/admin/*` | 构建、审计、评估、校对和复杂表管理 |
| `/knowledge/*`、`/corrections/*` | 知识资产与修正相关接口 |
| `GET /images/{filename}` | 读取解析图片，执行来源策略与目录边界校验 |
| `GET /page-images/{doc}/{page}` | 从允许展示且实际存在的源 PDF 渲染页面截图 |

管理端 `POST /admin/jobs/rebuild` 创建异步候选重建任务。任务成功输出包含 `candidate_gate`、`candidate_gate_report`、`answer_evaluation_required` 和 `latest_reports_published`；候选门禁失败时任务失败并保留版本目录中的报告，活动指针不变。`GET /admin/quality/status` 分别返回 `candidate_activation`（预激活运行时/检索门禁）和 `quality_gate`（含回答级盲测的完整发布门禁），客户端不能把前者通过解释为可直接发布。

`GET /admin/status` 的 `quality_evidence_context` 只返回证据契约版本和当前 `runtime_config_hash`，不返回用于计算哈希的原始配置或任何 Key。完整验证必须核对三类报告的 `verification_run_id` 和运行指纹；客户端提交的运行 ID 只用于关联，不能提交或覆盖服务端配置指纹。

`GET /admin/evaluation/status` 和 `GET /admin/quality/status` 优先通过 `data/audit/reports/quality_run_latest.json` 读取同一次完整运行。只有指针不存在的旧部署才回退 `*_latest`；指针存在但损坏、清单或产物完整性失败时不回退，并在响应的 `quality_evidence_errors` 返回固定值 `quality_evidence_unavailable`。`quality_gate.failed_checks` 同时包含阻断项 `evaluation_report_integrity`，客户端不得把空摘要解释为零失败或尚未运行。

### 评估任务语义

| 路径 | 目标与结果语义 |
| --- | --- |
| `POST /admin/jobs/evaluate` | 请求体为 `evaluation_set=regular|structured`、`top_k` 和可选的 32 位小写十六进制 `verification_run_id`；使用当前 API 已加载的检索状态，服务端自行写入 `runtime_config_hash`；检索未就绪或评估器返回 `ok: false` 时任务为 `failed`，报告和机器可读错误保留在 `outputs` |
| `POST /admin/jobs/evaluate-answers` | 请求体只允许 `evaluation_set=answer` 和可选 `verification_run_id`；使用服务端 `ANSWER_EVALUATION_API_BASE` 回调问答和图片接口，不允许客户端提供目标 URL、配置指纹或文件路径 |

评估任务成功只表示所有用例均完成。用例断言失败、命中率不足或回答通过率低于门禁阈值仍可形成 `succeeded` 任务，但报告中的 `failures`/`pass_rate` 会使质量门禁失败。目标 API 不可达、`/ready` 未就绪、响应不可解析或回答请求未完成属于评估执行失败，任务必须为 `failed`。这一边界防止把基础设施故障统计为一次有效的零分评估。

评估资产由服务端把稳定标识映射到仓库内版本化文件；客户端不得传递绝对路径、相对路径或任意自定义文件。未知标识、旧 `file` 字段和其他额外字段返回 HTTP 422。任务输出及 JSON/Markdown 报告包含 `evaluation_set_id`，并继续记录服务端实际文件路径和哈希用于同环境溯源。自定义评估集只能通过受控本地 Python 调用执行，不属于管理 HTTP API。

### 知识版本管理

| 路径 | 语义 |
| --- | --- |
| `GET /admin/versions` | 扫描版本根目录，返回状态、占用、指纹、保护原因、策略和当前可清理候选；不修改文件 |
| `PUT /admin/versions/{version_id}/retention` | 设置或取消人工固定；请求体为 `pinned` 和可选 `note`，操作写审计事件 |
| `POST /admin/versions/cleanup-plans` | 按服务端生效策略生成并持久化限时清理计划；客户端不能提交路径或阈值 |
| `POST /admin/jobs/cleanup-versions` | 提交已有 `plan_id` 进入串行后台任务；执行前重新核对保护集、策略和目录指纹 |

活动版本、排队/运行中的重建、人工固定、固定标记异常、路径异常、最短保护期和近期回滚版本始终受保护。计划过期、策略变化或目录指纹变化会阻止删除；部分删除失败会生成执行报告并使后台任务失败。接口不处理原始 PDF、根 manifest、活动指针、批准修正或全局审计目录。详细决策见 [ADR 0006](../adr/0006-知识版本采用计划确认与受保护清理.md)。

### 后台任务状态

| 路径 | 语义 |
| --- | --- |
| `GET /admin/jobs` | 返回持久任务列表及逐项 `diagnostics` |
| `GET /admin/jobs/{job_id}` | 返回单项任务及诊断；非法任务标识返回 HTTP 400，不存在返回 404 |
| `GET /admin/jobs/{job_id}/logs` | 返回最多 1000 条任务 JSONL 日志；`limit` 被限制在 1-1000 |

任务记录保留 `worker_id`、`heartbeat_at`、`progress_at`、`updated_at`、`error_code` 和 `recovery`。`diagnostics` 包含 `stalled`、`heartbeat_stale`、`reason`、进度/心跳年龄及生效阈值。`stalled=true` 表示任务超过配置时间没有推进步骤，不证明线程已经停止；`heartbeat_stale=true` 表示已记录的执行器心跳过期。

API 启动时会先对账任务，再初始化检索。旧执行器遗留的 `queued`/`running` 任务被收口为 `failed`/`interrupted`，错误码为 `PROCESS_RESTARTED`，并写恢复元数据和结构化日志。系统不会自动续跑或强杀 Python 工作线程，操作者应核对候选资产后显式重提。任务 JSON 使用同目录临时文件原子替换，并校验文件名与记录内 `job_id` 一致；损坏记录以 `JOB_RECORD_INVALID` 暴露且不阻断服务启动。该协议当前只适用于单 API 进程、单工作线程。

## 运行诊断契约

`GET /health` 只证明 API 进程能够响应，成功时返回 HTTP 200。`GET /ready` 检查 Chroma、活动 manifest、集合数量一致性、BM25 和两个模型密钥：全部满足时返回 HTTP 200，否则返回 HTTP 503。两种状态都返回同一结构：

```json
{
  "ready": false,
  "status": "not_ready",
  "checked_at": "2026-08-08T00:00:00+00:00",
  "reasons": ["MIMO_KEY_MISSING"],
  "data_version_hash": "",
  "built_at": "",
  "checks": {}
}
```

`reasons` 是供探针、控制台和告警规则使用的稳定机器码；`checks` 提供计数和依赖明细。客户端必须按 HTTP 状态判断是否接收问答流量，不能只判断响应体是否为 JSON。

`GET /metrics` 返回当前 API 进程自启动以来的 JSON 快照，包括请求总量、处理中请求、路由组和状态码分布、错误码分布、请求耗时统计以及最近错误。指标仅保存在进程内，重启后清零，也不会跨多个 worker 聚合；当前接口不是 Prometheus exposition 格式。

每个 HTTP 响应包含 `X-Request-ID`。客户端可以传入满足长度与字符约束的同名请求头，非法值会被替换。后台任务保存创建请求的 `request_id`，其 JSONL 日志也携带同一字段，可用于从请求追踪到任务执行。日志不会记录完整问答文本。

## 鉴权与兼容性

当 `API_AUTH_ENABLED=true` 时，聊天、校对和管理接口使用 `Authorization: Bearer <API_KEY>` 或 `X-API-Key: <API_KEY>`。模型列表、健康检查、指标、知识文档接口、静态资源和 OpenAPI 文档仍为公开运行面。

图片接口还执行 `data/metadata/specs.json` 中的来源策略：`public` 可直接读取，`authenticated` 接受 API Key 或系统生成的短期签名 URL，`disabled` 始终拒绝。未登记来源默认为 `authenticated`，无效策略按 `disabled` 处理。关闭全局 API 鉴权时，`authenticated` 资源只允许无代理头的回环请求；因此开发者不能用关闭鉴权的方式把受保护扫描页公开到局域网或隧道。

短期签名使用 `expires` 和 `signature` 查询参数，只携带资源授权证明，不包含 API Key。签名与路径绑定，过期、换路径或超出配置有效期均被拒绝。完整决策见 [ADR 0003](../adr/0003-来源资源采用分级访问与短期签名.md)。

## 变更策略

- 新增字段或端点：先更新后端响应模型，再重新导出 OpenAPI、生成前端类型并在发布说明中描述。
- 删除字段、改变语义、提高鉴权要求：视为破坏性变更，至少在一个发布周期前通知调用方。
- 管理接口不是稳定的第三方公共 API；对外开放前需补齐角色权限、审计和版本策略。
- `/ready` 从始终 HTTP 200 改为未就绪时 HTTP 503 属于探针语义修正；调用方应同步采用上述状态码契约。
