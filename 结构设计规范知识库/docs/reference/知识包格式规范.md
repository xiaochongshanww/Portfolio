## 1. 用途

知识包用于在“知识资产生产环境”和“轻量问答环境”之间迁移已经构建的运行资产。它不是原始 PDF 归档格式，也不包含人工校对工作区。

导出或导入成功只表示技术完整性，不表示包内内容可以公开传播。发布者必须另行完成来源与权利审核。

## 2. 容器与目录

文件扩展名使用 `.zip`，根目录结构如下：

```text
knowledge-package.json
runtime/
  manifest.json
  db/
  structured_tables/
  images/
  raw/
```

其中 `knowledge-package.json`、`runtime/manifest.json` 和 `runtime/db/` 为必需项。其余目录按清单中的能力声明选择性存在；`runtime/raw/` 默认不包含。

## 3. 包清单

`knowledge-package.json` 使用 UTF-8 JSON，核心字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | string | 固定为 `structural-spec-knowledge-package` |
| `schema_version` | integer | 当前导出为 `2`；校验和导入兼容 `1` |
| `package_id` | string | v2 由数据版本、实际 payload 哈希和质量证据哈希共同生成；v1 只绑定前两项 |
| `profile` | string | 当前固定为 `runtime` |
| `created_at` | string | UTC ISO 8601 时间 |
| `data_version_hash` | string | 来源构建 manifest 的数据版本 |
| `payload_hash` | string | 对排序后的文件路径、角色、大小与 SHA-256 声明计算的摘要 |
| `document_count` | integer | 文档数量摘要 |
| `chunk_count` | integer | chunk 数量摘要 |
| `compatibility` | object | 应用、Chroma、Embedding 和集合信息 |
| `capabilities` | object | 数据库、表、图片和原始 PDF 是否包含 |
| `quality` | object | v2 必需；门禁时间、数据版本、失败项、报告有效期、豁免和审计事件 |
| `files` | array | 所有 payload 文件的路径、大小、SHA-256 和角色 |

清单本身不出现在 `files` 中。除清单外，ZIP 中不得出现未声明文件。

v1 包没有 `quality` 字段，只为已有包保留技术兼容。它不能作为已经通过当前质量门禁的证据。

## 4. 能力声明

```json
{
  "prebuilt_vector_index": true,
  "structured_tables": true,
  "extracted_images": true,
  "source_pdfs": false,
  "page_images": false
}
```

`page_images` 只有在包含原始 PDF 时才为 `true`。缺少原始 PDF 的运行环境不得承诺 `/page-images/{doc}/{page}` 可用。

## 5. 完整性与安全规则

1. 所有 payload 文件必须使用相对 POSIX 路径。
2. 禁止绝对路径、盘符、反斜杠、空路径、`.` 和 `..` 路径段。
3. 每个文件必须匹配清单声明的大小和 SHA-256。
4. 不允许重复路径、符号链接或未声明文件。
5. 导入必须先完整校验，再复制资产，最后切换活动数据库指针。
6. 知识包不得包含 `.env`、API Key、运行时密钥或用户凭据。
7. SHA-256 清单用于发现损坏和非预期改动，不提供发布者身份认证；从不受信任渠道取得的包不得仅因校验通过而执行导入。
8. v2 包必须包含与 `data_version_hash` 一致的质量证据；门禁未通过时必须包含责任人和原因完整的显式豁免。
9. v2 `package_id` 绑定规范化质量证据；门禁时间、失败项、责任人、原因或审计事件变化都会改变包标识。

## 6. 兼容性

运行包携带预构建 Chroma 数据库，因此目标环境应使用兼容的 Chroma 主版本、相同集合名称和相同 Embedding 模型。导入工具对可识别的不一致给出警告；最终可用性仍需通过 `/ready`、集合数量和问答冒烟测试确认。

## 7. 生命周期

- 导出：读取活动数据库和对应 manifest，实时计算质量门禁；通过或完成显式豁免审计后，收集运行资产并生成哈希清单。
- 校验：不写入本地数据，只检查格式、路径、文件声明和哈希。
- 导入：安装为独立数据库版本，复制可选资产，更新根 manifest 和活动数据库指针。
- 激活后：重启或重载 API，再执行健康检查与质量门禁。
- 回退：恢复之前的 `active_db.json` 和 manifest；可选资产冲突必须使用导入前备份恢复。

具体命令和操作限制见 [部署运行手册](../operations/部署运行手册.md)。
