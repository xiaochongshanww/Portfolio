# 封闭试用方案

> 状态：草案
> 维护角色：产品与工程负责人
> 文档更新：2026-08-20
> 代码/流程核对：2026-08-20，已与 D-001、D-002 和来源登记台账边界核对
> 完整运行验证：不适用（尚未执行真实用户试用）
> 验证证据：[产品方向与边界](产品方向与边界.md)、[技术与产品待决策事项](../architecture/技术与产品待决策事项.md)、[来源登记台账](../governance/来源登记台账.md)
> 复核周期：每次试用前及试用结束后
> 访问级别：内部

## 目标

本方案用于验证一个窄范围的真实工作任务是否值得继续投入，不把一次试用包装成市场验证，也不承诺公开服务、收费服务或普遍准确性。

首轮只验证：用户能否使用已经构建的运行知识包完成规范定位、条文/表格依据确认和结果复核。首轮不要求用户本地解析扫描 PDF，因此不把 MinerU 的硬件和命令行门槛混入问答体验结论。

## 前置条件

试用开始前必须完成并留存：

- 参与者、任务范围、试用期限和反馈方式的书面确认；
- 所使用来源在[来源登记台账](../governance/来源登记台账.md)中有记录，并确认 B 级内容只用于封闭验证；
- 部署位置、API Key、日志、用户问题和反馈的责任人明确；
- 不上传与任务无关的个人信息、客户图纸或未获授权的第三方文件；
- 明确回答不能替代规范原文、设计复核或专业责任判断；
- 具备停止服务、删除试用数据和处理投诉的联系人及记录位置。

任一前置条件不满足时，试用保持 `planned`，不得通过公开链接或开放注册扩大范围。

## 试用配置

| 项目 | 首轮约束 |
| --- | --- |
| 参与者 | 由项目负责人邀请的少量专业用户，人数和名单写入试用记录 |
| 内容 | 当前已构建知识包；不向参与者分发原始 PDF |
| 交付 | 受控宿主机或受控运行包，具体方式在记录中填写 |
| 问题 | 预先准备一组规范定位、数值取值、公式/表格理解任务，并允许用户提交少量真实问题 |
| 证据 | 每个回答保留规范、条文/表号、页码和用户是否能复核的结果 |
| 数据 | 只保留完成任务所需的最小日志和脱敏反馈，试用结束按记录执行清理 |

## 执行步骤

1. 为每位参与者分配试用编号，填写[封闭试用记录模板](封闭试用记录模板.md)。
2. 先执行固定任务，再允许提交真实问题，避免只凭主观印象评价。
3. 参与者分别记录：是否找到依据、是否理解表格/公式、是否需要回看原页、是否发现明显错误、耗时和阻塞原因。
4. 项目负责人核对高风险答案的原始页面、条文号、表号、公式和单位，不把用户“觉得合理”当作正确性证据。
5. 对检索错误、解析错误、引用错误、界面问题和权限问题分别登记，不混成一个满意度分数。
6. 试用结束后生成结论：继续、调整后再试、暂停，及其证据链接。

## 记录格式与校验

实际记录应保存为受限目录中的机器可读 JSON，并保留一份适合人工阅读的记录。字段应按[封闭试用记录模板](封闭试用记录模板.md)填写；完成或暂停前必须运行：

```powershell
python scripts/validate_trial_record.py --record <trial-record.json>
```

校验器只检查记录结构、前置条件、固定任务依据、缺陷分类、收口结论和密钥字段安全边界，不会把自动校验结果当成真实用户证据，也不会读取或输出原始规范内容。校验通过不等于试用完成；`completed` 或 `paused` 记录还必须由负责人核对原始页面、用户反馈和数据清理结果。

为减少手工 JSON 编辑错误，可以先生成一个 `planned` 记录：

```powershell
python scripts/create_trial_record.py `
  --output <受限目录>\trial.json `
  --trial-id TRIAL-001 `
  --participant-id P-001 `
  --delivery 受控宿主机 `
  --environment-owner project-owner `
  --source-register-version source-register-2026-08-20 `
  --task "规范定位" `
  --task "表格取值" `
  --task "公式复核"
```

该命令只生成待填写计划，不设置前置条件、不生成依据、不记录结论，也不会把试用标记为完成。执行前仍须由负责人填写并确认全部前置条件。

## 判定标准

以下是内部试用门槛，不是市场承诺：

- 固定任务能被参与者独立完成，且阻塞原因可被记录和复现；
- 高风险答案都能回到规范标识、条文/表号和页码，不能只依赖模型解释；
- 未发现跨用户数据泄露、未授权来源外泄、密钥暴露或错误的公开资源访问；
- 反馈能够区分“内容/解析问题”和“产品交互问题”；
- 维护成本、供应商调用成本和部署责任有人承担。

出现未授权内容传播、无法解释的高风险错误、用户数据泄露或无法停止服务时，立即暂停试用并进入事故/下架流程。

## 当前结论

本文件只完成了试用治理方案，尚未证明目标用户愿意持续使用，也没有关闭 D-002。试用证据、用户任务频率、交付成本和后续方向必须写入实际记录后，才能更新产品方向文档。
