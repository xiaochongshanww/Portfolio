# 产品方向与边界

> 状态：生效  
> 维护角色：产品与工程负责人  
> 文档更新：2026-08-08  
> 流程核对：2026-08-08  
> 完整运行验证：不适用（本文件定义当前产品边界）  
> 验证证据：[技术与产品待决策事项](../architecture/技术与产品待决策事项.md)、[内容与来源治理政策](../governance/内容与来源治理政策.md)  
> 复核周期：每月或产品方向变化时

## 当前定位

本项目当前是结构设计规范知识库的工程验证项目，重点验证扫描 PDF 解析、结构化校对、规范知识排序、可追溯问答和运行知识包交付。现阶段不把“已经形成可公开销售或可无条件分发的商业产品”作为事实陈述。

项目面向的潜在使用者包括结构设计、审图和工程技术人员，但目标用户、使用频率、付费意愿和首选交付方式尚未经过真实市场验证。开发决策应优先积累可验证的使用证据，避免把技术能力直接等同于产品需求。

## 当前可确认能力

- 通过受控流程解析 PDF、审计结果、人工处理高风险内容并构建知识库。
- 通过混合检索、领域排序和回答约束提供带来源的规范问答。
- 通过评估集、盲测和质量门禁发现检索、回答与引用回归。
- 将已构建的运行数据导出为知识包，以减少目标环境对 MinerU 等重型构建依赖。

具体能力和限制以[系统架构概览](../architecture/系统架构概览.md)、[RAG 系统卡](../quality/检索增强生成系统卡.md)和实际代码为准。

## 尚未承诺的产品能力

- 不承诺公共 Web 服务、商业收费服务或应用商店安装包。
- 不承诺普通用户可以在零配置条件下完成 PDF 解析和知识库构建。
- 不承诺所有规范及扫描件具备对外展示、传播或商业使用权。
- 不承诺回答可以替代原规范、设计复核或专业责任判断。
- 不承诺跨操作系统、跨架构和跨数据库主版本的知识包完全兼容。

## 交付边界

当前保留源码运行、宿主机部署和运行知识包三种技术路径，但最终交付形态仍按[技术与产品待决策事项](../architecture/技术与产品待决策事项.md)中的 D-002 管理。任何真实用户试用都应先明确：

1. 试用对象和需要解决的具体任务；
2. 内容来源和截图展示权限；
3. 部署、密钥、数据和日志由谁管理；
4. 失败反馈、版本更新和停止服务方式；
5. 用什么证据判断继续、调整或停止该交付方向。

## 决策原则

1. 先验证用户任务，再扩大功能和部署投入。
2. 先解决内容权利和来源可追溯，再扩大分发范围。
3. 先通过质量门禁和人工边界，再对外承诺准确性。
4. 未经决策登记和验证的设想只能标记为候选方向，不能写入当前能力清单。

早期“成熟商业产品”路线保留在[产品化实施方案（归档）](../archive/结构设计规范知识库产品化实施方案.md)，仅作为历史背景，不代表当前承诺。
