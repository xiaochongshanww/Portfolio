## 定位

本原型集用于在正式前端重构前，统一审阅管理后台的页面结构、工作流入口、信息层级和交互边界。它是独立的静态 HTML 原型，不替代当前 Vue 页面，不连接真实 API，也不代表后端功能已经完成。

本轮沿用已通过评审的“工作流驾驶舱”视觉和信息架构，并将其拆解为六个可独立审阅的业务工作区：

1. **规范来源目录**：查看来源资产、元数据、权利状态和候选变更。
2. **构建任务队列**：查看构建任务、阶段、日志摘要、产物和失败原因。
3. **内容校对工作台**：对照原 PDF、解析结果、AI 证据和最终修正文进行审核。
4. **复杂表结构化队列**：集中处理复杂表识别、结构化结果和人工确认。
5. **质量验证中心**：查看质量门禁、评估集运行结果和发布阻断项。
6. **问答验证工作区**：用固定测试问题验证检索、引用和回答渲染效果。

## 治理扩展页面

版本管理是工作流驾驶舱中“版本关系”的独立治理入口，用于查看活动版本、候选版本、保护原因和受保护清理策略。它不改变六个生产工作区的主流程，但作为治理与验证分组下的独立页面提供版本清单操作。

- 原型：`版本管理页面原型.html`
- 当前状态：实施中，待独立页面评审后纳入正式页面基线。
- 必须保留：状态解释、活动版本保护、清理计划二次确认、版本详情和人工固定备注。

## 交互边界

- 左侧导航用于切换工作区，当前页面通过蓝色 Active 状态和 `aria-current` 表达。
- 顶部页面操作只表达该工作区的主入口；页面内部的按钮表达选择、保存、审核或查看详情。
- 原型中的数据、状态、日志和 PDF/表格均为演示数据，正式实现必须从后端任务状态、来源 revision、候选版本和知识包资产读取。
- 复杂表工作区保留“原 PDF 页面 + 结构化结果 + 人工确认”的三段关系，不能把表格退化为普通纯文本校对。
- 问答验证工作区保留问题、检索依据、引用和回答渲染区，不能只展示原始 JSON。

## 审阅重点

人工审阅时优先确认以下问题：

- 用户能否从任一页面判断当前所处生产阶段，以及下一步应做什么；
- 规范来源、构建候选、校对任务和质量门禁之间的状态关系是否符合实际流程；
- 失败任务是否能在任务列表、日志摘要和详情区定位到可执行的整改动作；
- 原 PDF、解析文本、结构化表格、最终修正文和问答引用是否保持可追溯关系；
- 窄屏或较窄浏览器窗口下是否仍能完成查看、选择和提交操作。
