## 1. 预期用途

为结构设计规范的条文定位、定义解释、表格取值、公式说明和版本范围问题提供带证据的问答辅助。特别适合“哪一条规定”“某取值/系数是多少”“适用条件是什么”等可追溯问题。

## 2. 非预期用途

- 不直接给出工程设计、审图、施工或安全责任结论。
- 不在缺失权威依据时编造条文、数值、公式或图片。
- 不自动批准复杂表、公式和强制性条文的解析修正。
- 不替用户确认规范现行性、地区适用性或项目专门要求。

## 3. 检索与回答策略

常规检索以 dense、BM25、条文号匹配、查询意图和规范权威规则形成基线排序。系统已具备默认关闭的智谱学习型精排提供方：启用后先扩展候选池，再将模型位次与基线位次融合；超时、限流、HTTP 或响应契约错误会回退基线，并通过 `/metrics` 暴露精排请求、成功、降级和耗时。该能力尚无当前活动数据上的真实供应商对照结论，不能据此宣称检索质量提升，仓库默认仍为关闭。

发布质量证据采用证据上下文 v1。常规检索、结构化检索和回答盲测必须具有同一 `verification_run_id`，并与当前运行配置及关键实现的不可逆哈希一致；旧契约、跨运行或跨配置报告不能组合为通过结论。哈希输入排除模型/API Key、完整查询、回答和用户内容。

显式质量预检在本地就绪和管理鉴权之后，通过受保护的 `POST /admin/provider-probes` 分别发起最小 Embedding 与聊天调用。探测只返回能力、模型、稳定状态、延迟和可选 HTTP 状态，不回显 Key、请求内容、上游正文或模型输出。鉴权失败、限流、超时、5xx、网络不可达或无效载荷会在三类评估启动前失败关闭；`/ready` 仍保持无外部调用的本地就绪语义。该机制只能证明调用链在检查时刻可用，不证明内容质量或供应商持续可用。

完整运行证据采用运行目录、完整性清单和原子最新指针。清单出现后该运行不可编辑；托管 API 的最终指针仅在父进程完成回收并合并生命周期结论后发布。兼容 `*_latest` 文件不作为新代码的权威来源，指针或产物损坏时失败关闭。该机制能发现本机文件意外损坏和部分发布，但不是数字签名，也不能抵抗具有主机写权限的可信边界内主体协同篡改。

原始质量运行采用受控生命周期治理：最新指针、脱敏历史引用、最近封存运行和最小保护期内运行不可进入清理计划；删除必须经过持久化计划、锁内重检和审计执行。该机制降低误删和无限增长风险，但原始运行一旦删除只能从受控运行数据备份恢复，脱敏快照不能还原问题与回答正文。

1. 采用 dense 语义召回、BM25、条文号匹配和领域排序。
2. 对“标准值、系数、限值、取多少、表号”等取值意图，优先规范正文表格和已发布结构化表。
3. 权威性通常按正文表格、正文条文、附录、条文说明排序；具体结果仍需同时满足规范、版本、条文/表号和内容匹配。
4. 回答提供规范标识、条文/表号、页码和可用截图引用，格式遵循 [答案格式规范](../reference/规范问答答案格式规范.md)。

## 5. 已知限制

- 扫描件 OCR、复杂跨页表、图形公式和合并单元格仍需要人工核对。
- 评估集的规范覆盖有限，新规范接入后必须扩充相应测试。
- 结果正确性依赖来源权利状态、解析版本、活动数据库和模型供应商可用性。
- 结构化表的可信度只覆盖已审核发布资产，草稿和 AI 建议不构成正式依据。

## 6. 变更要求

改变模型、Embedding、提示词、权威规则、结构化资产或评估阈值前，必须记录影响、执行回归、保留报告，并在必要时新增 ADR 和发布说明。
