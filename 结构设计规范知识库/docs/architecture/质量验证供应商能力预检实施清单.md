## 背景与基线

当前 API 在本地资产完整、Key 非空时返回 `/ready=true`。真实完整复验随后证明两家供应商都返回 HTTP 401：结构化 12 条通过，常规 100 条有 1 条在 Dense 失效后的降级检索中失败，回答 24 条全部因 MiMo 401 被 API 转换为 502。现有预检没有区分“配置存在”和“外部能力可用”。

## 目标

在不扩大秘密暴露面、不增加高频健康探针外网依赖的前提下，让显式质量预检真实验证 Embedding 与聊天能力，并在前置失败时阻止无意义的完整评估。

## 实施清单

- [x] 1. 建立脱敏供应商探测服务
  - 最小请求分别验证智谱 Embedding 与 MiMo 聊天。
  - 稳定区分未配置、鉴权失败、限流、超时、不可用和响应无效。
  - 响应与日志不包含 Key、请求内容、上游正文或模型输出。

- [x] 2. 建立受保护管理 API 契约
  - 新增严格响应模型和 `POST /admin/provider-probes`。
  - 更新 OpenAPI、生成客户端、语义别名和运行时成功场景。
  - 证明 `/ready` 语义保持不变。

- [x] 3. 将能力探测接入质量预检
  - 本地就绪与管理鉴权通过后执行供应商探测。
  - 完整验证在能力失败时跳过常规、结构化与回答评估，并形成同运行失败占位证据。
  - `--preflight-only` 保持不写质量报告，输出继续 ASCII 安全且不含秘密。

- [x] 4. 完成故障矩阵与完整门禁
  - 覆盖成功、401、429、超时、5xx、无效载荷和端点访问失败。
  - 通过 Ruff、OpenAPI、后端全量、前端测试/类型/构建及工程策略门禁。
  - 使用当前失效凭据证明真实预检在评估前失败关闭。

- [x] 5. 收口文档、提交与远程证据
  - 更新配置参考、接口参考、系统设计、运营手册、发布检查单、系统卡、文档中心和路线图。
  - 快照当前真实失败质量证据，不把工程修复写成内容质量通过。
  - 项目路径提交并推送，远程 CI 全部通过后标记 I-041 完成。

## 验收边界

- 本轮不更新、猜测或回显任何供应商 Key；凭据更新仍由秘密管理边界负责。
- 本轮不改变检索排序、评估样本、阈值或模型选择。
- 探测成功只证明调用链在该时刻可用，不证明内容答案正确、额度长期充足或供应商 SLA。
