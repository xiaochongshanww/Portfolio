## 背景

Dockerfile 只复制前端源码、后端源码、运行依赖锁、评估集和规范元数据，但当前 `.dockerignore` 仍允许 `.tools`、`frontend/node_modules`、`db` 与 `.runtime_*` 等本机资产进入构建上下文。当前工作目录中 `.tools` 与前端依赖缓存已超过 1.3 GiB，运行文件还包含本机 API Key、隧道地址和日志。未被 `COPY` 不等于未发送给构建器，因此需要把上下文边界变成可执行安全契约。

## 目标

构建上下文采用默认拒绝、显式放行策略，只发送 Dockerfile 实际需要的输入。任何新增放行都必须同步 Dockerfile、校验器、测试和文档；本机秘密、运行数据、开发工具与依赖缓存不能依赖个人清理习惯。

## 边界

- 本轮不改变最终镜像内容、运行依赖、Compose 持久卷或 API 行为。
- 上下文最小化降低误发送和构建开销，但不替代 BuildKit 远端权限控制、镜像扫描或秘密管理。
- Dockerfile 新增本地 `COPY` 输入时必须显式扩展允许集，不能退回宽泛包含整个仓库。
