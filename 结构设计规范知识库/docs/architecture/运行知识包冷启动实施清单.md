## 问题定义

当前 `package-probe` 能把知识包导入临时目录并直接打开 Chroma，但 API 仍默认读取源码内固定的 `data/`。因此现有证据没有覆盖用户真正需要的链路：在空运行目录导入知识包，启动服务，然后由 API 读取 manifest、索引和知识清单。

## 目标行为

1. 运行数据根可通过单一 `DATA_DIR` 设置，默认环境保持兼容。
2. 包导入目录与 API 运行目录使用同一契约，不需要复制文件或修改源码。
3. 来自 Windows/Linux 的真实 Chroma 包可以在另一平台导入后启动 API。
4. 冷启动验证不调用外部模型，不依赖真实密钥或版权受限资料。
5. 失败必须表现为明确的非就绪状态或非零退出，不能用空知识库冒充成功。

- [x] 新增统一路径解析函数，并支持绝对与项目根相对的 `DATA_DIR`。

## 非目标

- 本轮不改变知识包内容授权、签名信任根或对外分发决定。
- 本轮不调用问答模型，因此不证明生成答案质量或外部供应商可用性。
- 本轮不实现安装器、多租户、自动远程下载或任意目录自动发现。
- 原始 PDF 默认仍不进入知识包；页面动态渲染能力继续由来源策略和 D-005 管理。
