> 文档更新：2026-08-08

> 验证证据：本文件中的验收条件、关联提交、CI 结果与质量报告  
> 复核周期：每轮迭代结束或优先级变化时

## 目标

在不预设商业化结论的前提下，把项目持续推进为可复现、可交付、可评估、可追溯的专业知识库工程。技术改进不能绕过内容权利、人工校对和产品待决策事项。

## 排序原则

1. 先修复会导致安装、启动、数据完整性或质量判断失真的基础缺口。
2. 优先实施不依赖外部授权、模型密钥和人工专业结论的自动化能力。
3. 每项工作必须定义可执行验收证据；只有证据完成后才标记为完成。
4. 涉及内容分发、公开服务、安装器和商业承诺的事项继续由待决策登记管理。

## 当前迭代验收

- [ ] CI 后端任务通过全部自动化测试。
- [ ] CI 前端任务通过 `npm ci` 和生产构建。
- [ ] CI 容器任务完成镜像构建、健康检查和控制台静态页检查。
- [ ] Docker Compose 使用持久化 Open WebUI 数据卷，并将 API 地址配置为 OpenAI-compatible `/v1` 基址。
- [ ] 启用 API 鉴权时，Open WebUI 使用与 `API_KEYS` 匹配的独立连接 Key。
- [ ] 部署和配置文档与新的容器契约一致。
- [ ] Python 3.11 干净环境按开发锁安装并通过全部测试。

当前本机 Docker 客户端可用，但 Docker Desktop Linux engine 未运行，因此容器实跑必须由 CI 或恢复后的本机 Docker daemon 提供最终证据。在该证据产生前，I-001 至 I-003 保持“进行中”。

## 决策边界

不能由工程实现自行关闭的事项继续登记在[技术与产品待决策事项](技术与产品待决策事项.md)。路线图中的“受约束”不是遗漏，而是明确禁止在缺少授权或用户证据时提前作出产品承诺。
