> 复核周期：本轮每项完成后更新

## 背景与基线

管理 API 已有确定性 OpenAPI 快照、生成 TypeScript 类型、44 个运行时成功场景和远程漂移门禁。剩余缺口位于浏览器调用层：`contracts.ts` 手工列举管理路径并把路径映射到请求/响应类型，`api.ts` 再把拼接 URL 交给通用 Fetch 包装器。

当前锁定生成器已经通过隔离探针证明可以为同一快照生成 Fetch client 和逐操作 SDK，且无需新增运行时包。I-040 将把管理控制台从“类型生成、调用手写”推进到“类型与调用同时生成”。

## 目标

消除管理 API 方法、路径、参数和响应之间的手写映射，使 OpenAPI 成为前端传输契约的唯一事实来源，同时保持现有 API Key、首次鉴权探测、401 提示、错误文案和页面截图体验。

## 实施清单

- [x] 1. 扩展确定性生成与漂移门禁
  - 配置并生成 Fetch client、逐操作 SDK 和 TypeScript 类型。
  - 生成 SDK 使用仅返回数据和失败抛错语义，避免界面重复解包传输元数据。
  - 现有 `api:generate` 与 `api:check` 必须覆盖新增产物。

- [x] 2. 建立共享认证、错误与二进制适配
  - 请求拦截器按当前 `localStorage` Key 注入 Bearer 认证，且允许首次验证使用显式候选 Key。
  - 错误拦截器将 HTTP 失败转换为现有 `ApiError`，401 继续派发全局鉴权事件。
  - 页面截图通过生成操作取得 Blob 并创建对象 URL。
  - 单元测试覆盖认证头、显式 Key、JSON/文本错误、401 事件和 PNG Blob。

- [x] 3. 迁移全部管理控制台调用
  - 组件改用语义化生成操作别名和结构化 `path`、`query`、`body` 参数。
  - 删除 `AdminGetPath`、`AdminPostPath`、`AdminPatchPath`、`AdminPutPath`、`AdminDeletePath`、`AdminBlobPath` 及对应条件类型。
  - 仓库扫描证明管理组件不再以字符串 URL 调用通用管理包装器。

- [x] 4. 完成质量门禁与运行验证
  - 通过前端单元测试、类型检查、OpenAPI/生成代码漂移、安全审计和生产构建。
  - 通过完整后端测试与工程策略门禁，证明前端改造未改变后端契约。
  - 在真实本地 API 上完成浏览器首次鉴权、管理数据加载和页面截图冒烟。

- [ ] 5. 收口文档、提交与远程证据
  - 更新契约规范、系统详细设计、接口参考、文档中心和路线图。
  - 补充独立验证记录；本地与远程证据齐备后才把 I-040 标记为完成。
  - 使用项目路径提交并推送，确认远程 CI 全部通过。

## 验收边界

- 本轮只迁移 `/admin` 控制台调用，不改变 API 路径、鉴权策略、审批状态机或业务载荷。
- 非管理端健康、指标、知识文档和聊天调用仍可保留现有专用实现。
- 本轮证明浏览器调用受生成契约约束，不替代真实模型质量评估或人工内容校对。
