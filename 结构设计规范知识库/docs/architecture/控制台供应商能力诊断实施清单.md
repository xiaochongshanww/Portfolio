## 背景

I-041 已让命令行质量验证在评估前识别供应商 401、限流、超时和不可用，但控制台目前只能展示本地 Ready Checks。操作者遇到 AI 校对或问答失败时，仍需通过命令行或后端日志区分服务端 API Key、智谱 Embedding 和 MiMo 聊天故障。

## 目标

在概览页提供一次性、显式触发的供应商能力诊断。结果使用稳定中文标签展示，不回显秘密或模型输出，也不把单次成功长期保存为健康状态。

## 实施清单

- [x] 1. 建立人工触发界面
  - 初始加载、切换标签和全局刷新均不得调用供应商端点。
  - 只有点击“检测”后调用生成 SDK；执行期间阻止重复提交。
  - 控件通过 `title` 说明会发起最小模型调用，不增加常驻说明卡片。

- [x] 2. 建立稳定结果展示
  - 分别展示智谱 Embedding 与 MiMo 聊天的模型、中文状态、延迟和可选 HTTP 状态。
  - 成功、未配置、鉴权失败、限流、超时、不可用、请求失败和响应无效具有一致样式。
  - 传输错误显示在面板内；HTTP 401 继续由共享 client 触发全局鉴权事件。

- [x] 3. 完成自动化验证
  - 组件测试证明挂载不调用、点击只调用一次、成功/失败结果可读。
  - 前端测试、类型检查、生产构建、生成客户端漂移检查和后端完整门禁通过。

- [ ] 4. 完成真实浏览器与远程闭环
  - 在独占本地 API 上确认桌面和移动布局不溢出，失效凭据显示稳定故障状态。
  - 提交项目路径并通过远程十项 CI；验证记录、文档中心和路线图再转为完成。
  - 本地浏览器部分已通过：`1440×900` 与 `390×844` 均无横向溢出，合成失效凭据显示两项鉴权失败/HTTP 401，浏览器控制台无错误；远程 CI 待执行。

## 边界

- 检测会产生两次最小外部请求和可能的供应商费用，因此禁止自动轮询、自动刷新和页面挂载调用。
- 结果只描述检测时刻的调用能力，不进入 `/ready`，不作为持续健康、SLA 或内容质量证据。
- 本轮不新增 Key 编辑、供应商配置或秘密回显能力；凭据仍由部署环境管理。
