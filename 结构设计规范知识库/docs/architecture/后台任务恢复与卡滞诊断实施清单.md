## 目标

让后台任务在正常执行、长时间无进展和 API 进程重启三种场景下都呈现真实、可解释、可审计的状态，不通过危险的自动重跑或线程强杀伪装恢复能力。

## 实施清单

- [x] 任务模型增加执行器实例、心跳、进度和更新时间字段，同时兼容读取既有任务 JSON。
- [x] 任务 JSON 使用互斥、临时文件和原子替换；并发心跳与步骤保存不能产生损坏或状态回退。
- [x] 单线程执行器在任务运行期间低频续写心跳，并在成功或失败收口时停止续租。
- [x] API 启动时将旧执行器遗留的排队/运行任务标记为中断失败，保存稳定错误码、恢复元数据和结构化日志。
- [x] 启动对账幂等，已终态任务和当前执行器任务不被改写；损坏任务文件不导致整个服务无法启动。
- [x] 卡滞判断使用进度时间和可配置阈值，兼容旧任务字段，并输出进度年龄、心跳年龄和诊断原因。
- [x] 管理 API、质量门禁和版本保护使用对账后的真实任务状态，不自动删除仍受其他规则保护的版本。
- [x] 任务页面周期刷新列表与所选日志，显示中文状态、疑似卡滞标记、中断原因和最近进度时间。
- [x] 更新配置参考、接口参考、系统设计、部署/质量运维、可观测性验证记录和文档中心。
- [x] 自动化覆盖原子写、并发心跳、启动恢复幂等、旧格式兼容、卡滞诊断和 API 生命周期。
- [ ] 后端全量测试、前端审计/构建、容器冒烟和远程 CI 全部通过后，将 I-013 标记为完成。

## 非目标

- 本轮不自动续跑中断任务，不提供断点恢复。
- 本轮不强制终止 Python 工作线程，不把超时标记表述为进程已停止。
- 本轮不支持多 API worker、多副本或分布式任务租约。
