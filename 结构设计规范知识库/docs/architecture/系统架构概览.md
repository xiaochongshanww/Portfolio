## 1. 系统目标

系统将结构设计规范 PDF 解析为可追溯知识资产，并通过检索、权威排序、结构化表查询和多模态回答提供问答服务。它不是工程设计计算或审图结论工具；回答必须保留规范、页码、条文或表格来源。

## 2. 组件

```text
浏览器控制台 (Vue 3 + Tailwind) ───────────┐
Open WebUI（环境托管连接 + 启动探测）──────┼─> FastAPI 服务
OpenAI 兼容客户端 ─────────────────────────┘     ├─ 鉴权、就绪诊断和管理任务
                                                 ├─ 常规检索：Chroma + BM25 + 条文/权威排序
                                                 ├─ 结构化表检索：已发布表资产的独立匹配支路
                                                 ├─ 合并证据、生成 RAG 上下文与来源图片
                                                 └─ 生成：MiMo OpenAI-compatible API

PDF -> MinerU 或显式选择 PyMuPDF -> 审计与人工修正 -> manifest / Chroma / 图片资产
                                             └-> 运行知识包 -> 轻量问答环境
运行数据：活动数据库、manifest、结构化表、图片、原始 PDF、审计与任务日志
离线工程入口：配置示例验证、托管 API 质量门禁、知识包校验、完整快照与事务恢复
```

## 3. 运行时边界

- API 入口：`src.app.main:app`，由 FastAPI 创建路由和静态文件挂载。
- 控制台源码：`frontend/`；生产静态资产目录：`frontend/dist`。
- 问答模型：通过 `MIMO_BASE_URL`、`MIMO_MODEL` 和 `MIMO_API_KEY` 配置。
- 配置起点：`.env.example` 由 `scripts/validate_configuration_example.py` 严格校验语法、键集合、空敏感占位和真实 `Settings` 预检；它不携带秘密，也不证明外部供应商可用。
- 常规检索：使用智谱 Embedding 配置；向量结果由 BM25、条文匹配、权威性及表格意图规则重排。
- 结构化表检索不是常规结果的重排步骤：它从已发布的表资产独立匹配行数据，再与常规检索结果共同写入 RAG 上下文。
- 原始 PDF、解析产物、数据库、截图、审计和任务日志属于数据资产，不应混入代码发布包；运行环境通过受控目录或标准知识包安装所需资产。
- 轻量问答环境可以导入预构建运行知识包，不安装 MinerU，也不重复解析和向量化。必需资产是 manifest 与 Chroma 数据库；结构化表、解析图片和原始 PDF 按能力选择。
- Dockerfile 通过多阶段构建将 Vue 控制台打包进运行镜像；Compose 持久化完整 `data/`、数据库、日志和 Open WebUI 状态。容器实跑结论以 CI 和空环境验证记录为准。
- OpenWebUI 的 API 连接由环境变量托管并关闭持久配置覆盖；一次性 `openwebui-preflight` 必须先验证 Key 关系、目标鉴权状态和模型发现，成功后才启动 WebUI。
- `/page-images/{doc}/{page}` 会按请求读取原始 PDF 并渲染页面。没有原始 PDF 时，问答服务不会再提供该动态 URL；若知识包含匹配的解析图片，则仍可通过 `/images/*` 提供静态证据，否则按纯文本证据回答。
- 项目后端名 `mineru` 当前只验证了外部实现 `magic-pdf 1.3.12`。重建在写入候选产物前校验 CLI 实现和版本；MinerU 2.x/3.x 默认拒绝，只有显式试验策略可带未验证标记运行。PyMuPDF 是人工选择的替代后端，不是自动降级链路。详见 [ADR 0010](../adr/0010-PDF解析器采用显式兼容契约.md)。
- 管理任务由单进程、单工作线程串行执行，任务 JSON 原子持久化并分别记录心跳和进度。启动时旧进程活动任务安全收口为中断失败；当前不支持多 worker 抢占、自动续跑或线程强杀。
- 本机完整质量验证可由 `verify_quality.py --manage-api` 创建并回收独占 loopback API；它仍依赖活动知识资产和受控模型凭据，API 可启动不能替代检索与回答质量通过。
- 运行数据灾难恢复采用停机完整快照、独立校验和事务替换；当前不提供在线快照、增量复制、包内加密或外部存储调度。

## 4. 数据与质量流

1. PDF 以规范编号、名称、版本命名后进入受控数据源。
2. Pipeline 解析、生成元素和 chunk，并写入构建 manifest。
3. 规则审计和 AI 仅生成候选；文本、公式和表格修正必须经人工批准才可应用。
4. 复杂表先进入人工结构化队列，发布后执行结构化检索冒烟测试，失败则恢复上一版本或撤下首次版本。
5. 管理端重建先在独立版本目录构建运行资产并执行候选运行时、100 条常规检索和 12 条结构化检索门禁，通过后才提交活动指针；回答级盲测仍由完整发布质量门禁独立执行。详细边界见 [ADR 0005](../adr/0005-候选版本通过预激活门禁后事务化切换.md) 与 [质量运营流程](../operations/知识库维护与质量运营.md)。
6. 历史版本通过限时清理计划回收；活动、运行中、人工固定、近期回滚和最短保护期版本不可删除，执行前再次校验指纹并写审计记录。详细边界见 [ADR 0006](../adr/0006-知识版本采用计划确认与受保护清理.md)。

## 5. 关键架构决定

- 规范正文表格和正文条文优先于条文说明，避免“语义更像”压过“权威更高”。
- 结构化表不由 AI 自动发布，防止数值、单位、合并单元格和适用条件失真。
- 页面截图可通过 `/images/*` 和 `/page-images/{doc}/{page}` 提供；后者会按需从原始 PDF 渲染。两类资源按来源声明为公开、受保护或禁用；受保护引用使用 API Key 或短期 HMAC 签名，未知来源默认收紧。详见 [ADR 0003](../adr/0003-来源资源采用分级访问与短期签名.md)。
- 构建与问答通过版本化运行知识包解耦；原始 PDF 默认排除，导入前校验文件大小、SHA-256、路径安全和兼容性。详见 [ADR 0001](../adr/0001-运行知识包解耦构建与问答.md)。
- 知识包 v2 携带质量门禁与豁免证据；失败导出默认阻断，例外必须记录责任人和原因。详见 [ADR 0002](../adr/0002-知识包导出强制质量门禁.md)。
- 知识包 v3 在 v2 质量证据上增加强制来源策略文件，安装后不会丢失图片展示边界。
- 知识包 v4 把兼容性、能力和质量元数据绑定到包标识，并要求目标环境通过隔离 Chroma 运行探针；当前受控矩阵见 [ADR 0004](../adr/0004-知识包采用受控兼容矩阵与运行探针.md)。
- 管理端重建把数据库、解析文本和图片作为同一候选版本，只有预激活检索门禁通过后才以 `active_db.json` 为提交点切换；失败恢复旧版本，回答级盲测不被错误包含在此门禁中。详见 [ADR 0005](../adr/0005-候选版本通过预激活门禁后事务化切换.md)。
- 版本生命周期采用“清单与保护集 → 持久化计划 → 人工确认 → 执行前复核 → 隔离删除 → 审计报告”，不提供任意路径删除接口。详见 [ADR 0006](../adr/0006-知识版本采用计划确认与受保护清理.md)。
- 后台任务采用“原子状态记录 + 执行器心跳 + 进度时间 + 启动对账”恢复真实状态；卡滞只做诊断，进程重启不自动续跑。详见 [ADR 0007](../adr/0007-后台任务采用租约诊断与启动中断恢复.md)。
- manifest、活动指针、版本、任务、审计和可选资产统一从 `DATA_DIR` 派生；知识包导入和 API 冷启动必须指向同一数据根，`DB_DIR` 仅保留为无活动指针时的旧库回退。详见 [ADR 0008](../adr/0008-运行数据根采用显式单一配置.md)。
- 运行知识恢复采用受控知识包整包重部署和同一组运行断言，不以手工修改活动指针作为回退方案。详见 [ADR 0009](../adr/0009-运行知识恢复采用受控知识包重部署.md)。
- PDF 知识生产使用独立解析器哈希锁和显式兼容矩阵；运行镜像不携带重型解析器。构建 manifest 与单文档产物索引记录实际 CLI 路径、实现、版本、策略和兼容状态。详见 [ADR 0010](../adr/0010-PDF解析器采用显式兼容契约.md)。
- 质量验证采用单一显式目标并区分执行失败与质量失败；评估资产内置，凭据按环境变量、受控文件和显式无 Key 模式解析。详见 [ADR 0011](../adr/0011-质量验证采用显式目标与执行失败语义.md) 与 [ADR 0012](../adr/0012-质量验证采用内置评估资产与显式凭据.md)。
- 运行数据恢复采用离线完整快照与事务替换，目标冲突、清单漂移和安装失败均失败关闭。详见 [ADR 0013](../adr/0013-运行数据采用离线完整快照与事务恢复.md)。
- OpenWebUI 连接由环境托管并以启动探测阻断错配配置；本机无人值守质量验证只管理自己创建的 loopback API 进程。详见 [ADR 0014](../adr/0014-OpenWebUI连接采用环境托管与启动探测.md) 与 [ADR 0015](../adr/0015-无人值守质量验证采用受控本地API生命周期.md)。
- 可提交质量证据采用“脱敏当前快照 + 不可变历史归档 + 确定性索引”；写入先归档与索引、后发布当前状态，CI 验证指纹和一致性。该机制不提供外部签名信任。详见 [ADR 0016](../adr/0016-脱敏质量证据采用不可变历史归档.md)。
- 完整质量验证前可对既有或临时托管 API 执行无副作用预检，独立确认就绪、鉴权和进程回收，不覆盖质量报告，也不把可执行性等同于质量通过。详见 [ADR 0017](../adr/0017-质量验证采用无副作用前置条件预检.md)。
- 模型供应商、检索策略和内容来源变化从本规则生效后必须记录 ADR 或发布记录，并执行相应评估；既有历史决定尚未补录为 ADR。
