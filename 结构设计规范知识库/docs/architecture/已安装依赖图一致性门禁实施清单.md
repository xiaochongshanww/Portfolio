## 背景

三份精确哈希锁可以证明解析结果可复现，但不能单独证明已安装环境中每个包声明的版本约束都得到满足。pip 在已有环境或复杂依赖共存时可能完成安装后再报告冲突；I-044 又让开发环境同时安装 HTTPX 与 HTTPX2，因此需要把安装结果本身变成显式工程门禁。

## 目标

每个由项目控制的 Python 安装环境在进入测试、产包或镜像复制前执行 `python -m pip check`。检查失败必须立即终止任务，不允许依赖后续测试间接发现冲突，也不能在已移除 pip 的最终运行镜像中临时恢复安装工具。

## 边界

- `pip check` 不替代锁重建、哈希校验、安全审计或应用测试。
- PDF 解析锁体量大且不在常规 CI 安装，本轮不伪造解析器安装验证；实际知识生产环境仍由构建自检和解析器兼容契约负责。
- 最终运行镜像继续不包含 pip、setuptools 和 wheel；检查在 builder 中完成。
