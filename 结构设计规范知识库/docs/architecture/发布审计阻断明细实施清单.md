> 复核周期：发布门禁或来源治理字段变化时

## 目标

发布审计不能只告诉操作人员“有多少项阻断”，还必须保留逐来源、逐字段的可执行明细；明细只改善诊断，不改变门禁结果。

## 实施清单

- [x] 1. 为来源审计检查增加结构化 `items` 明细字段。
- [x] 2. 在外部和内部 profile 下保留来源阻断明细；台账结构错误也保留校验错误。
- [x] 3. 在 Markdown 审计报告中增加“来源资格明细”章节。
- [x] 4. 增加 JSON 保留和 Markdown 渲染测试。
- [x] 5. 更新路线图、文档中心、发布检查单、运营手册、ADR 和验证记录。

## 边界

- 明细只能来自机器校验结果，不生成法律结论，不替代内容治理负责人或法律复核。
- 默认 `external` 和显式 `internal-research` 的资格判定逻辑不因展示明细而改变。
- 报告仍不得包含 API Key、供应商响应正文或受限原文。
