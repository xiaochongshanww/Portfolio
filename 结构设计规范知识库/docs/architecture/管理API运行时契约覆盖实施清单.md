## 背景与基线

I-038 已为 `/admin` 的 43 个 JSON 操作和 1 个 PNG 操作建立响应模型、OpenAPI 快照与前端生成类型，但现有测试主要证明“契约已声明”。基线审计发现，只有少量管理端操作通过 `TestClient` 执行了 HTTP 成功路径；多数操作尚未在测试中穿过 FastAPI 的真实路由匹配、请求解析、响应模型校验和序列化链路。

这个缺口已经产生过实际故障：`/admin/active-db` 的旧活动指针含空路径时，静态 OpenAPI 正常，但运行时响应校验返回 500。单纯增加响应模型不能证明所有实现输出都符合模型。

## 目标

建立由 OpenAPI 操作清单驱动的运行时契约门禁。每个管理操作必须有一个可重复、无外部模型调用、无生产数据副作用的 ASGI 成功路径用例；新增或删除路由时，清单与测试覆盖必须同步变化。

## 实施清单

- [x] 1. 建立权威操作清单与覆盖不变量
  - 从应用 OpenAPI 动态取得方法、模板路径、operation id 和成功媒体类型。
  - 测试用例使用 operation id 登记，拒绝遗漏、重复、未知或只覆盖错误响应的条目。
  - JSON 与 PNG 操作分别验证媒体类型和成功载荷。

- [x] 2. 建立隔离的管理 API 运行时场景
  - 使用临时目录、确定性代表数据和受控替身，不读取或修改真实运行资产。
  - 禁止调用外部模型、MinerU、网络服务和后台工作线程。
  - 同时覆盖空状态与代表性非空状态，避免只验证所有列表为空的弱场景。

- [x] 3. 覆盖全部 44 个 HTTP 成功路径
  - 通过 `TestClient` 执行真实路由、请求模型、响应模型和序列化链路。
  - 43 个 JSON 响应必须能由对应 OpenAPI schema 识别，并满足稳定顶层字段。
  - 页面截图响应必须返回 `image/png` 和有效 PNG 签名字节。

- [x] 4. 建立故障矩阵和防回退门禁
  - 注入缺失必需字段、额外未声明字段和错误媒体类型，证明运行时会失败关闭。
  - 新增管理操作但未登记运行时场景时测试必须失败。
  - 场景登记了不存在操作、重复 operation id 或非 2xx 成功结果时测试必须失败。

- [x] 5. 接入工程质量门禁并同步文档
  - 运行 Ruff、全量后端测试、OpenAPI 漂移检查和现有前端门禁。
  - 更新系统详细设计、接口参考、文档中心和持续迭代路线图。
  - 补充 ADR 与验证记录；只有本地和远程证据齐备后将 I-039 标记完成。
  - 本地完整门禁与远程 CI #103 十项任务均已通过，生效文档和验证记录已同步。

## 验收边界

- 本轮证明管理 API 的实现输出在隔离代表场景中符合已发布传输契约，不证明生产数据的全部组合均已穷举。
- 本轮不调用真实模型，不改变模型质量结论，也不替代发布前的 100 条检索、12 条结构化和 24 条回答评估。
- 本轮不改变 API 路径、鉴权策略、业务审批状态机或产品交付形式。
