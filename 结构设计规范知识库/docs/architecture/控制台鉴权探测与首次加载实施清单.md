> 状态：实施中  
> 维护角色：前端与运行平台负责人  
> 文档更新：2026-08-08  
> 关联路线图：I-014  
> 完成规则：每项必须有代码、自动化测试或运行验证证据后才能勾选

## 问题定义

当前控制台根据浏览器 `localStorage` 中是否存在 API Key 推断后端是否启用鉴权。该推断会把“未保存 Key”和“后端要求 Key”混为一谈，导致关闭 `API_AUTH_ENABLED` 的本地或受控环境仍被登录遮罩阻断。无效 Key 还会在验证成功前写入浏览器，后续刷新会反复失败。

## 目标行为

1. 控制台启动时先请求一个受保护且轻量的后端端点，以真实 HTTP 结果判断访问状态。
2. 后端返回 2xx 时直接加载控制台，无论浏览器是否保存 Key。
3. 只有后端返回 401 时才显示 API Key 验证界面。
4. 网络错误和 5xx 显示可重试的连接失败状态，不伪装成鉴权失败。
5. 候选 Key 仅在后端验证成功后写入 `localStorage`；失败值不得覆盖原有效 Key。
6. 手工刷新和运行中出现的 401 继续触发统一验证界面。

## 实施清单

### 前端状态与 API 客户端

- [ ] 将首次状态从“按本地 Key 猜测”改为“正在探测后端”。
- [ ] API 客户端支持使用候选 Key 发起一次性验证，不提前持久化。
- [ ] 401 事件携带机器可读状态和用户可读错误信息。
- [ ] 区分 `checking`、`ready`、`auth-required`、`unavailable` 四种首次加载状态。
- [ ] 刷新操作先探测访问权限，避免一次无效 Key 触发多路受保护请求。
- [ ] 为网络故障提供明确且可重试的页面状态。

### 自动化验证

- [ ] 前端引入可重复执行的组件测试命令并纳入 CI。
- [ ] 覆盖关闭鉴权且无本地 Key 时可直接进入。
- [ ] 覆盖开启鉴权且无 Key 时只显示验证界面、不并发加载受保护资源。
- [ ] 覆盖候选 Key 成功后持久化并完成数据加载。
- [ ] 覆盖候选 Key 失败时不持久化失败值。
- [ ] 覆盖后端不可达时显示连接失败而非 API Key 弹窗。

### 文档与运行验收

- [ ] 配置和部署文档说明控制台的鉴权探测行为。
- [ ] 桌面与移动视口验证加载、401、重试和成功进入流程。
- [ ] 后端全量测试、前端测试、安全审计、生产构建和容器门禁通过。
- [ ] 远程 CI 通过后，将路线图 I-014 和本清单状态改为已完成。

## 非目标

- 本轮不引入用户账户、角色、租户或服务端会话。
- 本轮不改变 API Key 的服务端校验规则和受保护路由范围。
- 本轮不把关闭鉴权解释为适合公网暴露；部署安全边界继续以配置参考和部署手册为准。
