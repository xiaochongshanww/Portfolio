## 问题定义

运行知识包已经可以从空数据目录冷启动 API，但当前证据只覆盖首次导入。成功升级后的持久回退仍依赖人工恢复多个目录和指针，尚未证明上一版完整知识包能够在同一数据根恢复数据库、manifest、全局资产和 API 运行身份。

## 目标行为

1. 同一资产路径、不同内容和不同数据版本的知识包能够按 A→B→A 顺序受控部署。
2. 每次切换后 API 都读取预期包的数据库、manifest、文档清单和数据版本。
3. 回退恢复包内结构化表、图片与来源策略，不形成新旧版本拼接。
4. 覆盖导入中途失败时，活动版本和所有已存在目标保持不变。
5. 探针跨 Windows/Linux 执行，不调用真实模型、不依赖真实密钥或受限资料。

## 实施清单

### 恢复契约

- [ ] ADR 明确完整知识包、维护窗口、受控覆盖和禁止手工改指针的边界。
- [ ] 部署手册给出升级前、升级、验证、回退和灾难恢复的分层步骤。
- [ ] 发布检查单要求记录当前包、上一版包、校验值和回退演练证据。
- [ ] 文档明确知识包未覆盖的原始 PDF、任务、审计和人工修正记录。

### 合成资产与运行探针

- [ ] 跨平台样包生成器支持确定性内容变体，并保持资产路径一致。
- [ ] 冷启动验证器可复用“已导入数据根启动 API”的运行断言。
- [ ] 新增 A→B→A 恢复探针，核对包标识、数据版本、计数、数据库路径和全局资产。
- [ ] 每次 API 子进程在成功和失败路径都可靠退出。
- [ ] 探针结果显式记录外部模型调用数为零。

### 事务与自动化

- [ ] 单元测试覆盖同名资产默认拒绝和显式覆盖。
- [ ] 故障注入覆盖版本目录、全局资产、根 manifest 与活动指针的完整恢复。
- [ ] 交付契约测试要求 CI 执行恢复探针。
- [ ] Windows 和 Linux 包生产任务均执行本机 A→B→A 恢复探针。
- [ ] 现有 Windows→Linux 与 Linux→Windows 冷启动兼容任务保持通过。

### 发布证据

- [ ] 后端全量测试、前端测试、类型检查、安全审计、构建、配置和文档门禁全部通过。
- [ ] 生成本地验证记录，说明断言、故障注入和能力边界。
- [ ] 远程 CI 全部通过并记录任务链接。
- [ ] 远程证据通过后才将 I-016 与本清单标记为已完成。

## 非目标

- 不实现零停机热升级、双槽流量切换或多副本编排。
- 不把运行知识包扩大为原始资料、任务、审计和人工审批证据的完整灾备格式。
- 不改变知识包内容授权、签名信任根或对外分发决定。
- 不调用问答模型，因此不证明生成答案质量或模型供应商可用性。
