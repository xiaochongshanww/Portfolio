> 复核周期：审计检查项或整改责任边界变化时

## 目标

在已有阻断明细和整改行动之上，把所有未通过检查汇总成稳定的 `closure` 对象和可读的“收口矩阵”。该矩阵只组织证据收集工作，不生成、批准或替代任何外部权利、用户试用或产品决策证据。

## 实施清单

- [x] 1. 为审计 JSON 增加 `closure.ready`、计数、阻断/提醒检查编号和逐项收口条目。
- [x] 2. 每个收口条目保留检查状态、阻断级别、说明、责任角色、整改动作和验证条件。
- [x] 3. 在 Markdown 报告中增加“收口矩阵”，便于按责任角色和验证入口执行人工补证。
- [x] 4. 增加 JSON 汇总和 Markdown 表格测试，并验证 `ready`、`blockers`、`warnings` 原有语义不变。
- [x] 5. 同步路线图、文档中心、发布检查单和 ADR，明确该能力不等于发布就绪。

## 使用边界

- 收口矩阵是证据交接清单，不是自动执行器。
- 只有原始检查器、真实权利材料、真实试用记录或真实精排报告通过后，阻断项才会关闭。
- 不得通过修改 `closure`、审计 JSON 或路线图文本绕过发布门禁。
