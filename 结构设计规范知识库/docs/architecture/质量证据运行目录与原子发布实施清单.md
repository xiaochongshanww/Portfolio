## 背景

I-035 已确保发布门禁拒绝跨运行、跨配置报告，但详细报告仍逐个覆盖 `latest`。本轮把“识别混合证据”继续推进为“先形成完整运行证据包，再原子发布最新状态”，同时保留旧接口兼容。

## 实施清单

- [x] 1. 固化运行目录与原子发布决策
  - 接受 [ADR 0026](../adr/0026-完整质量证据采用运行目录与原子指针发布.md)。
  - 定义运行目录、必需产物、清单、最新指针、兼容副本和敏感数据边界。
  - 明确预检无副作用、部分执行失败关闭、单项评估不切换完整运行指针。

- [x] 2. 建立共享质量报告存储契约
  - 提供跨平台原子 JSON、文本和字节写入，失败时清理临时文件并保留旧目标。
  - 校验运行 ID、运行目录、产物名和相对路径，阻断目录穿越。
  - 生成并验证包含 SHA-256、大小和完整产物集合的运行清单。

- [x] 3. 贯通完整验证编排与后台评估
  - 本地、API 常规评估、结构化评估和回答盲测统一写入当前运行目录。
  - 跳过或前置失败写入同运行失败占位报告，不复用历史 `latest`。
  - 门禁读取显式运行路径，总报告完成后才发布兼容副本与原子指针。

- [x] 4. 升级读取端与脱敏快照
  - 管理 API 和评估状态优先读取原子指针，旧环境无指针时回退兼容文件。
  - 质量门禁把缺失、损坏、非对象报告转为阻断检查，不抛出未处理异常。
  - 脱敏快照支持运行目录相对路径，校验指针、清单哈希与路径隔离，兼容历史固定路径。

- [x] 5. 完成故障矩阵和工程验证
  - 覆盖原子替换失败、损坏 JSON、缺失产物、清单篡改、指针穿越、部分运行和旧格式回退。
  - 通过 Ruff、全量后端、前端、依赖锁、配置、Compose、容器与文档门禁。
  - 在无外部模型凭据环境生成一套新契约失败证据，确认状态仍为 `not_passed`。

- [x] 6. 同步生效文档并完成远程验证
  - 更新架构、系统卡、质量运营、接口参考、发布检查单、文档中心和路线图。
  - 提交实现并取得远程十任务 CI 证据后，才把本清单标记为工程完成。

## 验收边界

- 工程验收证明报告持久化、完整性和发布切换可靠，不证明检索或回答内容质量通过。
- 运行目录是受控本地审计资产，不改变 D-001 的内容分发限制，也不应提交 Git。
- 原子指针不是签名；具备主机写权限的主体仍在当前信任边界内。
- 本轮不自动删除历史运行目录，不改变质量阈值、模型、精排默认开关或评估集内容。
