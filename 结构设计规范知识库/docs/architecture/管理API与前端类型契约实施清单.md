## 基线

- `/admin` 共 44 个操作，成功响应 schema 为空的操作为 44 个；其中 43 个返回 JSON，1 个返回 PNG。
- `frontend/src/api.ts` 的 JSON 请求函数默认返回 `any`，主要控制台组件广泛依赖动态响应。
- 当前没有确定性 OpenAPI 快照、前端生成类型或契约漂移门禁。

## 实施清单

- [x] 1. 建立管理 API 响应模型
  - 覆盖状态、文档、任务、评估、质量、版本、校对、结构化和元素接口。
  - PNG 页面端点声明准确响应媒体类型。
  - 开放 JSON 只保留在明确的 manifest、报告、草稿和元素字段中。

- [x] 2. 建立确定性 OpenAPI 快照
  - 导出过程不启动服务、不访问模型、不修改运行数据。
  - 规范化 JSON 顺序与换行，支持写入和只读校验模式。
  - 测试拒绝空 JSON 成功响应、重复 operation id 和快照漂移。

- [x] 3. 生成并消费 TypeScript 契约
  - 精确锁定 OpenAPI TypeScript 生成器。
  - 请求函数移除默认 `any`，调用点使用生成的响应和请求正文类型。
  - 生成文件带来源说明，不允许人工编辑。

- [x] 4. 接入本地与远程门禁
  - 后端测试校验 OpenAPI 快照。
  - 前端任务在类型检查前重生成并验证无差异。
  - Windows/Linux 命令均不依赖 shell 专属语法。

- [ ] 5. 完成故障矩阵与全量验证
  - 覆盖缺失响应模型、空 schema、生成文件漂移、后端缺失必需字段和前端错误字段访问。
  - 通过 Ruff、全量后端、前端测试/类型检查/构建、依赖锁、文档和远程十任务 CI。
  - 本地已覆盖严格/开放响应边界、必需字段、显式 `any` 回归、知识包冷启动和完整工程门禁；远程十任务 CI 待补。

- [ ] 6. 同步生效文档并关闭迭代
  - 更新架构、接口参考、文档中心、路线图和验证记录。
  - 远程证据完成前不把 I-038 标记为工程完成。

## 验收边界

- 本轮证明管理端传输契约可生成、可消费、可阻止漂移，不证明真实模型回答质量通过。
- 本轮不改变 API 路径、鉴权策略、业务状态机或对外产品承诺。
