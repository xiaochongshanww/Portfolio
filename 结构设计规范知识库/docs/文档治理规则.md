# 文档治理规则

> 状态：生效  
> 维护角色：工程负责人  
> 文档更新：2026-08-20
> 流程核对：2026-08-20，链接、元数据、可达性、完成状态和来源台账规则已核对
> 完整运行验证：待本轮完整门禁完成后回填
> 验证证据：[生效文档状态一致性验证记录](releases/生效文档状态一致性验证记录.md)、`tests/test_documentation.py`、`tests/test_configuration_example.py`、`scripts/validate_configuration_example.py`、`scripts/validate_source_register.py`
> 复核周期：每次发布

## 1. 文档类型

项目采用四类面向读者的文档：

- 教程：帮助首次使用者完成一项完整任务。
- 操作指南：解决部署、导入、校对、发布等明确工作。
- 参考：接口、配置、数据模型、错误码和指标，要求精确且可检索。
- 说明：解释架构、权衡、风险和产品边界。

产品、治理和运行证据可使用独立目录，但必须从 `docs/文档中心.md` 可达。

## 2. 事实来源优先级

1. 可执行配置、代码、数据库 schema、OpenAPI、自动化测试和发布产物。
2. 已批准的 ADR、发布记录、来源登记和风险登记。
3. 当前活文档。
4. 阶段计划、交接材料和演进记录。

出现冲突时，先核对前两层；修正文档并在提交说明中注明。不能用文字绕过运行时行为。

## 3. 文档元数据

每个活文档开头至少包含：

```text
状态：草案 | 生效 | 模板 | 归档
维护角色：产品 | 工程 | 内容治理 | 质量运营
文档更新：YYYY-MM-DD
代码/流程核对：YYYY-MM-DD 或不适用
完整运行验证：YYYY-MM-DD、未执行或不适用
验证证据：报告、提交、命令或受控记录的链接
复核周期：每次发布 | 每月 | 每季度
```

敏感材料还要标明访问级别：公开、内部或受限。

## 4. 变更触发器

| 发生变化 | 必须更新的文档或证据 |
| --- | --- |
| API、鉴权、错误结构 | OpenAPI、API 参考、迁移说明 |
| 模型、提示词、检索或权威排序 | RAG 系统卡、评估结果、ADR 或变更记录 |
| 新 PDF 或新数据来源 | 来源登记、解析记录、评估覆盖、内容状态 |
| 解析修正或复杂表发布 | 校对记录、版本快照、质量门禁结果 |
| 部署、环境变量、域名或供应商 | 部署运行手册、配置参考、风险登记 |
| 生产事故或质量回归 | 事故复盘、运行手册、发布检查单 |
| 公开试用、收费或数据处理方式变化 | 内容政策、隐私政策、服务条款和免责声明 |

## 5. 复核与归档

- 发布前：检查所有“生效”文档是否仍符合代码和运行环境。
- 每月：复核运行、风险、供应商和已知限制。
- 每季度：复核内容来源权利状态、隐私和对外服务边界。
- 已完成计划移入逻辑归档，不删除；在 `docs/archive/历史文档说明.md` 标出其历史用途。

## 6. 文档质量门槛

文档应通过以下最小检查：内部链接有效、命令有工作目录和前置条件、配置不包含密钥、事实有来源、已知限制明确、完成状态可验证。

当前 `scripts/verify_quality.py` 已覆盖后端测试、前端构建、检索/回答评估和质量门禁；`tests/test_documentation.py` 自动检查本地 Markdown 链接、文档中心可达性、根目录文档白名单、治理元数据和完成状态一致性。完成状态检查从持续迭代路线图动态解析最新完成项，要求文档中心摘要同步，并拒绝关联工程已完成迭代的 ADR 继续保留“实施中”“待实施”、工程工作待完成或待回填完整验证元数据；“工程完成，外部证据待补/待复验”仍视为工程完成，但不会把外部证据缺口本身判为冲突。检查不覆盖模板、历史资料和治理草案。`scripts/validate_configuration_example.py` 与 `tests/test_configuration_example.py` 负责 `.env.example` 的语法、重复键、敏感占位和应用预检，CI 容器任务再使用同一示例执行 Compose 渲染。`scripts/validate_source_register.py` 与 `tests/test_source_register.py` 负责来源台账字段、运行元数据一一映射、原始文件 SHA-256 和 B/C 级对外权限一致性；默认命令只验证结构，`--require-release-eligible` 才检查对外资格。`python scripts/validate_ci_actions.py` 与 `tests/test_ci_actions.py` 负责外部 action 的不可变引用、版本注释和最低运行时代际，Dependabot 只提出更新而不自动合并。验证器不会检查真实 Key、供应商可达性、上游供应链绝对可信、授权凭证真实性或生产环境适配，这些仍须按部署、内容治理和发布流程核对。
