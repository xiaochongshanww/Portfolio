## 1. 适用范围

本文档覆盖宿主机和 Docker Compose 运行方式。Dockerfile 已使用多阶段构建生成并复制 `frontend/dist`，但当前工作环境的 Docker engine 未运行，镜像构建、容器健康检查和静态控制台检查仍需由 CI 提供最终证据。在 CI 首次通过前，Docker Compose 仍视为待验证交付方式。

## 2. 前置条件

- Python 3.11 运行环境。
- Node.js 与 npm，用于构建 Vue 控制台。
- 使用容器方式时需要 Docker Engine 与 Docker Compose v2。
- 以下两种数据准备方式任选其一：在构建环境持有 PDF、MinerU（或显式选择 PyMuPDF）和 Embedding 能力并完成重建；或在轻量运行环境导入已验证的运行知识包。导入运行包不需要 MinerU。
- `ZHIPUAI_API_KEY` 和 `MIMO_API_KEY`。不将真实密钥提交到 Git。

## 3. 本地启动

```powershell
Copy-Item .env.example .env
# 在 .env 中填写 ZHIPUAI_API_KEY、MIMO_API_KEY 和生产所需的 API_KEYS。

python -m pip install -r requirements.txt
Push-Location frontend
npm install
npm run build
Pop-Location

python -m uvicorn src.app.main:app --host 127.0.0.1 --port 8000
```

校验：

```powershell
Invoke-WebRequest http://127.0.0.1:8000/health
Invoke-WebRequest http://127.0.0.1:8000/ready
```

根路径会重定向到 `/static/index.html`。若未构建 `frontend/dist`，控制台不会被挂载。

## 4. Docker Compose 启动

Docker 镜像会在独立 Node 构建阶段执行 `npm ci` 和生产构建，最终镜像只复制 `frontend/dist`，不携带 Node.js 工具链。运行时镜像还包含评估集、规范元数据和动态 PDF 页面渲染所需的 PyMuPDF。

Compose 文件显式使用项目名 `structural-spec-kb`，避免中文目录名无法自动转换为合法 Compose 项目名。

```powershell
Copy-Item .env.example .env
# 填写模型密钥；启用鉴权时同时配置 API_KEYS 和 OPENWEBUI_API_KEY。
docker compose config -q
docker compose up --build -d
docker compose ps
Invoke-WebRequest http://127.0.0.1:8000/health
Invoke-WebRequest http://127.0.0.1:8000/static/index.html
```

Compose 将整个 `./data` 挂载到 `/app/data`，将 `./db` 和 `./logs` 分别持久化，并用命名卷保存 Open WebUI 内部状态。这样可覆盖 manifest、活动数据库指针、数据库版本、结构化表、校对记录和评估证据。该挂载也会把 `data/raw` 提供给 API 进程；只要目录中存在原始 PDF，公开的 `/page-images/*` 就可能读取它，因此不得把包含受限扫描件的该拓扑直接暴露到公网。

Open WebUI 使用 `http://api:8000/v1` 作为 OpenAI-compatible 基址。若 `API_AUTH_ENABLED=true`，`OPENWEBUI_API_KEY` 必须等于 `API_KEYS` 中的一个有效 Key；Open WebUI 已经初始化过连接时，环境变量变化可能需要在其管理界面同步更新。

## 5. 生产配置最低要求

- 设置 `API_AUTH_ENABLED=true` 和强随机 `API_KEYS`。
- 为 Open WebUI 设置单独的 `OPENWEBUI_API_KEY`，并将同一值加入 `API_KEYS`。
- 将 `CORS_ORIGINS` 限制为明确的控制台域名。
- 将 `PUBLIC_ASSET_BASE_URL` 配置为外部可访问的图片资源前缀；未设置时使用相对 `/images`。
- 当前 `/images/*`、`/page-images/{doc}/{page}` 与 `/static/*` 不受 API Key 路由规则保护。`/page-images/{doc}/{page}` 会读取原始 PDF 按需渲染；修复受控资源鉴权前，只能托管确认允许公开的图片、原始 PDF 和静态内容，不得以此方式暴露受限扫描页或用户文件。
- 通过反向代理终止 TLS；不要把开发端口直接暴露到公网。
- 生产运行必须使用独立的 `DB_DIR`、`IMG_DIR`、日志和备份目录。
- 检查模型供应商的地区、数据保留和密钥管理约束。

## 6. 运行知识包部署

知识资产维护者在已完成校对和质量验证的构建环境导出：

```powershell
# 默认不包含原始 PDF
python -m src.pipeline package-export --output dist\knowledge-runtime.zip

# 只在来源权利和目标用途允许时显式包含原始 PDF
python -m src.pipeline package-export --output dist\knowledge-runtime-with-pdf.zip --include-source-pdfs
```

目标环境应先做只读校验，再导入默认 `data/` 目录：

```powershell
python -m src.pipeline package-validate --package dist\knowledge-runtime.zip
python -m src.pipeline package-import --package dist\knowledge-runtime.zip
python -m uvicorn src.app.main:app --host 127.0.0.1 --port 8000
```

导入会把数据库安装为 `data/db_versions/import-<package_id>/`，复制包内结构化表和图片，并在最后更新 `data/active_db.json` 与 `data/manifest.json`。API 已运行时必须在导入后重启；当前命令不会热重载正在运行的进程。

操作约束：

1. 同一版本已安装或同名资产内容不同时，导入默认失败，不覆盖现有数据。
2. `--replace` 会覆盖冲突目标，只能在备份和确认包来源后使用。
3. `--no-activate` 只安装和检查，不切换活动数据库。
4. `--data-dir` 主要用于预安装、测试或项目数据目录迁移；当前 API 默认读取仓库 `data/active_db.json`，自定义目录不会自动改变在线进程的数据根。
5. 原始 PDF 默认不在包内；此时动态 `/page-images/*` 不可用，但已有解析图片仍可引用，纯文本问答不受影响。
6. 校验通过证明包未损坏，不证明内容获得传播、展示或商业使用授权。

## 7. 构建、发布与回退

1. 执行 Dry Run，确认源文件和解析后端。
2. 重建知识库，完成审计和人工校对。
3. 按 [质量运营流程](知识库维护与质量运营.md) 运行质量门禁。当前重建会先切换活动数据库，质量门禁失败时必须人工暂停对外发布并执行回退。
4. 执行 [发布检查单](../releases/发布检查单.md)。
5. 保留当前 manifest、结构化表版本、活动数据库、原始 PDF 和图片资产备份；失败时先恢复这些版本与资产，再恢复服务。

## 8. 常见故障初查

| 现象 | 首先检查 |
| --- | --- |
| 控制台空白或 404 | `frontend/dist` 是否存在；`STATIC_DIR` 是否指向该目录 |
| Open WebUI 无模型或返回 401 | 基址是否为 `http://api:8000/v1`；`OPENWEBUI_API_KEY` 是否属于 `API_KEYS`；既有 Open WebUI 持久化连接是否仍保存旧配置 |
| `401` | 是否开启 API 鉴权；请求是否传递 `Authorization: Bearer <key>` 或 `X-API-Key` |
| `/ready` 失败 | manifest、Chroma、Embedding/MiMo 密钥与 BM25 初始化状态 |
| 图片不显示 | `IMG_DIR`、`IMG_BASE_URL`、`PUBLIC_ASSET_BASE_URL`、原始 PDF 数据目录和反向代理路径 |
| 知识包导入失败 | 先运行 `package-validate`；检查包版本已安装、同名资产冲突、磁盘空间和 Chroma 兼容警告 |
| 回答无依据或检索异常 | 活动数据库、manifest 版本、评估报告是否过期；不要直接把模型回答当作诊断证据 |

发生影响用户、内容权利或数据安全的故障时，暂停受影响入口、保全日志和版本信息，并按 Runbook 模板创建事件记录。
