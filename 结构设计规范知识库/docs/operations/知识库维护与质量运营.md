# 知识库维护与质量运营

> 状态：生效  
> 维护角色：质量运营负责人  
> 文档更新：2026-08-08  
> 流程核对：2026-08-08  
> 完整运行验证：2026-07-05  
> 验证证据：`scripts/verify_quality.py`、`data/audit/reports/` 与发布检查记录  
> 复核周期：每次发布

## 标准工作流

1. 导入或更新 PDF，运行 Dry Run 和重建。重建先隔离生成候选运行资产，并在通过候选运行时、常规检索和结构化检索门禁后才激活；门禁报告保存在对应版本的 `quality/` 目录。
2. 在校对工作台审核文本、公式和普通表格修正。
3. 在结构化队列处理复杂表：
   - 确认跨页分组；
   - 生成或批量生成 AI 建议；
   - 对照页面截图检查每个数值、单位、条件和表注；
   - 应用建议后保存并校验；
   - 发布，等待结构化检索冒烟测试通过。
4. 运行常规评估和结构化专项评估。
5. 在概览的“质量运营”区域确认失败任务、待处理逻辑表和评估失败均已处置。

## 自动化边界

- AI 建议只用于减少录入工作，不会自动应用或发布。
- 发布前必须通过结构校验；发布后必须通过真实结构化检索冒烟测试。
- 冒烟失败会自动恢复上一版本，首次发布则自动撤下文件。
- 批量任务中单项失败不会阻断其他任务，失败原因保存在任务日志。

## 无人值守质量验证

在 API 已按完整环境变量启动的前提下，运行：

```powershell
python scripts/verify_quality.py
```

API 使用非默认端口或路径前缀时必须显式指定同一个目标：

```powershell
python scripts/verify_quality.py --api-base http://127.0.0.1:8017
```

验证器先请求该目标的 `/ready`。未就绪时报告列出 `reasons` 并跳过依赖 API 的评估，不会提交注定失败的后台任务。常规与结构化评估通过目标 API 的管理任务执行；回答级盲测由验证器直接请求同一目标的问答与图片接口，因此 `--api-base` 不会在后台退回默认端口。控制台发起回答盲测时则使用服务端 `ANSWER_EVALUATION_API_BASE`，自定义 API 监听地址的部署必须同步设置该变量。

该命令依次执行：

1. 完整后端测试；
2. Vue 前端生产构建；
3. 100 条常规检索评估；
4. 12 条结构化专项评估；
5. 24 条回答级盲测与引用资源 HTTP 验证；
6. 活动版本 manifest、运行集合数量、必需产物、高风险审计、报告溯源和任务状态门禁。

报告写入 `data/audit/reports/`：

- `verification_latest.md/json`：完整执行结果；
- `quality_gate_latest.md/json`：自动门禁结果；
- `evaluation_latest.md/json`：常规评估；
- `evaluation_structured_latest.md/json`：结构化专项评估。
- `evaluation_answer_latest.md/json`：回答级盲测、拒答与引用完整性评估。

退出码为非零时不得把当前活动版本视为可发布。候选激活门禁通过只证明运行时一致性和检索评估通过，不等于完整发布门禁。评估报告包含知识库数据版本与评估集哈希；重建知识库、修改任一评估集或报告生成时间超过 7 天后，旧报告会自动判定为过期。回答级门禁要求总体通过率不低于90%，规范依据、证据归属、截图来源、截图HTTP与拒答关键检查必须全部通过。

任务 `succeeded` 表示评估用例完整执行，不表示质量已经通过。完整执行后出现检索失败用例或回答断言失败，由报告和质量门禁判定；检索服务未就绪、目标不可达、响应无效或回答请求未完成属于执行失败，任务状态为 `failed`，同时保留报告路径和明确错误。排障时应先修复执行失败，再解读命中率或通过率。

`package-export` 会再次实时计算门禁并默认阻断失败导出。只有受控排障等例外场景才能同时填写 `--quality-waiver-actor` 与 `--quality-waiver-reason`；系统会把失败项、责任人和原因写入包清单及 `data/audit/package_exports/`。豁免只绕过自动质量条件，不绕过来源权利、人工校对、鉴权或回退要求。

本机验证通过带 API Key 的 `127.0.0.1` 管理接口运行，不占用公网请求限流额度。带有 `Forwarded` 或 `X-Forwarded-For` 的 Cloudflare 请求仍执行限流。

任务状态中：

- “未解决失败”表示某类任务最近一次结果仍然失败；
- “历史失败”只用于审计，若同类任务后来成功则不阻断门禁；
- `queued`/`running` 按 `progress_at` 计算无进展时间；旧记录回退到 `started_at`/`created_at`。默认超过 2 小时会进入“疑似卡滞”并阻断质量门禁；
- 心跳表示执行器仍在维护任务，进度时间表示步骤发生变化。仍有心跳但无进度通常应先检查外部模型、解析器或大文件步骤；心跳同时过期则检查 API 进程和任务日志；
- `PROCESS_RESTARTED` 表示 API 重启后安全收口的中断任务。系统不自动续跑；核对候选目录、输出和外部副作用后，再显式提交新任务；
- 不要手工把持久任务 JSON 改成成功，也不要因为中断任务已失败就绕过版本、回退点或最短保护期规则。

## 版本保留与清理

1. 在控制台“版本管理”查看活动版本、门禁状态、占用和保护原因；不直接在文件系统删除 `data/db_versions` 子目录。
2. 对事故证据、长期对照样本或指定回退点开启“人工固定”。损坏的固定标记按受保护处理，必须先修复标记才能清理。
3. 点击“生成清理计划”。计划只包含当时未受保护且满足期限或磁盘水位条件的版本，并保存目录指纹和策略快照。
4. 核对版本、原因和预计释放空间后确认执行。后台任务会再次读取活动指针、运行任务、固定状态和指纹；变化项自动跳过。
5. 在构建任务查看执行日志，在 `data/audit/version_retention/` 查看计划、执行报告和 JSONL 事件。`partial_failed` 或后台任务失败必须处理后再生成新计划。

默认策略保留活动版本、2 个近期回滚版本和 24 小时内变化的版本；成功版本 30 天、失败或不完整版本 7 天后才可能按期限进入计划。版本总占用超过 20 GiB 时尝试回收到 16 GiB，但不会突破任何保护条件。调整策略后旧计划自动失效。

## 人工职责

- 截图与建议逐项核对，尤其是合并单元格、图中系数、空白单元格和表注。
- 不以模型置信度代替人工判断；质量提醒和 assumptions 必须逐条处理。
- 只有确认来源页、数值、单位和适用条件后才能发布。

## 外部依赖优化

- 学习型 reranker：接口已经预留，启用前需要选定并部署可用的精排服务及基准测试。
- OCR/版面引擎升级：属于独立基础设施工作，需要模型、算力和部署环境，不在当前自动化闭环内。
- 新规范接入后应扩展评估集，不能仅依赖现有规范的历史通过率。
