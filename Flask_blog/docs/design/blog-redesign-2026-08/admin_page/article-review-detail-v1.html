深入理解 RAG：从检索到生成

从真实项目出发，重新理解检索、召回、Embedding、上下文构造与生成模型之间的协作。

为什么要重新理解 RAG

很多 RAG 项目最早都会被描述为“把文档切块、做 Embedding、然后交给模型回答”。这种描述没有错，但它会隐藏真正影响效果的几个关键环节。

实际系统更接近一条由检索、重排、上下文构造和生成共同组成的链路。

query → retrieve → rerank → context build → LLM generation

检索并不是终点

召回到相关片段只是第一步。真正需要控制的是进入模型上下文的信息质量、顺序、重复度以及与问题之间的关系。
