RAG 的最小工作链路。复杂内容可以突破正文宽度，但仍然围绕同一条中心轴展开。

文章详情页不应该假设所有内容都来自 Markdown。Markdown 很适合文字、标题、列表和基础代码块，但真实技术内容通常会继续长出图表、交互实验、视频、附件和结构化数据。

设计原则

所有 Block 共享同一条内容轴。差别只在宽度级别，而不是每种内容重新发明一套版式。

基础富文本

普通段落仍然是阅读体验的中心。正文宽度控制在约 760px，中文正文保持 17px 左右、较宽行距。重点信息可以加粗，但不建议通过大量彩色文本制造层级。

  • Markdown 正文
  • 富文本编辑器输出
  • 服务端生成 HTML
  • 结构化 Block 内容
技术文章真正难的往往不是“写出来”，而是把不同类型的信息组织成读者能够顺着理解下去的路径。 — 页面设计备注

代码块

代码块可以略宽于正文，但仍然以正文中心线为中心。它支持语言标识、复制、横向滚动，也为未来 diff、高亮行预留空间。

query = embed(user_question)

candidates = vector_store.search(
    query=query,
    top_k=20,
)

results = rerank(
    question=user_question,
    documents=candidates,
)[:5]

大图与图注

架构图、产品截图和复杂示意图允许扩展到 960px 左右。视觉上应该像正文“向外展开”，而不是突然换到另一套页面网格。

图片组 / 对比截图

多图内容比单图更适合使用独立图库 Block，并允许达到 1040px 的最大内容宽度。
