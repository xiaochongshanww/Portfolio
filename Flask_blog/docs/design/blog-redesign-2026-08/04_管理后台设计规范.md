# 04_管理后台设计规范

> 状态：Design Baseline  
> 适用范围：小重山 CMS 管理后台  
> 基线日期：2026-08  
> 关联原型：2026 Admin Article Management V1、2026 Admin Suite  
> 核心原则：任务效率优先、信息密度优先、弱装饰、单一 Primary、统一 Data Pattern

---

# 1. 后台定位

管理后台不是公开站的“另一套皮肤”。

公开站和后台属于两个不同的产品环境：

```text
公开站
→ 内容消费
→ 阅读优先
→ 个人技术感
→ 视觉可以适度留白

管理后台
→ 内容治理
→ 操作效率优先
→ 信息密度优先
→ 视觉必须克制
```

两者只共享：

- 品牌名称；
- 基础字体；
- 中性灰白基调；
- 克制的圆角；
- 统一的文字层级。

后台不复制公开站的内容卡片、文章排版和 Reading Rail。

---

# 2. 后台设计关键词

```text
Productive
Dense
Clear
Calm
Operational
Consistent
```

对应中文：

- 高效；
- 紧凑；
- 清晰；
- 稳定；
- 面向操作；
- 统一。

后台视觉目标不是“看起来很酷”，而是：

> 用户进入后台以后，可以快速找到、判断、筛选和操作内容。

---

# 3. 明确禁止的旧后台视觉

以下设计不再允许重新出现：

- 蓝紫大渐变；
- Glow 发光；
- 大面积彩色 KPI 卡；
- 页面 Hero Card；
- 页面标题再包一层渐变容器；
- 大用户信息卡常驻 Sidebar 顶部；
- Sidebar Active 使用大面积渐变；
- 卡片套卡片；
- 过多阴影；
- 所有字段都做成 Badge；
- 每个页面自行发明一套筛选区；
- 每个页面自行定义按钮颜色；
- “编辑 / 删除 / 状态操作”在不同页面使用完全不同的交互；
- 为了显得“现代”而牺牲信息密度。

---

# 4. Admin Shell

后台统一结构：

```text
┌─────────────────────────────────────────────┐
│ Sidebar │ Topbar                            │
│         ├───────────────────────────────────┤
│         │                                   │
│         │ Page Header                       │
│         │                                   │
│         │ Page Content                      │
│         │                                   │
└─────────┴───────────────────────────────────┘
```

---

# 5. Sidebar

## 5.1 宽度

Desktop：

```text
224px
```

较窄桌面：

```text
196px
```

Mobile：

```text
隐藏
→ Drawer / Mobile Navigation
```

不允许为了显示更多菜单把 Sidebar 扩大到 260–300px。

---

## 5.2 品牌区域

顶部：

```text
山  小重山 CMS
```

要求：

- 高度约 58px；
- 不使用大 Logo；
- 不使用 Glow；
- 不放副标题。

---

## 5.3 菜单分组

当前后台 IA：

```text
工作台
  仪表盘

内容
  文章
  评论

组织
  专题
  标签
  项目

资源
  媒体

系统
  用户
  安全
  日志
  设置
```

菜单项高度：

```text
约 36px
```

Active：

```text
Primary Soft Background
+
Primary Text
```

例如：

```text
#EFF6FF
+
#2563EB
```

不使用渐变。

---

## 5.4 用户信息

用户信息放在 Sidebar 底部。

结构：

```text
Avatar
manual@verify.com
管理员
⌄
```

不使用大型 User Card。

---

# 6. Topbar

推荐高度：

```text
58px
```

主要职责：

- Breadcrumb；
- 返回网站；
- 少量全局动作。

不要放：

- 网站主导航；
- 巨大的写文章按钮；
- 页面级业务操作；
- 重复用户信息。

页面业务动作属于 Page Header。

---

# 7. 页面内容区域

推荐：

```text
max-width: 1280px
horizontal margin: 20px+
top padding: 28px
```

后台页面不追求超宽满屏铺开。

对于大型数据表，允许根据业务调整 max-width。

---

# 8. Page Header

标准形式：

```text
文章管理                         [+ 新建文章]
管理、发布和维护站点文章内容。
```

结构：

```text
Title
Description
Primary Action
```

要求：

- 不放进 Card；
- 不使用背景色；
- 不使用渐变；
- 不增加大 Icon；
- Title 约 24px；
- Description 约 13px。

页面只允许一个明确 Primary Action。

---

# 9. Admin Design Tokens

## 9.1 颜色

基线：

```text
Background       #F6F7F8
Surface          #FFFFFF
Surface Subtle   #FAFAFA

Text             #18181B
Text Secondary   #3F3F46
Muted            #71717A
Muted Light      #A1A1AA

Border           #E4E4E7
Border Strong    #D4D4D8

Primary          #2563EB
Primary Soft     #EFF6FF

Success          #15803D
Success Soft     #F0FDF4

Warning          #B45309
Warning Soft     #FFFBEB

Danger           #B91C1C
Danger Soft      #FEF2F2
```

---

## 9.2 Primary 使用范围

Primary 只用于：

- Primary Button；
- Active Menu；
- Selected State；
- 链接；
- 轻量关键状态。

不得：

- 整个 Header 蓝色；
- 整个页面背景蓝色；
- 大面积蓝紫装饰。

---

# 10. 字体与字号

推荐：

```text
Page Title          24px
Section Title       13–15px
Table Body          12–13px
Toolbar Control     12px
Supporting Text     10–12px
```

后台可以比公开站更小，但不能为了密度无限缩小。

正文式说明文字原则上不低于：

```text
12px
```

---

# 11. 控件高度

统一：

```text
Primary Button      36px
Normal Button       32–34px
Input               34px
Select              34px
Table Action        28–30px
Sidebar Menu        36px
Pagination          28px
```

避免：

- 同一个页面出现 30 / 36 / 42 / 48px 多套按钮高度；
- “创建”按钮突然巨大。

---

# 12. 圆角

```text
Button / Input      7–9px
Toolbar             10–12px
Card                10–12px
Floating Menu       10px
Dialog / Drawer     12–16px
```

后台圆角应比公开站略克制。

---

# 13. 阴影

普通 Card：

```text
不使用阴影
```

允许阴影：

- Dropdown；
- Popover；
- Dialog；
- Drawer；
- Floating Menu。

后台结构层级优先靠：

```text
Border
+
Background
```

表达。

---

# 14. Summary / KPI

后台仍然允许 Summary，但禁止旧式彩色 KPI Card。

推荐：

```text
┌────────┬────────┬────────┬────────┐
│ 全部 47│ 发布 42│ 草稿 3 │ 审核 2 │
└────────┴────────┴────────┴────────┘
```

特征：

- 同一容器；
- 1px Border；
- 内部分隔；
- 无彩色背景；
- 无大 Icon；
- 无 Glow。

只有真的有决策意义的数字才展示。

---

# 15. Toolbar

所有列表型页面统一使用：

```text
Toolbar
├─ Search
├─ Filters
├─ Secondary Actions
└─ Result Count / Refresh
```

推荐：

```text
[ 搜索_______________ ] [状态▼] [专题▼] [更多筛选]

                                   47 条结果 [刷新]
```

筛选控件不单独套 Card。

---

# 16. Data Table

后台核心信息承载组件。

原则：

- 真正回归 Table；
- 行高紧凑；
- 关键字段优先；
- 辅助信息弱化；
- 不把每个字段做成 Tag；
- 列宽稳定；
- Hover 轻量。

推荐：

```text
Header Height      42px
Row Padding        12–14px
Body Font          12px
Title Font         13px
```

---

# 17. Table 信息层级

一条记录最多分三层：

```text
Primary
→ 标题 / 名称

Secondary
→ 摘要 / 邮箱 / 描述

Tertiary
→ Tag / Slug / 更新时间
```

例如文章：

```text
深入理解 RAG：从检索到生成
从真实项目出发理解检索和上下文……
RAG · Python
```

不要同时显示：

```text
作者
头像
作者邮箱
发布日期 Badge
更新时间 Badge
图标
字数
评论
收藏
点赞
```

除非业务真的需要。

---

# 18. 状态设计

统一状态体系：

```text
Success
Warning
Neutral
Danger
```

推荐表现：

```text
● 已发布
● 待审核
● 草稿
● 失败
```

即：

```text
Dot + Text
```

比彩色大 Badge 更适合表格。

Badge 适合：

- Role；
- Topic；
- Tag；
- 类别。

Status 不建议默认用大 Badge。

---

# 19. 操作体系

统一规则：

```text
Primary Row Action
→ 直接按钮

Secondary / Dangerous
→ ···
```

例如：

```text
编辑   ···
```

菜单：

```text
预览
复制
取消发布
────────
删除
```

禁止不同页面分别出现：

```text
状态操作▼
撤销
查看文章
更多
删除
```

但没有统一语义。

---

# 20. Dangerous Action

危险动作：

```text
删除
禁用
撤销关键状态
```

要求：

- Danger 色只在真正危险动作使用；
- 不把整个页面很多按钮染红；
- 删除通常进入 Menu；
- destructive action 需要二次确认。

---

# 21. Pagination

统一放在 Table Footer。

结构：

```text
共 47 条                        ‹ 1 2 3 ›  20 / 页
```

不将分页放在 Table 外随意漂浮。

---

# 22. Form 页面

表单页原则：

```text
Page Header

Form Sections
├─ Basic
├─ Content
├─ Visibility
└─ Advanced
```

单个 Section 可以使用 Card。

不要：

- 每一个字段一个 Card；
- 多层阴影；
- 左右随机排列。

推荐字段宽度：

```text
Short          240–320px
Normal         420–560px
Long           100%
```

---

# 23. Dialog / Drawer

## Dialog

适合：

- 确认；
- 简短表单；
- 删除；
- 状态变更。

## Drawer

适合：

- 查看详情；
- 较复杂编辑；
- Audit Detail；
- 用户详情。

不要用大 Dialog 承载整个页面。

---

# 24. Empty State

后台 Empty State 保持克制：

```text
暂无待办事项
当前没有需要处理的内容。
```

不使用大型插画。

---

# 25. Loading

Table：

```text
Skeleton rows
```

Card：

```text
Skeleton block
```

按钮：

```text
disabled + spinner
```

不要整页只显示中央 Loading。

---

# 26. Error

错误应靠近发生位置。

例如 Table 请求失败：

```text
文章列表加载失败
[重新加载]
```

不应该直接整页跳错误页，除非页面本身不可访问。

---

# 27. Responsive

后台 Desktop First。

### ≥ 1050px

完整 Sidebar。

### 720–1049px

- Sidebar 可缩；
- Summary 2 列；
- Table 横向滚动；
- 页面操作保持。

### < 720px

- Sidebar Drawer；
- Toolbar 换行；
- Summary 单列或 2 列；
- Table 可横向滚动；
- 不为了手机强行把复杂 Table 变成完全不同数据模型。

后台移动端目标：

> 可用，不追求与桌面相同效率。

---

# 28. Accessibility

- 所有 Menu 可键盘访问；
- Dialog / Drawer Focus Trap；
- Esc 关闭；
- Button 有明确 Label；
- Status 不只靠颜色；
- Checkbox 有可点击区域；
- 表格 Header 使用语义 th；
- 危险操作有确认。

---

# 29. Admin 与公开站品牌关系

共享：

```text
小重山
Inter / System Font
灰白背景
克制圆角
弱阴影
```

区别：

```text
公开站 Signal
→ #FF5C35

后台 Primary
→ #2563EB
```

不要强行把两者统一成同一种强调色。

它们属于同一品牌，但服务不同任务。

---

# 30. 后台验收清单

## Shell

- [ ] Sidebar 约 224px
- [ ] User Info 在 Sidebar 底部
- [ ] Topbar 不混入公开站主导航
- [ ] Page Action 放在 Page Header
- [ ] 页面内容宽度稳定

## Visual

- [ ] 无蓝紫渐变
- [ ] 无 Glow
- [ ] 无页面 Hero Card
- [ ] 普通 Card 无阴影
- [ ] Primary 只有一套
- [ ] Success / Warning / Danger 使用统一 Token

## Data

- [ ] 列表优先使用 Table
- [ ] Toolbar Pattern 一致
- [ ] Status 使用 Dot + Text
- [ ] 低频操作统一进入 ···
- [ ] Pagination 位于 Table Footer
- [ ] 辅助字段不过度 Badge 化

## Responsive

- [ ] Table 不会撑破页面
- [ ] Toolbar 可换行
- [ ] Sidebar 在小屏可关闭
- [ ] 不通过缩小到 10px 以下来塞内容

---

# 31. 最终原则

后台任何新页面首先问：

```text
它是什么工作任务？
```

而不是：

```text
这里还能放什么卡片？
```

设计优先级始终是：

```text
任务
→ 信息
→ 操作
→ 状态
→ 视觉
```

而不是反过来。
