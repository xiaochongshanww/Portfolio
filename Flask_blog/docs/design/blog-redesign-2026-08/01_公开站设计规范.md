# 01_公开站设计规范

> 状态：Design Baseline  
> 适用范围：小重山个人技术主页公开站  
> 基线日期：2026-08  
> 关联原型：2026 Home V2、Article Detail V5b、专题/项目/归档/搜索/关于页原型

---

## 1. 设计目标

本项目不是传统博客、个人简历站或作品集，而是一个持续更新的个人技术主页。

公开站需要同时承载三类信息：

1. 正在写的内容；
2. 正在做的项目；
3. 长期沉淀的专题与知识。

核心体验不是“展示个人信息”，而是让访问者快速理解：

- 最近更新了什么；
- 当前正在做什么；
- 有哪些长期主题；
- 如何继续深入阅读。

因此公开站遵循以下优先级：

```text
内容
→ 项目
→ 长期专题
→ 个人信息
```

个人身份存在，但不作为首页主体。

---

## 2. 设计关键词

公开站统一使用以下设计关键词：

```text
Personal
Technical
Current
Calm
Structured
Readable
```

对应中文理解：

- 个人，但不过度自我介绍；
- 技术感来自内容和结构，而不是视觉特效；
- 强调“持续更新中”；
- 克制、稳定、不过度装饰；
- 页面具有清晰的信息层级；
- 长时间阅读舒适。

---

## 3. 明确禁止的旧设计语言

以下视觉语言不再作为公开站设计方向：

- 大面积蓝紫渐变；
- 玻璃拟态；
- 大量模糊光斑；
- 卡片套卡片；
- 所有内容都放进圆角容器；
- 过度 hover 浮起；
- 彩色阴影；
- 首页大 Hero 自我介绍；
- 过度强调登录 / 注册；
- 像内容社区一样展示作者、点赞、收藏、评论、阅读量等元数据；
- 为了“丰富”而给每个页面设计完全不同的视觉系统。

后台管理端不受此限制，可继续以 Element Plus 为核心。

---

## 4. 页面总体结构

公开站使用统一 Header 和 Footer。

### Header

桌面端：

```text
山 小重山        文章  项目  专题  归档  关于        搜索 ⌘K
```

要求：

- 高度约 64–68px；
- sticky；
- 轻微透明 + backdrop blur 可以保留；
- 不使用厚重阴影；
- 当前导航只通过文字颜色变化表示；
- 搜索是功能入口，不做大型输入框；
- 登录 / 注册默认不出现在公开 Header 主导航中。

### Footer

Footer 保持轻量：

```text
© 2026 小重山                 GitHub · RSS · 关于
```

不增加大面积空白，不做二次导航站点地图。

---

## 5. 基础视觉 Token

### 颜色

推荐基线：

```text
Background      #F7F7F5
Surface         #FFFFFF
Surface 2       #F1F1EE
Text            #171717
Muted           #6B6B67
Border          #E3E3DF
Border Strong   #D4D4CE

Signal          #FF5C35
Signal Soft     #FFF0EA
Signal Ink      #A53B21

Blue Soft       #EDF3FF
Green Soft      #EDF6EF
Sand Soft       #F5EFE3
```

Signal Color 的职责：

- 新内容；
- 活跃状态；
- 当前阅读位置；
- 交互重点；
- 技术图中的关键节点。

不得用于大面积页面背景。

### 字体

优先：

```text
Inter
system-ui
PingFang SC
Microsoft YaHei
sans-serif
```

正文不依赖装饰性字体。

### 字号建议

```text
页面主标题          36–48px
文章标题            42–48px
Section 标题        15–18px
文章正文            17px
辅助说明            13–15px
最小辅助信息        11–12px
```

原则：

- 中文正文不得过小；
- 普通辅助文字尽量不低于 12px；
- 不通过极小字号制造所谓“高级感”。

### 行高

正文建议：

```text
font-size: 17px
line-height: 1.85–1.95
```

中文长文优先阅读舒适度。

---

## 6. 页面宽度体系

### 页面最大宽度

```text
Page Container: 1180px
```

### 内容轴

文章页额外使用：

```text
正文           760px
Code           820px
Wide Content   960px
X-Wide         1040px
```

所有宽度必须围绕同一页面中心轴对称展开。

不允许出现：

```text
正文因为目录存在而向左偏移
```

---

## 7. 圆角、边框、阴影

推荐：

```text
小控件       8–10px
普通内容块   12–16px
大内容块     16–20px
```

边框优先于阴影。

阴影只允许用于：

- 浮动目录；
- 搜索浮层；
- Drawer；
- 少量需要从背景中脱离的悬浮元素。

普通卡片尽量只使用 1px Border。

---

## 8. 动效

动效必须服务于状态反馈，不做装饰动画。

推荐：

```text
transition: 160–200ms
```

可使用：

- hover 边框变化；
- 轻微位移 1–2px；
- opacity；
- Drawer / Search Overlay；
- Reading Rail 出现 / 消失。

必须支持：

```css
@media (prefers-reduced-motion: reduce)
```

关闭非必要动画。

---

## 9. 响应式原则

### Desktop

完整显示：

- Header Navigation；
- Reading Rail；
- 宽内容 Block。

### Medium

目录不再占右侧空间：

```text
Reading Rail
→ 隐藏
→ 独立“目录”按钮
```

### Mobile

原则：

- 内容优先；
- Navigation 折叠；
- 宽 Block 自动退化到 viewport；
- Table 横向滚动；
- Gallery 单列；
- Interactive Demo 可改为上下结构；
- 目录通过 Drawer / Bottom Sheet 打开。

无论任何断点：

> 目录不得推动正文位置。

---

## 10. 中文优先规则

UI 默认使用中文。

例如：

```text
精选
最近更新
最近文章
正在进行
长期专题
约 12 分钟
最后更新
本文目录
```

保留常用技术术语：

```text
Python
AI
RAG
Agent
Git
JWT
Embedding
Vue
Flask
```

避免为了“科技感”加入不必要英文。

---

## 11. 技术视觉原则

公开站中的图形不是装饰封面，而应该表达内容。

推荐：

```text
RAG           → 问题 → 检索 → 上下文 → 生成
Git Rebase    → Commit Graph
RBAC          → Role → Permission → Scope
JWT           → header.payload.signature
结构力学      → 可拖动结构示意
```

不推荐：

- 随机渐变；
- 抽象球体；
- 无含义 3D 图；
- 通用 Stock Image。

技术视觉的目标是：

> 看到图，大致就知道文章 / 项目在讲什么。

---

## 12. Dark Mode

Dark Mode 可以实现，但不应在第一阶段阻塞上线。

要求：

- 保持同样的信息层级；
- Signal Color 继续使用；
- 不使用纯黑大面积背景；
- Code Block 与普通 Surface 保持明显区分。

---

## 13. Accessibility

最低要求：

- 所有交互控件支持键盘；
- Search 支持 ESC；
- TOC 支持键盘导航；
- 图片具有 alt；
- 图表不能只靠颜色区分；
- Signal Color 与背景保持足够对比；
- prefers-reduced-motion；
- 移动端可点击区域建议 ≥ 40px。

---

## 14. 实现验收清单

### 全站

- [ ] 首页不存在传统大 Hero
- [ ] 公开 Header 不突出登录 / 注册
- [ ] UI 中文优先
- [ ] 没有蓝紫渐变和玻璃拟态回潮
- [ ] 不出现大面积彩色背景
- [ ] 不存在大量卡片套卡片
- [ ] 中文辅助文字没有普遍低于 12px
- [ ] Header / Footer 在各页一致
- [ ] Hover 克制，不使用明显浮起阴影
- [ ] 技术视觉与内容直接相关

### 响应式

- [ ] Desktop / Tablet / Mobile 均可正常阅读
- [ ] Table 可以横向滚动
- [ ] Gallery 在移动端退化为单列
- [ ] Reading Rail 不推动正文
- [ ] 移动端目录使用独立入口
- [ ] 宽内容不会造成页面整体横向滚动

---

## 15. 原型与规范的关系

三者职责固定：

```text
HTML Prototype
= 视觉参考基线

Design Spec
= 行为、约束、设计原则基线

Vue Production
= 最终生产实现
```

开发过程中，如果 Vue 实现与 HTML 原型视觉存在差异：

1. 先判断是否违反 Design Spec；
2. 如果违反，按规范修复；
3. 如果规范未覆盖，再以确认过的 HTML 原型为视觉参考；
4. 不允许开发者或 AI 自行增加新的视觉体系。
